# 5.4 build evidence — Show detected game conditions and allow manual completion of unavailable fields before recording

## What was built

Implemented PLAN.md §5.4 per `.autodev/evidence/5.4.contract.md` (11 ACs),
on branch `autodev/logging-instrumentation`. Nothing committed.

**New: `detected_conditions.js`** (repo module convention: guarded
`BlindfoldSession` global → IIFE `'use strict'` → Node `module.exports`
shim for tests):

- `CONDITION_PROBES` — frozen table of the five §5.4 fields. Only
  `playerColor` is `verified: true`: the `wc-chess-board` element +
  `flipped` class probe, with selector and logic both having in-repo
  precedent (`chess_utils.js` `getBoardElement`, `squareToXY`'s
  `classList.contains("flipped")`) cited in the entry's `verification`
  field. The other four are `verified: false` with documented reasons
  and empty selector lists: `botName`/`botDisplayedRating`/`timeControl`
  are manual-only (deferred — no verified in-game selector exists;
  inventing one risks fabricated evidence, the 3.3.4 precedent);
  `assistanceSettings` is manual-only by design (3.3.4 marks
  hints/assistance DOM observation as unsupported; never attempted).
- `detectGameConditions(document)` → frozen `{field: {value, source}}`.
  Board present: `playerColor` `{value: 'white'|'black',
  source: 'observed'}`; board absent: `{value: null, source:
  'observed'}` (detection was attempted — the 1.2 contract's own
  meaning of `'observed'`). The other four always `{value: null,
  source: 'manual'}`. Each probe individually guarded (one probe's
  throw cannot poison the rest); non-document argument → TypeError.
- `installConditionsPanel({beforeElement})` → `{element,
  getDetectedConditions, setEnabled, showAdopted}`. Five rows:
  playerColor read-only when detected (White/Black select when the
  board is absent), text inputs for botName / botDisplayedRating /
  timeControl, an assistanceSettings key/value row editor with an
  always-present empty trailing row. Live source tags
  (`observed`/`manual`/`not set`); a "Re-detect" button (manual refresh
  affordance); the panel disables with the form while recording; an
  adopted-session note (`Session adopted after reload — conditions were
  recorded at its start…`) via `showAdopted`. Merge at Start: fresh
  `detectGameConditions(document)` merged with manual overrides —
  manual-dirty wins; cleared-to-blank falls back to detection.
  The panel NEVER throws for invalid manual input and NEVER coerces
  it to null: `parseRating` parses `/^\d+$/` strings to Number (type
  normalization of valid input — the 1.2 `normalizeBotRating` requires
  a number and throws TypeError on numeric strings, so passing `"250"`
  through un-normalized would abort an honest Start); invalid input
  passes through un-coerced so the 1.2 normalizers throw and Start
  aborts honestly as `record-build-failed`. `parseAssistanceValue`:
  `'true'`→true, `'false'`→false, finite numeric strings→number, else
  the trimmed string; `"null"`/`"NaN"`/`"Infinity"` stay strings (1.2
  "no sentinel" rule); blank-name rows ignored; `__proto__` passes
  through to the 1.2 normalizer, which rejects loudly.
- `attachConditionsPanel(fieldsHandle, panelHandle)` — composite
  preserving the `isFieldsHandle` shape
  (`{getSelection, setSelection, setEnabled, getDetectedConditions}` +
  `showAdoptedCategory`), so `session_controls.js` stays
  byte-identical; `setEnabled`/`showAdoptedCategory` drive both forms
  (panel's `showAdopted` plus the fields' own adoption presentation).

**Wiring (all additive)**: `content.js` installs the panel before
`installSessionFields` (fields anchor before the panel, so the DOM
reads [fields][panel][Start][lights] — "select then Start"), passes
`panelHandle.getDetectedConditions` as the 5.2 plug-in (undefined when
the panel failed to install → the `UNDETECTED_CONDITION_FIELDS`
fallback), and wraps both handles via `attachConditionsPanel`. If the
fields install fails, the panel element is removed rather than left
inert. `manifest.json`: `detected_conditions.js` added to the
content_scripts js list (after `session_controls.js`). `overlay.css`:
additive panel classes only. No new channel messages (offscreen MSG_*
stays 24), no new event types, SW-side envelope stays 7, no
`conditions_changed` emission in 5.4 (scope is "before recording";
the 1.2.4 path stays available for 5.9). Manual completions are NOT
remembered (5.3's scope fixed at three fields). `.autodev/DECISIONS.md`
gained the `## 5.4` section.

**Open questions closed**: (1) panel anchor = before the 5.1 cluster
via `beforeElement` (fields anchor before the panel); (2)
assistanceSettings parse edges — `"null"`/`"NaN"` stay strings, empty
→ null, blank-name rows ignored; (3) the refresh button is labeled
"Re-detect" with aria-label "Re-detect game conditions".

## Deviations

1. **Rating parse clarification** (contract-strict reading): a valid
   `/^\d+$/` rating string is parsed to Number before passing to
   `buildInitialConditions`. This is type normalization of *valid*
   input, not the forbidden silent null-coercion — the 1.2
   `normalizeBotRating` requires a number and throws TypeError on
   numeric strings, so an un-normalized `"250"` would abort an honest
   Start. Invalid non-blank input (`"12x"`) passes through un-coerced
   → the normalizer throws → honest `record-build-failed`.
2. **5.3 follow-up repair** (committed separately as `583266c` on
   2026-10-06, before 5.4's pin evolution): 5.3's feature commit had
   missed its own exact-permissions pin evolutions in

   clear message so 5.4's diff-discipline pins see a clean baseline.
   This was repair of prior work, not 5.4 scope.

   instruction.
