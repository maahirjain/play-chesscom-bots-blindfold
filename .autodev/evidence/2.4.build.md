# Task 2.4 Build Report — Transactional event writer

## What was implemented

**`writer.js`** (new, repo root): SW side of the 2.3 handoff, in the
Section-1 script pattern (guarded `BlindfoldSession` global, IIFE
`'use strict'`, Node shim; no `chrome.*` / `indexedDB` / `DB` /
`isValidEvent` read at load time — all resolved at call time).

- `installWriterListener()` — installs the `chrome.runtime.onMessage`
  adapter; returns the listener function for lifecycle management (see
  Deviations). Plain `Error` when `chrome.runtime.onMessage` is
  unavailable. Bracket notation keeps the `chrome.` literal out of the
  source (static-guard convention from sender.js).
- Adapter: `kind:'event'` → `writeEvent()` → exactly one `sendResponse`,
  `return true`; other kinds → `return false`, no response; malformed
  `kind:'event'` (event missing/not an object) → synchronous
  `{ok:false, eventId:null, error:'malformed-message'}`, `return false`.
- `writeEvent(event)` → `Promise<ack>`: `TypeError` synchronously for
  non-object input (programmer-facing); every wire-data failure becomes
  an `{ok:false,...}` ack, never a throw/rejection (defensive mappers at
  both layers so the sender never hangs).
- Validation boundary: `isValidEvent` (envelope-level) + writer-owned
  `appendSeq===null` rule → `'append-seq-present'`. NO per-type payload
  validation (contract §2.3: emitters validate at construction; new types
  must not require writer changes).
- Dedup: read-before-write inside the tx; same content (recursive
  deep-equal excluding top-level `appendSeq`, key-order irrelevant) →
  idempotent `{ok:true}`, counter untouched; different content →
  `{ok:false, error:'event-id-content-mismatch'}`, stored record never
  overwritten.
- appendSeq: ONE `readwrite` tx over `['events','sequence_state']` via
  RAW IndexedDB (per DECISIONS.md #9a — `DB.put` resolves on request
  success, not commit). New record via `Object.assign` (never mutates
  intake). Ack `{ok:true}` produced ONLY from `tx.oncomplete`.
  Synchronous DataError/NotFoundError throws wrapped to
  `write-failed:<name>` (DECISIONS.md #9b). Unavailable indexedDB →
  `write-failed:unavailable`.
- Transaction-body discipline: callbacks only, no non-IDB awaits while
  the tx is open. Concurrency safe without a JS lock per contract §2.6
  (single-threaded JS + IDB overlapping-readwrite serialization +
  sole-writer invariants, recorded in the module header).

**`sw.js`**: `importScripts('db.js', 'event_envelope.js', 'writer.js');`
plus `BlindfoldSession.writerListener =
BlindfoldSession.installWriterListener();` (see Deviations); header
updated (2.4 line removed from the absent list; 2.3 noted as
content-script-only).

**`tests/writer.test.js`** (new): 27 V1 checks with a hand-rolled
in-memory IDB fake consuming the REAL `DB.SCHEMA` (documented limits:
no overlapping-transaction serialization modeling — AC13/V2 is the
backstop; no structured-clone modeling). The fake models true
transactional semantics: per-tx write journal applied only on commit,
abort discards, reads see own journaled writes — so the AC9 atomicity
tests are faithful. Covers AC1–AC11: Node loading, static guards,
malformed messages, envelope boundary (incl. a test pinning that payload
semantics are NOT validated), append-seq-present, assignment +
commit-ordered ack (order log asserts ack comes from `tx.oncomplete`),
per-session counters, idempotent duplicate (incl. key-order
insensitivity), content mismatch, injected put failure on either put
(event rolled back when the counter put fails), sync transaction throw,
unavailable IDB, listener adapter behavior (return true/false, exactly
one sendResponse, plain-Error on no chrome), diff discipline.

**`~/workspace/tools/ext-verify/sw-writer.js`** (harness, outside repo):
V2 driver reusing the 2.3 /tmp test-extension technique (product files
verified byte-identical).

## Deviations from the contract

1. **`installWriterListener()` returns the listener; `sw.js` keeps the
   handle** (`BlindfoldSession.writerListener`). Reason: the 2.3 V2
   harness's AC9 (no-ack behavior) removes its stand-in listener to
   simulate transport failure — but with the real writer installed,
   acks still flow, so AC9 failed (3 checks). Making the writer's
   listener removable via its lifecycle handle restores a genuine
   no-ack state. This also serves 2.6 (restart listener management).
   One line in each file; no behavior change otherwise. The 2.3
   harness was updated accordingly (removes both listeners in AC9).
   → Reviewer: confirm this is an acceptable minimal addition.
2. **Honest cumulative test evolution** (2.2/2.3 precedent): the
   sw.js-pinning assertions in `tests/db.test.js`,
   `tests/manifest_sw.test.js`, and `tests/sender.test.js` were updated
   to the 2.4 cumulative state (exact three functional lines;
   header absent-list; db.js still byte-identical). Invariants
   preserved/strengthened, each change commented.
3. **Two bugs found in the builder's own work during V1, both fixed:**
   (a) `createEvent` always mints its own `eventId` — the test fixture's
   `eventId` override was silently dropped (fixture now applies the ID
   post-creation); (b) a brace mismatch from the listener-handle edit
   (caught immediately by the test run).
4. **Test-expectation correction:** `eventType: 'not_a_type'` is VALID
   flat snake_case — the writer (correctly) accepts it. The
   invalid-envelope test now uses `'NotASnakeCaseType'`. This confirms
   the contract's validation-boundary decision: shape, not a type
   registry.
