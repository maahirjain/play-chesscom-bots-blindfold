# Task 4.6 build report — start separate recording streams

PLAN.md §4.6: "Start separate microphone, screen, and webcam recording
streams, saving actual start times rather than assuming simultaneous
starts."

Per `.autodev/evidence/4.6.contract.md` (12 ACs: AC1–AC8 V1, AC9–AC11 V2,
AC12 V3-deferred to §7).

## What was built

**`stream_starter.js`** (new, DOM-free, repo module pattern + Node shim):
- `createStreamStarter(opts)` — everything injected
  (`mediaDevices`, `getDisplayMedia`, `MediaRecorder`, mic/camera/capture
  selectors, SW broker client, 4.5 `formatSupport`, session thunks,
  `nowUtcIso`/`perfNowMs` clocks, `newUuidV4`). Document globals are read
  lazily when not injected (the offscreen document path).
- `startStreams()` — runs the three per-stream pipelines concurrently via
  `Promise.all`; each pipeline: fresh `verifyFormats()` → acquire stream
  → `new MediaRecorder(stream, {mimeType: <first verified>})` → read the
  REAL `recorder.mimeType` → `recorder.start()` with NO timeslice and
  `ondataavailable` unset (4.8's seam) → capture `streamStartedAtUtc` +
  `streamStartedAtMonotonicMs` → widened manifest write via 4.5's
  `recordSegmentFormat`. Returns `{ok, streams: {microphone, screen,
  webcam}}` with per-stream `{ok:true, segmentId, ...}` or `{ok:false,
  error, errorName, stage}` (stages: `verify-formats`,
  `acquire-stream`, `construct-recorder`, `start-recorder`,
  `write-manifest`).
- **4.6 mints `segmentId`** (uuid-v4, no weak fallback) — the 4.5 §2
  contract amendment: the manifest record is written at stream start and
  `recording_manifest`'s keyPath IS `segmentId`.
- **Separateness**: three distinct `MediaStream`s, three `MediaRecorder`s,
  no `AudioContext`, no track merging (V1-pinned). `audioTrackPresent` /
  `videoTrackPresent` recorded per stream for 4.7/4.14.
- **Failure independence**: one stream's failure never blocks the others;
  partial tracks are stopped; no manifest record for failed streams; a
  manifest-write failure after a live start stops the recorder + tracks
  (no orphaned recording without a manifest record).
- **Guards**: `no-session` (no device touched), `already-started`,
  `start-in-progress`. Module registry `getActiveStreams()` /
  `getStreamRecord(streamKind)` of live `{stream, recorder, segmentId}`
  for 4.8/4.9/4.13.
- **Acquisition**: mic/webcam — selector's selection with
  `deviceId:{exact}`, else `{audio:true}`/`{video:true}` and the
  actually-used device recorded as `source:'default'` (never `'user'`;
  a `recordDefault` persistence failure fails the stream honestly).
  Screen/tab — the 4.3 capture mode: tab mode resolves the target tab via
  the SW broker and mirrors the 4.3 probe constraints (single-use
  `streamId`, never persisted); screen mode calls `getDisplayMedia` and
  maps `InvalidStateError` → `error:'picker-unavailable'` honestly (no
  fabricated workaround — tab mode is the supported path).
- **No new event types**: manifest records + channel response are the
  durable trace.

**`device_selection.js`** — new `recordDefault(deviceId)`: persists an
actually-used-but-unselected device as `source:'default'` with the same
persist-before-live discipline as `select()` (4.2 SF-1) and emits the
`device_selected` event with `source:'default'`.

**`format_support.js`** — deliberate 4.6 widening per the field-ownership
table: `MANIFEST_KEYS` 8 → 13 (`streamStartedAtUtc`,
`streamStartedAtMonotonicMs`, `effectiveDeviceId`, `audioTrackPresent`,
`videoTrackPresent` — `segmentId` was already present). The six new
fields are nullable; `recordSegmentFormat` still accepts the 4.5 call
shape (absent → `null`) and passes real values through when provided;
`requireValidManifestRecord` validates the new fields' types.

**`recorder.js`** — `recorder-start-streams` channel message (driven by §5
later), failure-isolated per the 3.2 SF-1 precedent; `getStreamStarter()`
lazy constructor; `getStreamStarter` exposed for 4.8/4.9/4.13. The 4.1
boundary is preserved: recorder.js references NO media-capture APIs
(`MediaRecorder`, `getUserMedia`, `getDisplayMedia`) — the starter reads
them from the document globals; recorder.js wires only selectors, broker,
format support, session thunks, clocks, and uuid. `o.streamStarter`
injection seam retained for tests.

**`recorder.html`** — loads `stream_starter.js` after `format_support.js`.

**Tests** — `tests/stream_starter.test.js` (43 tests, AC1–AC8): happy
path (three distinct streams/recorders, no timeslice, `ondataavailable`

## Deviations and findings

1. **Real bug found by V2, fixed**: `stream_starter.js`'s
   document-global `getDisplayMedia` fallback returned the method
   unbound → `TypeError: Illegal invocation` in the real document
   (V1 never caught it — injected fakes are plain functions). The
   fallback now returns a bound caller; a V1 regression test
   (`Illegal invocation` guard) pins it. `getUserMedia` was unaffected
   (always called as a method on `mediaDevices`).
2. **recorder.js kept free of media-capture APIs** (design decision, not
   a contract change): rather than weakening the 4.1/4.2/4.3 V1 pins that
   assert `recorder.js`/`recording_host.js` reference no `MediaRecorder`/
   `getUserMedia`/`getDisplayMedia`, `getStreamStarter()` no longer
   accepts those injections — the starter reads document globals lazily.
   All existing pins pass unmodified.
3. **CDP permission findings** (harness-only, documented in
   `sw-streams.js`): `new URL('chrome-extension://…').origin` is the
   string `'null'` (opaque) — origin-scoped `Browser.setPermission` is
   impossible for the extension; origin-less (context-wide) grants work
   but are **tied to the CDP session lifetime** — `page.close()` and
   `session.detach()` were both observed to revoke them. The harness
   sends grants on the offscreen target's own session and keeps it open
   through the media calls.
4. **Harness hygiene**: profiles are wiped per run — selector
   `localStorage` and extension IDB otherwise leak between runs and
   break the "no capture mode" precondition and manifest counts.
   (Extension ID stays stable: it derives from the fixed `/tmp` ext path.)
5. **V1 note**: Node 24's `globalThis.navigator` is a getter-only
   accessor — plain assignment silently fails; the lazy-wiring test uses
   `Object.defineProperty` with descriptor restore.
6. No new event types; no PLAN.md changes; no analysis/metrics features.
   AC12 (real-device three-stream start + true picker behavior) is
   deferred to §7/owner verification as the contract requires.
