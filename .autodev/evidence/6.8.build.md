## What was built

**New file `EXPORT.md` (repo root):** User-facing export documentation covering all five contract §2 areas:

1. **Where the ZIP goes.** Browser download manager, user's configured location (`saveAs: false`). The extension does not choose the location.
2. **What the user does.** The user extracts the ZIP into their experiment directory. Directory naming: `<category>/<YYYY-MM-DD>_<gameId>/` (single) or `<category>/<YYYY-MM-DD>_session-<sessionId>/` (multi-game, media stored once).
3. **What's inside.** Table documenting `metadata.json`, `events.jsonl`, `media-sync.json`, and the three numbered media file kinds (original format, no transcoding).
4. **Re-export after interruption.** Click Download again; rebuilt from retained data; no cleanup needed (links to 6.7's guarantee).
5. **What the extension does NOT do.** No arbitrary filesystem writes, no deletion on export, no upload/sync/backup, no transcoding, no analysis.

**Placement rationale (contract §3):** Standalone `EXPORT.md` in the repo root (not a README edit) because:
- The existing `README.md` is gameplay-focused (shortcuts, Chess.com settings, move input).
- 7.14 ("Update README with setup, recording controls, export instructions, and verified coverage limitations") will integrate this content into the README. `EXPORT.md` gives 7.14 a clean source to merge.
- Repo-root Markdown is the established pattern (`README.md`, `AGENTS.md`, `PLAN.md`).
