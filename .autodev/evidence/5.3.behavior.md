## Behavioral honesty checks (traced against real code)

**(a) No-silent-change invariant — all four mechanisms verified:**

1. *Write-once (5.2):* `session_fields.js:294` — `setSelection` returns
   immediately `if (!enabled)`; the form is disabled at Start
   (`session_controls.js` calls `fieldsHandle.setEnabled(false)` right
   after the `onSessionStarted` fire), so a restore landing
   mid-session is a harmless no-op.
2. *No record-write path:* comment-stripped scan of
   `selection_memory.js` for `session-save`, `saveSessionMetadata`,
   `saveConditions`, `indexedDB`, `sendMessage`, `chrome`,
   `storage.sync` → **zero hits**. The module's only external surface
   is the injected `{get,set,remove}` adapter; it never touches the
   `chrome` global.
3. *Capture reads the live form at Start only:* `onSessionStarted`
   fires exactly once at the `phase → 'active'` point
   (`session_controls.js:831`), i.e. after `session-save` succeeded and
   the slots were set — with the `selection` object that was actually
   recorded. No abort path reaches the firing point (every abort path
   throws/returns before it); boot adoption sets the phase directly and
   never fires it.
4. *No load-past-session path:* `restore` only calls
   `fieldsHandle.setSelection`; nothing reads a past session's record
   back into the form.

**(b) Boot-adoption race — both orderings leave adopted truth winning:**
adoption-first → the form is disabled, so `restore`'s `setSelection`
no-ops (mechanism 1); restore-first → the adoption path writes the
adopted category into the select directly and disables the form,
overriding the remembered value. The V2 reload-adoption check (45/45)
exercises the real path.

**(c) `onSessionStarted` — exactly once per successful Start** at the
`phase → 'active'` point, guarded in `try/catch` so a throwing callback
can never break Start (3.2 SF-1); not fired on any abort (no-category,
ensure-failure, channel-failure) or on boot adoption.

**(d) `validateRememberedSelection` totality:** non-plain-object input →
`null`; unknown category string → whole value `null` (no half-valid
restore); text fields coerced via `String()` with `null`/`undefined` →
`''` (never the literal `"null"`); extra keys ignored. Corrupt stored
values are safely discarded and can never break the page.

**(e) Storage:** `chrome.storage.local` under the single versioned key
`'blindfold.sessionSelection.v1'` only; no `chrome.storage.sync`
anywhere (scan-clean); the module is loaded in content scripts only
(manifest diff confirms), never in the SW or offscreen document.

**(f) Changed-files discipline:** `selection_memory.js` is the only new
product file; `session_controls.js` diff is only the optional
`onSessionStarted` install option; `content.js` diff is only the memory
construction/wiring; `manifest.json` diff is only the `"storage"`
permission + the `selection_memory.js` content_scripts entry; all
record-path and gameplay files byte-identical.

**(g) PLAN.md integrity:** `git diff main -- PLAN.md` is empty —
verified unmodified.

## Notes (informational, non-blocking)

- N1: `validateRememberedSelection`'s totality holds for all
  JSON/structured-clone-representable inputs (everything
  `chrome.storage.local` can hold); a `Symbol` value would throw in
  `String()`, but Symbols cannot exist in storage or in DOM-derived
  form values, so the path is unreachable.
- N2: `capture` swallows storage write failures by design — the session
  already started; the consequence is only that next time's defaults
  are blank (honest, no masquerade).
