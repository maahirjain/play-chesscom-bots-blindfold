## Notes (not defects)

1. **Chrome wire behavior (worth recording):** when an `onMessage`
   listener returns `false` without responding, `sendMessage`'s promise
   **resolves `undefined`** in this Chrome build — it does not hang.
   The writer's contract ("ignore, no response") is still the correct
   description of the writer's behavior; the `undefined` is the
   platform closing the port. Future tasks defining new message kinds
   should not interpret an `undefined` response as an ack.
2. **Per-page senders each emit their own `clock_anchor`** for the same
   session (observed: 3 anchors for 3 pages). Each anchor consumes a
   sequence number through the same writer path — correct per the 1.3
   segment model (each content-script context is its own clock segment),
   and §6.2 consumers should expect one anchor per emitting context.
3. **AC15 (real chess.com end-to-end)** remains deferred to §7 /
   owner-device acceptance, as contracted.
