## What was built

**New module `timecode.js`** (repo module pattern: dependency-free classic
script → guarded `BlindfoldSession` global → IIFE `'use strict'` → Node
`module.exports` shim). Nine pure functions, zero platform surface (no
IDB, no `chrome.*`, no DOM, no `Date.now()` / `performance.now()` calls —
V1 code-scan pinned):

- `mediaToMonotonicMs(startMono, timecodeMs)` = `startMono + timecodeMs`
  (media timeline → document clock; encodes the §3.1 assumption that
  timecode 0 ≈ the `start()` call time)
- `wallUtcMs(anchor, mono)` = `anchor.utcEpochMs + (mono − anchor.monotonicMs)`
  (canonical wall derivation, V1-pinned equal to
  `event_envelope.deriveWallUtcMs` on a fixture battery)
- `chunkWallUtcMs(anchor, startMono, timecodeMs)` (composition; `null`
  when `timecodeMs` is null — unknown, never arrival-time-backed)
- `streamStartWallUtcMs(anchor, startMono)`
- `markerMediaOffsetMs(markerMono, startMono)` (may be honestly negative)
- `markerWallUtcMs(anchor, markerMono)` (anchor = the anchor named by the
  marker event's own `clockSegmentId` — no cross-context confusion)
- `streamStartOffsetMs(refStartMono, otherStartMono)`
- `isUsableSyncMarker(payload)` (the 4.11-review-required rule: only
  `'played'`/`'shown'` participate; `'failed'`/`'skipped'` excluded;
  malformed → `false`, never throws)
- `mediaRangeIsContinuous(discontinuityMonos, fromMono, toMono)`
  (closed-interval gap check; the clock continues across 4.9's gaps,
  media must not be interpolated across them)

**Error discipline** (repo convention): `null`/`undefined` → `null`
(unknown is null); non-finite (`NaN`, `±Infinity`) → `null` (platform
garbage is unknown); negative `timecodeMs` → `null` (unusable platform
data, not a domain error thrown into bulk export loops — deliberate,
contract §2); wrong-type non-null → `TypeError`; malformed anchor →
`TypeError` (an anchor is never "unknown null" — the caller resolves it
or does not call); `fromMono > toMono` → `RangeError`. `createTimecode()`
factory for the shared-namespace pattern.

**4.12 persists nothing.** `MANIFEST_KEYS` stays exactly 16, `DB_VERSION`

## The timecodeMs characterization (AC9(d), reported verbatim)

Headless Chrome 154 (`--use-fake-device-for-media-stream`, VP9/WebM)
yielded, over 4 chunks in ~12 s: `timecodeMs = [0, 0, 4654.8, 4831.4]`
— nulls=0, zeros=2, non-decreasing=true. I.e. the first chunks carry
`timecodeMs: 0` (the initial `requestData()` flush before the encoder
advanced), then genuinely advancing media times. One implementation's
behavior is not a spec guarantee (§3.1 of the contract); the ruling
holds regardless, and §7/AC11 re-characterizes on the owner's device.
