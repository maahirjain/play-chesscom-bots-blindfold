## What was built

**New `sync_marker.js`** (offscreen document module; repo pattern:
dependency-free script → guarded `BlindfoldSession` global → IIFE
`'use strict'` → Node shim; fully injected platform surface —
`emitEvent`, `getSessionId`, `sendRelayMessage`, `audioFactory`,
`assetUrl`, `setTimeoutFn`, `newUuidV4`):

- Owns `SYNC_MARKER_EVENT_TYPE = 'sync_marker'` (1.3 convention, flat
  snake_case) and the exact-keys payload constructor
  `createSyncMarkerPayload({markerId, phase, modality, status, error,
  detail})` (TypeError = wrong type/shape incl. malformed uuid;
  RangeError = bad domain value).
- `emitStartMarker()`: mints a fresh uuid-v4 markerId, plays one beep,
  emits the audible event **synchronously with the `play()` call** (no
  await between — the envelope's `monotonicMs` IS the beep time), then
  requests the visible flash via the SW relay.
- `emitStopMarker()`: same, but **two beeps 150 ms onset-to-onset apart**
  (each with its own audible event; the two share the markerId and are
  ordered by the event log's own sequence — no derivable `sequence`
  field persisted). **Defined, not wired**: 4.13 must call it BEFORE
  `recorder.stop()` (the seam is documented in recorder.js and here;
  the section-4 auditor must verify 4.13 wires it).
- **NOT a mixer**: `HTMLAudioElement` only — no `AudioContext`, no
  `MediaStreamDestination`, no `AnalyserNode` anywhere in the file; the
  4.7 code-scan pin passes UNMODIFIED.
- Failure honesty: a synchronous `audioFactory`/`play()` throw → one
  `'failed'` event with the verbatim error. An async `play()` rejection
  cannot retract the already-emitted `'played'` event (events are
  append-only, 2.4): the `'played'` event is the honest record of the
  *attempt* (timestamped at the beep time); the rejection then emits a
  second event with `status: 'failed'` and the verbatim error (the
  honest record of the *outcome*, `detail: 'play-promise-rejected'`).
  Both are true observations; nothing is rewritten. Streams are never
  touched by any marker path.
- Relay `{relayed:false}` → visible `status: 'skipped'` with the honest
  `detail` (`no-target-tab`, `send-failed`, `relay-rejected`,
  `relay-threw`); relay `{relayed:true}` → nothing (the content script
  reports the flash itself).

**New `sync_beep.wav`** (extension root): 880 Hz sine (A5), 250 ms,
44.1 kHz 16-bit mono, 10 ms raised-cosine fade in/out. Generated
deterministically with Python's `wave` module (no opaque binary blob):

```
python3 - <<'EOF'
import wave, struct, math
SR, DUR_S, FREQ, FADE_S, AMP = 44100, 0.25, 880.0, 0.010, 0.8*32767
n = int(SR*DUR_S); fade = int(SR*FADE_S); samples = []
for i in range(n):
    s = math.sin(2*math.pi*FREQ*i/SR); w = 1.0
    if i < fade: w = 0.5*(1-math.cos(math.pi*i/fade))
    elif i >= n-fade:
        j = n-1-i; w = 0.5*(1-math.cos(math.pi*j/fade))
    samples.append(int(AMP*w*s))
with wave.open('sync_beep.wav','wb') as w:
    w.setnchannels(1); w.setsampwidth(2); w.setframerate(SR)
    w.writeframes(struct.pack('<%dh'%n, *samples))
EOF
```

Verified: 11025 frames, peak 26213 (= 0.8·32767), first/last samples 0,
exactly 440 zero crossings (880 Hz).

## Deviations (documented, no product-code deviation from the contract's intent)

1. **The played/failed two-event semantics** (§Failure honesty above):
   the contract's §4 (emit synchronously with `play()`) and §6
   (`play()` rejects → `'failed'` event) are jointly satisfiable only
   this way, since the rejection is unknowable at call time. The
   `'played'` event is the attempt record; the `'failed'` event is the
   outcome record. V1-pinned.
2. **`sessionId` rides the relay messages additively** (offscreen→SW
   and SW→tab): the contract's shapes omit it, but the visible event's
   envelope requires a uuid sessionId and the page's `activeSessionId`
   is unset pre-§5 — the offscreen document's 4.6 no-session guard is
   the authority at marker time. The SW→tab message is
   `{kind:'blindfold-sync-flash', markerId, phase, sessionId}`.
3. **The stop double-beep has no persisted `sequence` field**: the
   contract's exact 6-key payload has no room for one (and the spawn
   brief's `sequence` mention contradicts the contract's §5); the two
   beeps are ordered by the event log's own sequence. Standing rule:
   don't persist derivable values.
4. Test-only: the lazy getters check factory availability before the
   `o.*` injection, so the new suite merges the full factory namespace
   (track_monitor.test.js precedent); cumulative pin evolutions with
   justification comments in all 20 suites' allowlists + the 3 MSG_*
   snapshots + the 6 manifest/retention pins (lifecycle, sender,
   session_store, recording_host ×1, retention ×2).
