# 6.7 build report — Provide repeatable export from retained local data

Implemented PLAN.md §6.7 ("Provide repeatable export from retained local data if a download is interrupted") per `.autodev/evidence/6.7.contract.md`.

## What was built

### Tests (`tests/exporter.test.js`)

**6.7 AC1 — re-export is byte-identical except exportedAtUtc:**
- Runs `exportSession` twice with fake deps (same seeded stores, different `nowUtcIso` values: `14:00:00` vs `15:00:00`).
- Captures both ZIP blobs via the `createObjectURL` fake.
- Unzips both via the system `unzip` binary (6.6 AC1 precedent).
- Asserts: same file list; `metadata.json` and `media-sync.json` are identical except `exportedAtUtc` (each has its own clock value); all other files (events.jsonl, media) are byte-identical.

**6.7 AC2 — full byte-identity with fixed clock:**
- Runs `exportSession` twice with the SAME `nowUtcIso`.
- Asserts the two ZIP buffers are fully byte-identical (`Buffer.equals`).

**6.7 AC3 — Download button stays enabled for re-export:**
- Static pin: asserts the success-path comment "Keep the button enabled for re-export" is present in `session_controls.js`.
- Asserts the only `setDownloadEnabled(false)` is for the Start phase ("while starting"), not after export.

**6.7 AC4 — diff discipline:**
- Asserts 6.7 touches no product files (`exporter.js`, `sw.js`, `manifest.json`, `session_controls.js`, `content.js`, `recorder.js` all untouched in the diff).
- Asserts PLAN.md is unmodified.

### The exportedAtUtc resolution (contract §2.2)

Two exports at different wall-clock times differ ONLY in the two `exportedAtUtc` fields. This is honest and documented:
- `exportedAtUtc` is the one labeled clock read in the pipeline (6.1, 6.3). It records when the export ran.
- It cannot be derived from stored data without fabrication (no stored "export time" exists), so the wall clock is the only honest source.
- Everything else — events.jsonl, media files, ZIP structure, CRCs, paths — is byte-identical.
