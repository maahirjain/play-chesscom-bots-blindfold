## Implementation summary

- `event_envelope.js` (new): `EVENT_TYPES={CLOCK_ANCHOR:'clock_anchor'}`
  (seeded with 1.3's own type only — not a global registry),
  `SOURCE_CONTEXTS=['content_script','service_worker','recording_context']`
  (frozen; no invented popup value), `EVENT_TYPE_RE`
  (`/^[a-z][a-z0-9_]{0,63}$/`), `newEventId()`/`newClockSegmentId()` (UUID
  v4, throw if unavailable), `createClockAnchor` (exactly 3 keys:
  segmentId/utcEpochMs/monotonicMs; epoch ms not ISO strings; monotonic
  unrounded; no timeOrigin), `captureClockAnchor` (performance.now() then
  Date.now(), throws if performance.now unavailable — no silent Date.now
  substitution), `createAnchorEvent`, `createEvent` (exactly **11** keys —
  see correction below; appendSeq hard-coded null; refs default null),
  `requireValidEvent`/`isValidEvent`, pure `deriveWallUtcMs(anchor, t) =
  utcEpochMs + (t − monotonicMs)`.
- Key contract decisions: event types are flat snake_case domain-prefixed
  strings — **no namespacing, no 1.2 amendment** (churning a DONE task for
  aesthetics rejected; prefix filtering works on flat strings; hierarchy
  derivable at analysis time); `sessionId` required, `gameId` uuid-or-
  explicit-`null` (null = session-scoped, e.g. clock anchors); per-event
  wall clock NOT persisted (non-monotonic, derivable via anchor —
  persisting both would violate "no derivable values"); `sourceSeq` is a
  per-(`sourceContext`,`clockSegmentId`) counter owned by the §2.3 sender
  (contract takes it as a validated parameter — honest layering, not
  weakening); `refs` is mechanism-only (`null` or flat `{roleId:
  uuid-v4}`, keys `/^[a-z][a-zA-Z0-9]*Id$/`) with NO role inventory
  (roles belong to §3.2/§3.4/§4.10); source times never rewritten on
  delivery (contract-layer proof: JSON round-trip bit-identical).
- `session_identity.js`, `session_conditions.js` byte-identical (AC21).
- No existing gameplay files modified. No PLAN.md changes.
