# 7.11 contract — Verify permission denial, device loss, storage failure, and interrupted sessions produce explicit incomplete status and recoverable saved data

**Planner:** section-7 planner subagent. **Date:** 2026-10-06.
**Scope:** PLAN.md §7.11. **Branch:** `autodev/logging-instrumentation`.
**Status:** CONTRACT ONLY. No implementation code written. PLAN.md unmodified.

## 1. What "verify" means

PLAN.md §7.11 requires demonstrating that four failure modes each produce
**two** guarantees:

1. **Explicit incomplete status:** the failure is surfaced honestly — the UI
   (5.1's lights, 5.6's badge, 5.10's completion verdict) and the stored
   records (stream status, stop verdict warnings, media-sync.json gaps)
   name the failure. Nothing silently degrades to "complete."

2. **Recoverable saved data:** whatever was successfully captured before the
   failure is retained in IndexedDB and exportable (6.7). The failure does not
   corrupt or delete the good data.

| Failure mode | Where it's handled | Expected incomplete status | Expected recoverability |
|---|---|---|---|
| **Permission denial** (user denies mic/camera/screen) | `stream_starter.js` / `device_selection.js` (4.x) | Stream light shows failed/denied; session can start with reduced streams or refuse honestly (per 4.x contract) | Granted streams record normally; denied streams are explicitly absent (not silently empty) |
| **Device loss** (mic unplugged mid-session) | `track_monitor.js` (4.9) | Track-ended event; stream status degrades; 5.6 badge reflects it | Pre-loss media retained; post-loss gap is explicit |
| **Storage failure** (IndexedDB write fails) | `writer.js` / `sender.js` (2.x) | 5.6's badge never reaches ready (no ack); 5.10's flush reports undelivered events | Events queued in memory are reported as undelivered (honest count), not silently dropped |
| **Interrupted session** (browser crash, SW killed) | `finalizer.js` (4.13) + 6.5 | Segments with `segmentNumber: null` (unfinalized); media-sync.json `unfinalized` gaps; 6.1's completion `unknown` | Chunks written before the crash are in the store; 6.5 numbers them on the fly; export includes them |

## 2. What already exists

- 4.x stream modules: `stream_starter` (permission probing), `device_selection`
  (device enumeration), `track_monitor` (4.9: track-ended/discontinuity).
- 5.6 (readiness badge), 5.10 (completion verdict with warnings).
- 6.3 (media-sync.json gaps), 6.5 (unfinalized numbering), 6.1 (completion
  `unknown`).
- `tests/track_monitor.test.js`, `tests/stream_starter.test.js`,
  `tests/device_selection.test.js`, `tests/sender.test.js`,
  `tests/finalizer.test.js`.

**Gaps identified:**
1. The **four modes as an acceptance matrix** — each mode's status +
   recoverability asserted together — does not exist. The unit tests cover
   mechanisms; 7.11 is the end-to-end guarantee.
2. **Permission denial's session-level outcome** (does the session start with
   reduced streams? refuse? — per 4.x contract) needs pinning at the
   acceptance level.
3. **Interrupted-session exportability**: 6.5 covers numbering, but the full
   "crash → relaunch → export → media present" path deserves an explicit
   test.

## 3. Verification plan

### V1 — static/unit (Node)

- [ ] **AC1.** Permission denial: drive the stream-starter with a denied
  permission; assert the stream result is `{ok: false}` with the denial
  named, the session's `mediaInventory` (6.1) shows zero segments for that
  kind (explicit, not omitted), and other streams are unaffected.
- [ ] **AC2.** Device loss: simulate `track.onended` mid-session; assert the
  discontinuity event is emitted, the stream status degrades, and the
  pre-loss chunks remain in the store (count unchanged).
- [ ] **AC3.** Storage failure: inject a writer rejection; assert the sender
  reports the failure honestly (5.6 badge stays unready / 5.10 reports
  undelivered count), and no event is silently dropped (queue retains it).
- [ ] **AC4.** Interrupted session: create segments with `segmentNumber:
  null` (simulating crash before finalize); run the 6.1–6.6 export path;
  assert the export succeeds, the segments are numbered on the fly (6.5),
  media-sync.json marks them `unfinalized`, and completion is `unknown`
  (never `complete`).

### V2 — integration (headless Chrome)

- [ ] **AC5.** Permission-denied harness: deny mic via Chrome DevTools
  Protocol overrides; start a session; assert the honest degraded status in
  the real SW.
- [ ] **AC6.** Crash-recovery harness: write chunks, kill the SW context
  without finalizing, re-create; assert export recovers the chunks.

### V3 — deferred to owner device

- [ ] **AC7.** On the real device: physically unplug the mic mid-recording;
  confirm the gap is explicit and the pre-unplug audio is intact.
