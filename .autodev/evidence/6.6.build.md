## What was built

### 1. ZIP writer (`exporter.js`, pure)

- **`buildZipParts({files, dosDateTime})`** — hand-rolled STORE-method (method 0)
  ZIP writer. Per file: 30-byte local header + path + raw data Blobs;
  then central directory (46-byte entries); then 22-byte end record.
  All multi-byte fields little-endian. UTF-8 flag (bit 11) set.
  No data descriptors (flag bit 3 NOT set) — sizes/CRCs known upfront.
- **CRC-32:** reuses the existing in-module `crc32Update`/`crc32Finalize`
  (no new CRC code). For JSON files the writer computes CRC over UTF-8 bytes;
  for media it consumes 6.4's precomputed CRC.
- **`buildBundleDir({sessionCategory, dateIso, gameIds, sessionId})`** —
  `<category>/<YYYY-MM-DD>_<gameId>/` (single) or
  `<category>/<YYYY-MM-DD>_session-<sessionId>/` (multi). Category sanitized
  (`[A-Za-z0-9_-]` only → TypeError). Date from `dateIso` (must be valid ISO).
- **`buildDownloadFilename({...})`** — `<category>-<YYYY-MM-DD>-<shortId>.zip`.
- **`dosDateTimeFromIso(isoString)`** — MSDOS date/time encoding. Unparseable
  → MSDOS epoch (1980-01-01); never the wall clock silently (contract §2.5).
- **`requireValidZipPath(path)`** — rejects absolute paths, backslashes,
  `..` segments (fail-closed).

**Verified:** `unzip -t` passes on generated ZIPs; `unzip -p` extracts
byte-identical data; CRCs validate.

### 2. Orchestration (`exportSession`, `exporter.js`)

Async `exportSession({sessionId, stopVerdict, deps})` with injected deps
`{db, downloads?, createObjectURL?, revokeObjectURL?, nowUtcIso?}`:

1. Validate sessionId (UUID-v4) → TypeError; validate stopVerdict (null OK).
2. Snapshot: count events + manifest rows for sessionId (bySessionId).
3. Read `session_metadata` → absent → `{ok:false, error:'session-not-found'}`.
4. Read `conditions` → absent → null (6.1 handles honestly).
5. Extract `clockAnchors` from `clock_anchor` events; `gameStartingFens`
   from `game_started` events (first per gameId wins).
6. `nameSegmentFiles` (6.5) → corrupt manifest → `corrupt-recording_manifest-record:*`.
7. Per segment (6.5's order): read chunks via the 4.13 compound-key-range
   precedent (`{lower:[segmentId,-1], upper:[segmentId,MAX]}` — no index;
   `media_chunks` has no bySegmentId index), `assembleSegmentChunks` (6.4),
   accumulate `chunkStats` with `chunksAfterFinalize` (chunk createdAtUtc >
   manifest finalizedAtUtc).
8. Build 6.1–6.3 JSON (passing `bySegmentId`, `chunkStats`, `clockAnchors`,
   `gameStartingFens`). `'failed'` verdict → `session-not-complete`
   (catches 6.1's throw per reviewer N1).
9. Resolve `dateIso`: earliest usable manifest `createdAtUtc`; none →
   MSDOS epoch (the 1.1 metadata record carries no timestamp — documented
   deviation from the contract's assumption; honest stored-data proxy).
10. `buildZipParts` with JSON files first, then media in 6.5 order.
11. Re-count events + manifest + chunks → mismatch →
    `{ok:false, error:'store-changed-during-export'}` (NO download).
12. `new Blob(parts)` → `createObjectURL` → `downloads.download({url,
    filename, saveAs:false})` → revoke URL → `{ok:true, filename, bytes,
    fileCount}`.

**Failure mapping (all honest):** `session-not-found`, `session-not-complete`,
`store-changed-during-export`, `corrupt-<store>-record:<detail>`,
`download-failed:<reason>`, `downloads-unavailable`. Readonly end-to-end.

## Contract deviations (documented)

1. **Session-start timestamp:** The contract assumed `session_metadata.createdAtUtc`
   exists (§2.2, §11 Q3). It does NOT — the 1.1 record has no timestamp field.
   Resolution: orchestration uses the earliest usable manifest `createdAtUtc`
   as the honest stored-data proxy; none usable → MSDOS epoch (contract §2.5's
   specified fallback). Documented in DECISIONS.md.
2. **No data descriptors:** The contract's §3.1 mentions the precomputed CRC
   "feeds 6.6's ZIP data descriptors (flag bit 3)" — this was the 6.4 planner's
   phrasing. The 6.6 contract §2.3 explicitly says "No data descriptors (flag
   bit 3 NOT set)". Implementation follows the 6.6 contract (no descriptors).
