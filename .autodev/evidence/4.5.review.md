## Verified sound

- **DB_VERSION 1→2 upgrade.** `applySchema()` (`db.js:182`) is idempotent:
  it creates only missing stores/indexes and never deletes. No product code
  enumerates stores for deletion (the 2.9 retention scan is test-only), so the
  new store cannot be wiped by existing code. 2.6 restoration reads
  `session_metadata`/`conditions`/`sequence_state` — untouched stores.
  Mid-session extension update: the SW restarts (clearing `cachedDb`),
  `onupgradeneeded` adds `recording_manifest`, existing data untouched.
- **Manifest mutability.** Justified: 4.10 (clock anchor), 4.12
  (timecode/offsets), 4.13 (finalization) must amend the record, so the
  append-only event log is the wrong home. Single writer (the offscreen
  document via `recordSegmentFormat`); `put` keyed by uuid-v4 `segmentId`
  means no cross-session clobber vector short of a uuid collision.
  `db.js` performs no read-time validation (2.2 rule), so later validator
  widening cannot break reads of 4.5-written records.
- **actualMimeType.** `recordSegmentFormat` takes `requestedMimeType` and
  `actualMimeType` as separate inputs; `fileExtension` is derived from the
  actual via `extensionForMimeType` only, and the diverged requested/actual
  pair is V1-pinned. Nothing in 4.5 can leak the requested string into the
  actual field. The V2 synthetic `actualMimeType` is honestly documented;
  the real `recorder.mimeType` read at stream start is correctly 4.6's to
  prove.
- **fileExtension mapping.** Complete relative to the candidate lists: every
  negotiable type (`video/webm`, `audio/webm`, `video/mp4`, `audio/mp4`)
  maps; unknown → `null`, never fabricated. A real negotiated MIME cannot
  map to `null` unless it falls outside the probed candidate set, in which
  case `null` ("unknown — §6 must not assume") is the honest value.
- **No-session gating on `recorder-get-formats`.** Sound: it is a device
  capability query, emits nothing, carries no PII. Gating it on a session
  would add nothing.
- **Validator widening readiness.** `MANIFEST_KEYS` is frozen, published as
  `BlindfoldSession.MANIFEST_KEYS`, and the exact-keys convention forces
  4.10/4.12/4.13 to widen deliberately. The contract's field-ownership table
  reserves their fields.
- **Scope.** No `new MediaRecorder` in product code (verified by grep and by
  the AC8 comment-stripped pin). No new event types (`event_envelope.js`
  untouched). Content scripts (`content.js`, `chess_utils.js`, `sounds.js`)
  byte-identical. The `sender.test.js` hunk-proof rewrite preserves the
  guarantee (every changed hunk carries a 4.5 marker; verified against the
  actual diff).

## NOTEs

1. **Empty-string `actualMimeType`.** `requireMimeOrNull` accepts `""`; if 4.6
   passes `recorder.mimeType` verbatim from a constructor called without a
   `mimeType` option and the platform reports `""`, the manifest stores `""`
   with a `null` extension. 4.6 should decide whether `""` means unknown
   (normalize to `null`).
2. **Screen candidate list has no vp9-without-opus fallback.** All screen
   candidates pair video with opus; a platform reporting `vp9,opus`
   unsupported but vp9-only supported would fall through to vp8+opus. Minor:
   Chrome supports opus universally.
3. **`put` is last-writer-wins.** No optimistic concurrency on manifest
   records. Fine under the single-writer design (one offscreen document);
   4.10/4.12/4.13 merge-writes should read-modify-write rather than blind
   `put`.
4. **`getFormatSupport` caches the lazily-read MediaRecorder namespace** at
   first construction. A MediaRecorder appearing later would not be picked
   up. Irrelevant in practice (the document context is fixed at load).
5. **Hunk-marker heuristic.** The stray-hunk regex tests whole hunks
   including context lines, so a stray change adjacent to a 4.5 comment
   would pass. Weaker than the old byte-identical pin but documented and
   adequate; future `db.js` changes must keep their markers inside the
   changed hunks.
6. **V2's synthetic payload.** The manifest write path is proven end to end,
   but with a synthetic `actualMimeType`. The real negotiated read is
   4.6's V2 to prove — correctly deferred, not a 4.5 gap.
