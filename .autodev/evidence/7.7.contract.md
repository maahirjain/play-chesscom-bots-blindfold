# 7.7 contract — Verify speech cancellation and actual delivery are distinguishable

**Planner:** section-7 planner subagent. **Date:** 2026-10-06.
**Scope:** PLAN.md §7.7. **Branch:** `autodev/logging-instrumentation`.
**Status:** CONTRACT ONLY. No implementation code written. PLAN.md unmodified.

## 1. What "verify" means

PLAN.md §7.7 requires demonstrating that the speech-event stream lets an
analyst distinguish three outcomes for every utterance:

| Outcome | Meaning | Expected record |
|---|---|---|
| **Delivered** | The utterance played to completion | `utterance_started` → `utterance_completed` (or the contracted "done" event) with matching utterance ID |
| **Cancelled** | The user pressed Esc (or a new utterance preempted it) before completion | `utterance_started` → `utterance_cancelled` with matching ID; NO `utterance_completed` for that ID |
| **Failed** | The speech engine errored | `utterance_started` → `utterance_error` (or the contracted error event) with the error detail; distinguishable from cancellation |

"Distinguishable" means: for any utterance ID in `events.jsonl`, exactly one
terminal event exists, and its type unambiguously identifies the outcome. A
cancelled utterance must never look completed, and vice versa.

## 2. What already exists

- `tests/speech.test.js`:
  - AC2 (`utterance_started` payload), AC3 (clean end), AC4 (cancel
    requests), AC5 (error correlation), AC8 (onDone / promise semantics),
    AC9 (inertness and failure isolation)
- `sounds.js`: the speech wrapper with cancellation.

**Gaps identified:**
1. The **three-way terminal-event exclusivity** (exactly one terminal event
   per utterance ID, type matches outcome) is covered per-module but deserves
   an explicit acceptance assertion.
2. **Preemption** (new utterance cancels the in-flight one): AC4 covers cancel
   requests, but the preemption path (speak `w`, then immediately speak `i`)
   should be pinned as cancellation, not completion, of the first utterance.

## 3. Verification plan

### V1 — static/unit (Node)

- [ ] **AC1.** Deliver: start utterance, let it complete; assert
  `utterance_started` + terminal `completed` with matching ID, no
  `cancelled` for that ID.
- [ ] **AC2.** Cancel: start utterance, cancel via Esc path; assert
  `utterance_started` + terminal `cancelled` with matching ID, no
  `completed` for that ID.
- [ ] **AC3.** Preempt: start utterance A, start utterance B before A
  completes; assert A gets terminal `cancelled`, B gets terminal
  `completed` (when it finishes) — A's ID never shows `completed`.
- [ ] **AC4.** Error: inject a speech-engine error mid-utterance; assert the
  terminal event is the error type (not `cancelled`, not `completed`) and
  carries the error detail.
- [ ] **AC5.** Exclusivity sweep: run AC1–AC4 in one session with multiple
  utterances; assert every utterance ID has exactly one terminal event.

### V2 — not required (speech is faked in tests; the event logic is V1)

### V3 — deferred to owner device (7.8/7.9 context)

- [ ] **AC6.** On the real device: verify actual audio delivery matches the
  `completed` events (spot-check with the audible marker in 7.9).
