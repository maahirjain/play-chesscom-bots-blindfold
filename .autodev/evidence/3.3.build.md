- `visibilityRecorder` created after the 3.2 trackers; `recordInitial('init')`
  called at load (failure-isolated; inert pre-§5). §5 seam documented:
  §5's session-start path must call `recordInitial('session_start')`.
- `setPieceSet(mode, source)` gains optional `source` (default `'api'`);
  records the transition failure-isolated (3.2 SF-1 precedent). The `v`-key
  handler passes `'keyboard'`. `observePieceRenders` re-application path
  unchanged and event-free (no state change).

  - `s`: `getBoardElement() !== null` (its own try/catch)
- `j`, `v`, `Escape` never produce `help_requested` (scope exclusions).
- No help UX changed: all speech calls preserved verbatim.

## Deviations

1. **Validator accepts `from === to`** (no-op handled in `recordTransition`,
   not the validator). The contract's "validates; no-op when from === to"
   was ambiguous about where the same-mode case is rejected; accepting it
   in the validator and no-op'ing in the recorder is the coherent reading
   (a same-mode call is well-formed but not a transition). Test asserts both.
2. **`getBoardElement` exported** (not named in contract) for the `s`
   usable-content test — additive, makeMoveOnBoard 3.2 precedent.
3. **Harness fix (mine, not product):** the non-unique `bySessionId` index
   does not order by appendSeq within a session; the phase-4 check searches
   for the expected transition instead of assuming array position.
4. Test-pin evolutions in 8 suites (allowlist additions for the 3.3 files;
   attempt_tracker's "no 3.3 scope" pin narrowed to 3.4/3.5) — all
   inline-documented, none weakened.
