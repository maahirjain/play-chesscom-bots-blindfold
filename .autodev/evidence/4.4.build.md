# Task 4.4 build report — webcam selection and permission handling

PLAN.md §4.4: "Add webcam selection and permission handling so the
player's face is saved separately from the screen."

Status: BUILT, V1 + V2 verified. PLAN.md unmodified. STATE.json untouched
(coordinator-owned). Nothing committed.

## What was built

Per `.autodev/evidence/4.4.contract.md` (AC1–AC8 V1, AC9–AC11 V2, AC12
V3-deferred to §7).

### `device_selection.js` (the only factory change)

1. **Probe constraints kind-branch (the genuine gap fix, contract §1).**
   `runPermissionProbe` built `{ audio: ... }` unconditionally; it now
   builds `{ video: { deviceId: { exact } } }` / `{ video: true }` for
   `kind: 'videoinput'` and keeps the audio branch for `audioinput`.
   No `audio` key ever appears in a video probe (V1-pinned via a
   getUserMedia spy). No resolution/framerate/facingMode policy —
   4.6's decision.
2. **Validator error messages parameterized (contract §2 builder
   note).** `requireValidPermissionChangedPayload` /
   `requireValidDeviceSelectedPayload` took an optional second argument
   (the event-type name, defaulting to the `microphone_*` pair for
   backward compatibility). The factory's internal emit calls pass the
   instance's names, so 4.4 failures blame `camera_*`, never
   `microphone_*` (AC6).

### `recorder.js` (channel wiring)

- A second selector instance: `getCameraSelector()` with
  `kind: 'videoinput'` (beside `getMicSelector()`; independent
  instances; `o.cameraSelector` injection for tests).
- The `cam-*` family on 4.1's envelope: `cam-list-devices`,
  `cam-select`, `cam-request-permission`, `cam-get-state` — mirroring
  the `mic-*` family exactly, same failure isolation (3.2 SF-1
  precedent), same channel error vocabulary (`unknown-device` /
  `invalid-request` / `internal-error`).
- `recorder-set-session` arms/disarms both selectors (shared seam);
  session activation announces the camera selection once with its
  actual source (`user` / `restored`).
- `restoreDevices()` restores the camera selector best-effort — and
  was repaired to await **all** selector restores (see deviation 2).

### Boundaries honored

- No UI (§5). No manifest changes (extension `getUserMedia` video needs
  no manifest permission, 4.2 precedent). No `MediaRecorder`, no chunks,
  no retained streams (probe-then-stop: every probe track stopped
  before the probe resolves; 4.6 re-acquires at Start). "Saved
  separately from the screen" is 4.6's stream wiring — 4.4 must not and
  does not build it. Content scripts byte-identical.

## Deviations

1. **No deviations from the contract's design.** The implementation
   follows the contract's reuse plan exactly.
2. **Repair found during V1: `restoreDevices()` awaited only the first
   selector's restore (real race).** The old implementation returned the
   first non-null restore promise; a camera-restore test (restore →
   `await restoreDevices()` → `getState()`) failed because the camera
   restore was still in flight. Repaired to `Promise.all` over all
   three selectors' best-effort restores (each rejection swallowed to
   null; the function still never throws). Pre-existing behavior for
   mic/capture is preserved and improved; documented here and in
   DECISIONS.md §4.4.
