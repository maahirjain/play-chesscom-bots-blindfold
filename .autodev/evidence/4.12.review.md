## The key judgment: "persist nothing" (focus area 1)

PLAN.md §4.12: "Save timecode/offset information needed to align each media
segment with event time; do not use chunk-arrival time as exact frame time."

The contract's §0.1 reading note says the "save" half is satisfied in
aggregate — 4.6 saved per-stream starts, 4.8 saved raw `timecodeMs`,
4.10 saved the `clockSegmentId` link, 4.11 saved marker source timestamps —
and that persisting 4.12's computed offsets would violate the standing
no-derivable-values rule (repo AGENTS.md; user prompt: "Do not unnecessarily
persist derivable values").

Judgment: **faithful reading, not a weakening.** Every one of the nine
offsets is a pure function of already-stored values on already-identified
clocks; persisting them would be textbook derivable-value persistence and
would create a second source of truth that could drift. PLAN's requirement
is that the information needed for alignment be *available* — it is
(V1-pinned functions over stored inputs). The reading is recorded durably
in the contract and DECISIONS.md `## 4.12` with an explicit auditor remedy
(deliberate, documented widening if the section-4 auditor disagrees), which
is exactly the honest way to handle a judgment call. No silent weakening.
PLAN's second clause (arrival time ≠ frame time) is honored structurally:
no 4.12 conversion even accepts `receivedAtMonotonicMs` as a parameter.
