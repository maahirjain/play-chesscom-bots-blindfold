## 3. Contract verification (code read directly)

### 6.2 — `buildEventsJsonl({events})` (exporter.js:379)

- **appendSeq ordering:** pre-validates every event's `appendSeq`
  (`requireValidAppendSeq`, exporter.js:351), rejects duplicates,
  then stable-sorts an index array by `appendSeq` ascending.
  Contract §3.1 satisfied.
- **Verbatim passthrough:** each line is `JSON.stringify(events[i])`
  with no key add/remove/reorder. Contract §3.3 satisfied.
- **No metrics / no position filtering:** the function adds nothing
  and strips nothing (AC3 test confirms `move_confirmed` gains no
  `fen`/`san`/`pgn`/`moveNumber`/`durationMs` keys, and the
  `game_started` FEN + recovery checkpoint survive). Contract §3.4–3.5
  satisfied.
- **Malformed input:** non-array → TypeError; non-object element →
  TypeError naming the index; null/negative/non-integer/NaN
  `appendSeq` → TypeError naming the `eventId` and index;
  duplicates → TypeError. Contract §5 satisfied.
- **Byte-stability:** frozen envelope key order → deterministic
  `JSON.stringify`; empty input → empty string; trailing `\n`.
  Contract §3.2, §3.6 satisfied.

### 6.3 — `buildMediaSyncJson({...})` (exporter.js:619)

- **Schema (§3):** top-level key order is exactly
  `segments, knownGaps, stopVerdict, exportedAtUtc`; per-segment key
  order is exactly the contract's 17-key list (verified against
  `buildSyncSegment`, exporter.js:564). 2-space pretty-print.
  Contract §3 satisfied.
- **ONE computed value:** `mediaStartWallUtcMs` =
  `anchor.utcEpochMs + (streamStartedAtMonotonicMs - anchor.monotonicMs)`
  (exporter.js:556), null when the anchor or start time is unusable,
  never rounded. The V1 golden test pins `1000500.5` (float, no
  rounding). Contract §3 open question 2 resolved per contract.
- **Known gaps:** session-level echoes 5.10's warning vocabulary
  verbatim (`warnings.slice()`); absent verdict →
  `['stop-verdict-unavailable']` with `stopVerdict: 'unknown'`
  (never fabricated `'complete'`). Per-segment vocabulary:
  `unfinalized`, `flush-timed-out` (kind-level), `stream-failed`,
  `chunks-after-finalize:<N>`, `missing-clock-anchor`,
  `missing-stream-start-time` (exporter.js:568–594). Contract §4
  satisfied.
- **`'failed'` verdict:** plain `Error('exporter: session-not-complete
  ...')` — fail-closed (6.1 precedent). Contract §3 satisfied.
- **Deterministic ordering:** `compareSegments` (exporter.js:536)
  sorts kind (microphone, screen, webcam) → segmentNumber
  (nulls last) → createdAtUtc → segmentId. Contract §3 satisfied.
- **Purity:** no I/O, no IndexedDB, no ID minting; only clock read
  is the labeled `exportedAtUtc` via injected `nowUtcIso`.
  Inputs not mutated (`manifestRecords.slice().sort(...)`).
  Contract §6 (AC6) satisfied.

### Edge case noted (not a defect)

`buildSegmentGaps` checks the raw `record.clockSegmentId` for the
`missing-clock-anchor` gap while `buildSyncSegment` normalizes empty
strings to `null` in the output. A manifest record with an
empty-string `clockSegmentId` would get a `missing-clock-anchor`
gap. This follows the contract's letter ("non-null"), is fail-safe
(adds a gap rather than hiding one), and is not a real data case
(the 4.10 link is a UUID or null; `requireValidManifestRecords`
requires a non-empty `streamKind` but does not constrain
`clockSegmentId` — acceptable leniency).
