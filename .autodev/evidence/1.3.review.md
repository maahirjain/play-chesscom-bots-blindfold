### SHOULD_FIX

1. **Stale "12 keys" comments in the deliverable contradict the enforced
   contract.** `event_envelope.js:289` ("Creates an event envelope: exactly
   the 12 keys") and `event_envelope.js:343` ("Full envelope validation: all
   12 keys present") both say 12. Behavior is 11 (`EVENT_KEYS.length` drives
   `requireExactKeys`; AC1 test pins 11). The coordinator explicitly
   corrected (12)→(11), and I verified the §3.3 shape has exactly 11 keys
   (eventId, eventType, sessionId, gameId, sourceContext, sourceSeq,
   clockSegmentId, monotonicMs, appendSeq, refs, payload). A future task
   reading "12" could be misled into adding a key. Fix both comments to 11.
   (Same typo exists in coordinator-owned records — contract line 351 and
   build report line 17 — noted below for coordinator cleanup; the code
   comments are the ones that ship with the deliverable.)

2. **Test gap: appendSeq smuggling not pinned.** AC16 asserts `appendSeq`
   is `null` at creation but never passes `appendSeq` in the options object.
   The implementation is correct (ignores `options.appendSeq`), but a future
   refactor could silently start honoring it. Add a test:
   `createEvent({...valid, appendSeq: 7}).appendSeq === null`.

3. **Test gap: `crypto` present but `randomUUID` missing.** `newUuid()`
   handles it (`typeof cryptoObj.randomUUID !== 'function'` → plain Error),
   but the test only covers `crypto === undefined`. Add the partial-
   capability case.

4. **Test gap: `captureClockAnchor` with an invalid supplied segmentId.**
   Implementation throws TypeError via `requireUuidV4` before touching the
   clocks (correct); no test covers it.

5. **Process: record the error-class deviation in DECISIONS.md at task
   close, and amend the contract §2.10 parenthetical.** The contract's §2.10
   lists "non-uuid IDs" under RangeError, contradicting its own AC5/AC15
   (explicitly TypeError) and the 1.1 precedent
   (`session_identity.js:143`: malformed gameId → `TypeError('gameId must be
   a uuid-v4 string')`; `session_conditions.js:91-92`: closed-vocabulary
   violations → RangeError *including non-strings*). The builder's choice —
   TypeError for all malformed IDs, RangeError for domain violations of
   non-ID fields (event-type syntax, sourceContext, sequences, monotonicMs,
   refs role names) — is exactly consistent with 1.1/1.2 and the concrete
   ACs. **Decision: TypeError stands; the §2.10 parenthetical is the
   outlier and should be corrected by the coordinator**, not by weakening
   the code to match a parenthetical.

### NOTE

1. Contract §3.1 table row for `requireValidEvent` says "(all 12 keys...)" —
   coordinator typo; behavior is 11 (verified above).
2. Build report line 17 says "exactly 12 envelope keys" — evidence typo;
   behavior is 11 (verified above).
3. Refs role regex `/^[a-z][a-zA-Z0-9]*Id$/` permits semantically odd role
   names (`constructorId`). Verified safe: `__proto__` fails the regex
   (rejected loudly, the 1.2 lesson applied); every value must be UUID v4;
   the record is a fresh frozen object, so no inherited-setter or
   pollution hazard. Ugly names are a future-task naming concern, not a
   safety defect.
4. **Event-type convention decision (flat snake_case, no namespacing, no 1.2
   amendment) is sound, not a dodge.** PLAN 1.3.1 imposes no taxonomy
   requirement; namespacing would have forced churn on a DONE, frozen,
   47-test-passing 1.2 contract for zero functional gain. The convention is
   enforced in code (`EVENT_TYPE_RE`, every envelope validated), and
   `'conditions_changed'` demonstrably round-trips (AC4). Residual risk: no
   *runtime* type registry — collision prevention across §3.x/§4 tasks
   relies on each task's contract extending the §2.2.1 vocabulary table.
   That is honest layering (a central registry would be incomplete by
   construction), but the coordinator should treat "vocabulary table
   extended?" as a per-task review checklist item.
5. Headless-Chrome renderer smoke (contract §5: real `performance`/`Date`
   in a renderer, incl. `captureClockAnchor`) was not run by the builder and
   is assigned to the behavioral verifier. The AC10 call-order test with
   stubbed globals is genuine (stubs record call sequence; it would fail if
   the implementation read `Date.now()` first) — not a mirror test — but it
   does not replace the renderer smoke.
6. `createClockAnchor` treats `segmentId: null` as omitted (generates fresh),
   mirroring 1.1's `addGameToSession`. Asymmetric with `gameId` (where null
   is preserved as "session-scoped"), but semantically justified: null
   segmentId carries no meaning distinct from omitted. Documented in the
   build report.
7. `requirePayload` freezes the caller's payload object in place while
   `requireRefs` builds a fresh frozen copy. Asymmetric but documented in
   the contract ("shallow-frozen by createEvent") and harmless: frozen
   payloads are safely reusable across calls.
8. `requireSourceContext` throws RangeError for non-strings (e.g.
   `undefined`), consistent with the 1.2 precedent ("anything outside the
   domain is a RangeError, including non-strings",
   `session_conditions.js:91-92`) and AC6's "anything else → RangeError".
   Not a defect, but the general "TypeError = wrong type" phrasing in the
   error-convention docs is slightly idealized; the codebase's actual rule
   is "closed-vocabulary violations → RangeError", which this follows.

## Requirement-by-requirement adversarial assessment

- **1.3.1 envelope completeness:** all six required elements present
  (eventId, eventType, session/game ref, sourceContext, sourceSeq, payload);
  exactly 11 keys, no more/no fewer, frozen. `sourceSeq` as a validated
  caller-supplied parameter (counter owned by §2.3) is honest layering, not
  a weakening — the envelope carries the field with defined per-segment
  semantics, and the contract explicitly defers counter *state*.
- **1.3.2 anchor:** exact 3-key shape, epoch-ms (not ISO), unrounded
  monotonicMs, no `timeOrigin`. Capture order is genuinely
  `performance.now()` then `Date.now()` (verified in code and by a real
  order-asserting test). Missing `performance.now` → plain Error, no silent
  `Date.now()` substitution. Multiple anchors per segment permitted but not
  required — documented extension point, no code.
- **1.3.3 source timestamping:** `monotonicMs` stored verbatim (fractional
  round-trip asserted with `Object.is`); no per-event wall clock;
  `deriveWallUtcMs` formula correct, anchor self-consistent
  (`deriveWallUtcMs(a, a.monotonicMs) === a.utcEpochMs` exactly). Nothing
  fabricates occurrence times.
- **1.3.4 append sequence:** field + null-at-creation + never-rewrite
  invariant delivered; assignment explicitly deferred to §2.4 with the
  dependency recorded (AC18). `requireValidEvent` accepting non-null
  appendSeq is required for §2.4 intake of stored events, not a hole.
- **1.3.5 references:** mechanism only, no role inventory in code or tests
  beyond illustrative examples (`attemptId`, `moveId` used as fixtures).
  Values UUID-validated, keys regex-validated, record frozen. AC20 deferred
  to emitting tasks with dependency recorded.
- **Downstream service:** §2.4 dedup (eventId as key, UUID v4, no weak-ID
  fallback) ✓; §2.5 retry (same eventId on retry; frozen envelope)
  ✓; §3(a) (clock_anchor event rows) ✓; §4.10–§4.12 (segment→anchor
  linkage via refs/eventId; `deriveWallUtcMs` for alignment) ✓; §6.2
  (appendSeq ordering; occurrence order via monotonicMs+anchor, never file
  position) ✓.
- **Scope:** no sender/queue/retry/storage/export/media/analysis code; no
  §3.x types; no manifest changes; no gameplay changes; no PLAN.md edits;
  no credentials/network. `isValidEvent` is a contract-listed §2.4 intake
  helper, not creep.
- **Privacy:** envelope carries only random IDs, type strings, counters,
  and timestamps. No PII.
