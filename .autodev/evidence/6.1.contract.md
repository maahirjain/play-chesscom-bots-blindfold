# 6.1 contract — Generate metadata.json from stored context and observed completion status

**Planner:** section planner subagent. **Date:** 2026-10-06.
**Scope:** PLAN.md §6.1. **Branch:** `autodev/logging-instrumentation`.
**Status:** CONTRACT ONLY. No implementation code written. PLAN.md unmodified.
STATE.json untouched (coordinator-owned).

## 1. Scope

PLAN.md §6.1: "Generate metadata.json from stored context and observed
completion status."

**PLAN evidence:** the §(a) export table defines metadata.json's raw
data: "IDs; session category; protocol/schema/extension versions;
initial conditions; observed/manual sources; game starting FEN; media
inventory and collection coverage/completeness."

**What 6.1 does:** Add a pure builder function (SW-side exporter
module, per the section architecture) that takes the session's stored
records plus 5.10's stop verdict and returns the exact
`metadata.json` string for the bundle. 6.1 owns the *content* of
metadata.json; 6.6 owns putting it in the ZIP.

**What 6.1 does NOT do:** It does not read IndexedDB itself (the
exporter orchestration in 6.6 does the reads and passes plain records
in — the builder is pure and Node-testable). It does not compute
metrics, infer missing data, or fabricate completion status. It does
not touch events.jsonl (6.2), media-sync.json (6.3), or media files
(6.4/6.5).

## 2. Inputs

The builder function signature (names at the builder's discretion):

```
buildMetadataJson({ metadata, conditions, manifestRecords, stopVerdict, eventCount })
```

| Input | Source | Required? |
|-------|--------|-----------|
| `metadata` | `session_metadata` store (1.1 record, verbatim) | Yes — absent → honest export error (a session without metadata was never properly started; do not invent it) |
| `conditions` | `conditions` store (1.2 record, verbatim) | No — absent → `conditions: null` (unknown = unknown) |
| `manifestRecords` | `recording_manifest` bySessionId (18-key records) | Yes — may be empty (a session with no media is honest data); drives the media inventory |
| `stopVerdict` | 5.10's retained `{stopResp, flushResult, verdict, warnings}` passed in the `export-request` message | No — absent → `completion: { verdict: 'unknown', warnings: [], note: 'stop-verdict-unavailable' }` (never fabricate 'complete') |
| `eventCount` | count of the session's rows in `events` (from the §3 before-proof) | Yes — coverage reporting |

All inputs are plain data. The function performs no I/O, reads no
clock, mints no IDs.

## 3. metadata.json schema (exact)

Top-level keys, in this order (stable output for 6.7's byte-identity):

```jsonc
{
  "sessionId": "<uuid-v4>",           // from metadata
  "gameIds": ["<uuid-v4>", ...],      // from metadata, ordered; length > 1 flags shared session (5.9)
  "sessionCategory": "baseline|training|evaluation",
  "versions": {
    "schemaVersion": "1.0.0",        // 1.1 SCHEMA_VERSION
    "extensionVersion": "<string>",  // 1.1 record
    "protocolVersion": "<string|null>" // user-maintained protocol.md version, may be null (unknown)
  },
  "training": {                       // 5.2's fields, verbatim from metadata
    "trainingApproach": "<string|null>",
    "verbalScaffolding": "<string|null>"
  },
  "initialConditions": {              // 1.2 record verbatim, or null
    // seven CONDITION_FIELDS, each {value, source} — observed/manual
    // sources preserved exactly as stored (5.4's manual-vs-observed)
    "playerColor": {"value": "white", "source": "observed"},
    ...
  },
  "gameStartingFen": {                // per gameId; null where unknown
    "<gameId>": "<FEN string|null>"
  },
  "completion": {
    "verdict": "complete|complete-with-warnings|unknown",
    "warnings": ["<warning-string>", ...],  // 5.10's warnings verbatim
    "finalizedAtUtc": "<iso|null>",   // from stopVerdict.stopResp (4.13)
    "undeliveredEvents": "<number|null>" // from flushResult.pending
  },
  "mediaInventory": {                 // derived from manifestRecords, facts only
    "microphone": {"segments": 2, "finalized": 2, "formats": ["audio/webm"]},
    "screen": {"segments": 1, "finalized": 1, "formats": ["video/webm"]},
    "webcam": {"segments": 0, "finalized": 0, "formats": []}
    // a kind with zero segments = missing/failed stream, explicit (PLAN §(a))
  },
  "coverage": {
    "eventsStored": 142,             // eventCount input
    "gamesObserved": 1               // gameIds.length (facts, not metrics)
  },
  "exportedAtUtc": "<iso>"           // export time — the one non-session
                                     // timestamp; labeled as such
}
```

**Field rules (raw-data discipline):**
- Every value is copied from the inputs or derived by counting —
  no computed metrics (no durations, no rates, no move counts beyond
  the stored event count, no accuracy).
- `gameStartingFen`: the FEN each game started from. Source: the
  first `game_started`-equivalent observation per gameId if the
  event stream carries it; else the 1.2 conditions' starting FEN
  (session-level, applied to gameIds[0]); else `null`. The builder
  documents the exact precedence. Never synthesize a FEN.
- `initialConditions`: the stored 1.2 record verbatim, including
  per-field `{value, source}` — "observed/manual sources" per the
  export table. The five 5.2 placeholder fields (`{value:null,
  source:'manual'}`) export as stored: null is honest.
- `completion.verdict`: mapped directly from 5.10's verdict.
  `'failed'` (stop itself failed) → export refuses honestly
  (`{ok:false, error:'session-not-complete'}` at the orchestration
  layer — 6.1's builder returns the verdict; 6.6's orchestration
  enforces the refusal). A bundle must never claim to document a
  session whose Stop failed.
- `exportedAtUtc`: the wall-clock time of export, explicitly labeled
  — it is export metadata, not session data. (The one allowed
  non-stored timestamp; everything else is stored facts.)

## 4. Observed completion status (5.10 → 6.1 mapping)

| 5.10 verdict | metadata.json `completion` |
|---|---|
| `'complete'` | `{verdict:'complete', warnings:[], ...}` |
| `'complete-with-warnings'` | `{verdict:'complete-with-warnings', warnings:[...verbatim...], ...}` — includes `*-flush-timed-out` and `N-events-undelivered` (the audit's "known gaps" input, also consumed by 6.3) |
| absent (null) | `{verdict:'unknown', warnings:[], note:'stop-verdict-unavailable'}` — fail-closed toward unknown, never toward complete |
| `'failed'` | builder returns the verdict; orchestration refuses the export |

`finalizedAtUtc` comes from `stopResp.finalizedAtUtc` (4.13's mark);
`undeliveredEvents` from `flushResult.pending`. Both nullable.

## 5. Acceptance criteria

### V1 — static/unit (Node, no IndexedDB)

- [ ] **AC1.** Golden-shape test: fixture inputs (multi-game metadata
  with `gameIds.length === 2`, mixed observed/manual conditions,
  three-kind manifest, complete verdict) produce byte-exact
  metadata.json matching the §3 schema — key order stable,
  pretty-printed with 2-space indent (human-readable; events.jsonl
  is the line-oriented one).
- [ ] **AC2.** Null-honesty: absent conditions → `"initialConditions":
  null`; absent stopVerdict → `completion.verdict === 'unknown'`
  with the note; never `'complete'` on missing input.
- [ ] **AC3.** No fabrication: a fixture with zero manifest records
  yields explicit zero-segment inventory (not omitted kinds); a
  fixture with `gameStartingFen` unresolvable yields `null` per
  gameId (not a synthesized FEN).
- [ ] **AC4.** Purity: the builder reads no clock except for the
  single labeled `exportedAtUtc` (injected `nowUtcIso` for
  testability); performs no I/O; mints no IDs; throws
  `TypeError` on malformed input (never silently defaults).
- [ ] **AC5.** Multi-game flag: `gameIds.length > 1` is preserved
  verbatim (the shared-session flag is the array length — no extra
  flag field invented).
- [ ] **AC6.** Diff discipline: new code lives only in the exporter
  module (+ its test file); no changes to stores, writer, manifest,
  or content scripts; no new event types/messages/stores/
  permissions (6.6 owns the permission + message); PLAN.md
  unmodified.

### V2 — integration (real headless Chrome, repo-path argv)

- [ ] **AC7.** Seed a session via the real paths (session-save,
  manifest writes): run the metadata builder against the real
  stored records; assert the output parses and every ID in it
  matches the seeded records byte-for-byte.
- [ ] **AC8.** Regression: full V1 suite green.

### V3 — deferred to §7 / owner device

- [ ] **AC9.** Real session export: metadata.json's IDs, conditions,
  and completion match what the device observed; the file opens as
  valid JSON after ZIP extraction.
