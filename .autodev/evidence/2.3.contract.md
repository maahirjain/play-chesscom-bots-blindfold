# Task 2.3 Contract — Content-script event sender (timestamp + queue observations immediately)

## 1. Scope

PLAN.md §2.3 says (quoted verbatim):

> 2.3. Add a content-script event sender that timestamps and queues observations immediately.

This task creates the **content-script-side sender**: it timestamps each
observation at the moment of observation (1.3 clock), builds the frozen
11-key envelope, appends it to an in-memory FIFO queue immediately, and
pumps the queue to the service worker via `chrome.runtime.sendMessage`
with a stop-and-wait acknowledgment discipline. It defines the sender→SW
message shape and the ack protocol it expects, **without implementing the
SW intake side** (that is §2.4's contract).

Design inputs inherited from 1.3 §7 ("Downstream needs this contract must
serve — §2.3 (sender)"):
- calls `captureClockAnchor()` at context startup;
- emits the `clock_anchor` event first (`createAnchorEvent`, conventionally
  `sourceSeq: 0`);
- owns the per-segment `sourceSeq` counter (starts 0, +1/event);
- captures `performance.now()` at the observation point and passes it as
  `monotonicMs` (the contract layer never captures event times itself);
- never rewrites source times on retry;
- **open design input:** decide segment/anchor creation when no session is
  active (envelope requires `sessionId`) — resolved in §2.5 below.

## 2. Design decisions

### 2.1 Module layout: `sender.js` + manifest + one wiring line

- **New file `sender.js`** at repo root, in the Section-1 script pattern
  (guarded `BlindfoldSession` global, IIFE `'use strict'`, Node
  `module.exports` shim). Unlike the pure contract modules it is
  **content-script-specific**: it reads `performance.now()` and
  `chrome.runtime.sendMessage`, both resolved **lazily** (per call/attempt,
  never at load) so the module loads in Node and in the SW for tests.
  The header states this honestly.
- **Manifest `content_scripts[0].js`** becomes
  `["event_envelope.js", "sender.js", "sounds.js", "chess.min.js",
  "chess_utils.js", "content.js"]` — dependencies before dependents; the
  relative order of the four pre-existing entries is unchanged, so gameplay
  behavior cannot shift at the manifest layer. Only `event_envelope.js` is
  added as a dependency (the sender needs `createEvent`,
  `createAnchorEvent`, `captureClockAnchor`); `session_identity.js`,
  `session_conditions.js`, `game_records.js` are §3's decision, not 2.3's.
- **`content.js`** gains the minimal instantiation at top-level (before any
  observation wiring):
  `BlindfoldSession.sender = BlindfoldSession.createSender();`
  Published on the shared global so §3 emitters in `chess_utils.js` and
  `sounds.js` can reach it. No other content.js change.

Why a new file, not inline in content.js: the sender is a self-contained
unit with its own queue/clock/ack state, its own test surface, and two
future consumers (§3.2 in chess_utils.js, §3.4 in sounds.js) that must not
depend on content.js's UI wiring. Inline would couple instrumentation to
UI code.

### 2.2 Timestamp-at-observation guarantee

`emit()` is **synchronous** through timestamping and queueing:

1. Read `performance.now()` **first**, before any other work in `emit()`.
2. Assign the next `sourceSeq` (per-segment counter, starts 0).
3. Call `BlindfoldSession.createEvent({eventType, sessionId, gameId,
   sourceContext: 'content_script', sourceSeq, clockSegmentId:
   anchor.segmentId, monotonicMs, payload, refs})` → frozen envelope.
4. Append to the in-memory FIFO queue **immediately** (before any send is
   attempted).
5. Kick the async pump (fire-and-forget; the pump never throws).

Because steps 1–4 are synchronous, the envelope's `monotonicMs` is the
observation time, never the send time — even if the SW is dead and the
event sits queued for the whole page lifetime. The pump never mutates a
queued envelope (1.3: source times are never rewritten on delivery).

### 2.3 Clock anchor and the no-session case (resolves 1.3's open input)

- `createSender()` captures the clock anchor **at construction**
  (`captureClockAnchor()` with a fresh segment UUID) — that is "context
  startup" for one content-script instance = one segment per page load.
  If `performance.now` is unavailable the constructor throws plain `Error`
  (honest failure, per 1.3 convention).
- The `clock_anchor` event is emitted **lazily on first `emit()` per
  `sessionId`**: the sender tracks which sessionIds have been anchored in
  this segment. First `emit()` for session S sends `createAnchorEvent({
  sessionId: S, sourceContext: 'content_script', sourceSeq: 0, anchor})`,
  then the observation event (`sourceSeq: 1`). A later `emit()` with a
  different sessionId S2 re-emits the (same, segment-scoped) anchor with
  `sessionId: S2` before S2's first observation — the anchor payload is
  segment-scoped, the event row is session-scoped, and this keeps every
  session's export self-describing.
- Rationale: the envelope requires `sessionId`, and sessions are created
  by §5 (Start wiring), which does not exist yet. Capturing the anchor at
  construction but emitting it session-bound is the only design that
  satisfies both "anchor at context startup" and "envelope requires
  sessionId" without inventing a session.

### 2.4 Queue discipline: unbounded in-memory FIFO, stop-and-wait

- **Unbounded** FIFO array. Rationale: observations are human-rate (moves,
  utterances, help requests — units per second); a queued envelope is a
  few hundred bytes; even 10k queued events ≈ 5 MB, acceptable for a page
  lifetime. A bound would force drops, violating the never-silently-drop
  invariant; persistent failure surfacing is §2.8's job. (Reviewer
  stress-test point.)
- **Stop-and-wait, in-order attempts**: the pump sends the queue head,
  awaits the ack, dequeues on ack, then sends the next. Exactly one event
  is ever "unacknowledged," which makes 2.5's retry target precise. (1.3
  notes delivery order may differ from occurrence order; stop-and-wait
  gives the writer occurrence order in the common case, and `appendSeq`
  is the durable order regardless.)
- The queue is **context-scoped**: page unload discards unacked events.
  Loss across segments is detectable via `sourceSeq` gaps (1.3 §2.5) —
  preserved as evidence, not hidden. Persisting the queue is out of scope
  (2.5 retries "while the originating context remains available").

### 2.5 Transport: `chrome.runtime.sendMessage` (one-shot, wakes the SW)

- `chrome.runtime.sendMessage` (promise form), **not** `runtime.connect`.
  Rationale: one-shot request/response matches the ack protocol exactly;
  it wakes an idle SW for delivery; a persistent Port would defeat MV3
  idle semantics for no benefit at human event rates.
- Transport resolved **lazily per send attempt**:
  `options.transport || (globalThis.chrome?.runtime?.sendMessage)`.
  `options.transport` is the test injection. If no transport exists
  (e.g. Node), the event stays queued — `emit()` never throws for
  transport reasons.
- The pump is bulletproof: every attempt is wrapped so no rejection
  escapes (no unhandled promise rejections from the sender, ever).

### 2.6 Sender→SW handoff contract (2.4 implements the SW side)

Message (sender → SW), fresh plain object per attempt (structured-cloned):

```js
{ kind: 'event', event: <frozen 11-key envelope> }
```

`kind: 'event'` is the discriminator — the SW will handle other message
kinds in the future (2.4 defines its intake; this contract only fixes what
the sender sends).

Ack (SW → sender; **defined here, implemented by §2.4**):

```js
{ ok: true, eventId: <uuid> }              // durable write done
{ ok: false, eventId: <uuid>, error: <string> }  // write failed, keep queued
```

Sender's ack handling (stop-and-wait on the queue head):
- `response.ok === true && response.eventId === head.eventId` → dequeue,
  clear `lastError`, send next.
- `response.ok === false` (eventId matches) → keep queued, set
  `lastError = response.error`, **stop the pump** (2.5 resumes).
- `undefined` response (no SW listener — the expected state until 2.4
  lands), shape mismatch, eventId mismatch, or transport rejection →
  keep queued, set `lastError` (`'no-ack'` / `'transport-error:<name>'`),
  stop the pump. Never dequeue without a matching positive ack.

2.4 owns (explicitly not here): the `onMessage` listener, envelope
validation, dedup by `eventId`, `appendSeq` assignment, commit-awaiting
semantics (DECISIONS.md #9a), and the DataError surface (DECISIONS.md
#9b).

### 2.7 Public API (`BlindfoldSession`)

| Signature | Behavior |
|---|---|
| `createSender(options?)` → sender | Captures the clock anchor now (throws plain `Error` if `performance.now` unavailable). `options.transport` overrides the send function (tests). Returns the sender instance. |
| `sender.emit({eventType, sessionId, gameId, payload, refs?})` → envelope | Synchronous through queueing (§2.2). Minimal shape check (object → `TypeError`); field validation delegated to `createEvent` (`TypeError`/`RangeError` per 1.3). Lazily emits the session's `clock_anchor` first (§2.3). Returns the frozen envelope. Kicks the pump. |
| `sender.flush()` → `Promise<{delivered, pending}>` | Runs the pump to completion now: attempts delivery until the queue drains or an attempt fails. The primitive §2.5's retry policy will call. |
| `sender.pendingCount()` → integer | Queue length. |
| `sender.getStatus()` → `{pendingCount, lastError, transportAvailable}` | For §2.8's status indicator. `lastError` is `null` when clear. |
| `sender.anchor` | The frozen clock anchor (read-only property). |
| `SENDER_MESSAGE_KIND` | Frozen `'event'` discriminator constant. |

`emit()` returns the envelope so §3 emitters can link follow-ups (e.g.
utterance → move refs) without re-reading the queue.

### 2.8 Error conventions (AGENTS.md)

- `emit(nonObject)` → `TypeError` (wrong shape). Bad envelope fields →
  `TypeError`/`RangeError` from `createEvent` (1.3's validation, not
  re-implemented).
- Unavailable `performance.now` at construction → plain `Error` (never a
  `Date.now()` substitution — 1.3 convention).
- Transport absence/failure → **never throws**; the event stays queued and
  `lastError` records it (surfacing is §2.8's).
- The pump never lets a rejection escape.

## 3. Exact deliverables

### 3.4 New test: `tests/sender.test.js` (`node --test`, no framework)

V1 with injected mock transport (no `chrome.*` in Node):

- Module loads with `chrome` undefined; exposes `createSender`.
- `emit()` timestamps at observation: `t0 = performance.now(); env =
  sender.emit(...); t1 = performance.now()` with a transport capturing
  send time `t2` ⇒ `t0 <= env.monotonicMs <= t1 <= t2`.
- First emit for a session: queue order is `[clock_anchor, event]`;
  `sourceSeq` 0 then 1; anchor event has `gameId: null`,
  `eventType: 'clock_anchor'`, payload deep-equals `sender.anchor`;
  subsequent emits continue 2, 3, …; new sessionId re-emits the anchor.
- FIFO + stop-and-wait: with a controllable transport, assert exactly
  one send per `flush()` until ack; acks dequeue in order.
- Ack handling: `ok:true`+matching id → dequeued; `ok:false` → kept,
  `lastError` set, pump stopped; `undefined` → kept (`'no-ack'`);
  rejection → kept (`'transport-error:…'`); wrong eventId → kept.
- No transport → `emit()` does not throw; `pendingCount()` grows;
  `getStatus().transportAvailable === false`.
- Envelopes frozen; `sourceContext === 'content_script'`; `appendSeq`
  null; message shape `{kind: 'event', event}` deep-equals expectation.
- Static: `sender.js` has no `chrome.` reference outside the lazy
  transport resolver; manifest js list exact; `sw.js`/`db.js` byte-identical
  to HEAD; `content.js` diff is only the instantiation line.

## 4. Acceptance criteria

- [ ] **AC1 (V1).** `sender.js` loads in Node with `chrome` undefined;
  exposes `createSender` and `SENDER_MESSAGE_KIND === 'event'`.
- [ ] **AC2 (V1).** Timestamp-at-observation: `monotonicMs` is captured
      synchronously in `emit()`, before queueing and before any send
      (test bounds it between pre/post `performance.now()` readings).
- [ ] **AC3 (V1).** Per-session `clock_anchor` first (`sourceSeq: 0`,
      `gameId: null`, payload = anchor), then observations (`sourceSeq`
      1, 2, …); a new `sessionId` re-emits the anchor; the counter is
      per sender instance (per segment).
- [ ] **AC4 (V1).** FIFO queue, stop-and-wait: one in-flight send at a
      time; acks dequeue in order; exactly one event is ever
      unacknowledged.
- [ ] **AC5 (V1).** Ack discipline: matching `ok:true` dequeues and
      continues; `ok:false`/`undefined`/rejection/eventId-mismatch keeps
      the event queued, records `lastError`, stops the pump; `flush()`
      reports `{delivered, pending}` honestly.
- [ ] **AC6 (V1).** No transport ⇒ `emit()` never throws; events queue;
      `getStatus()` reports `{pendingCount, lastError, transportAvailable:
      false}`.
- [ ] **AC7 (V1).** Diff discipline: manifest `js` list exactly
      `["event_envelope.js", "sender.js", "sounds.js", "chess.min.js",
      "chess_utils.js", "content.js"]`; `content.js` diff is only the
      instantiation line; `sw.js`, `db.js`, `manifest.json` otherwise
      byte-identical to HEAD (modulo the js list).
- [ ] **AC8 (V2).** Real extension SW context as proxy: evaluate
      `event_envelope.js` + `sender.js` in the live SW, install a test
      `onMessage` listener (standing in for §2.4), emit through a sender
      using the **real** `chrome.runtime.sendMessage`; assert the
      listener receives `{kind: 'event', event}` with the envelope
      structured-clone intact (all 11 keys, frozen-shape preserved as
      plain data), acks dequeue, order preserved across several events.
- [ ] **AC9 (V2).** Transport failure in the real context: with the test
      listener removed, sends get no ack → events stay queued,
      `lastError` set, no uncaught exceptions, SW stays healthy.
- [ ] **AC10 (V3, deferred).** Real content-script injection on
      `https://www.chess.com/play/computer`: sender constructs at page
      load, anchor captured, first session emit produces `clock_anchor`
      + event in the SW's DB. Requires the real site (match pattern);
      deferred to §7/owner-device acceptance.
- [ ] **AC11 (V1/V2 regression).** Full accumulated suite passes;

**Why the SW context is an honest V2 proxy for a content script here:**
the sender touches exactly two platform surfaces — `performance.now()`
and `chrome.runtime.sendMessage` — both present with identical semantics
in the SW. The content-script-only aspects (isolated world, DOM
observation) are not exercised by the sender itself. Labeled as proxy,
not as content-script verification.

## 6. Explicit non-goals (builder must NOT)

- SW intake: no `onMessage` listener, no validation, no dedup, no
  `appendSeq` assignment, no ack responses (2.4).
- Retry policy/timers/backoff (2.5) — only the `flush()` primitive.
- SW-restart restore (2.6); lifecycle event *types* and page start/end
  emission (2.7 — the `clock_anchor` here is 1.3's, not 2.7's);
  status-indicator UI (2.8 — only `getStatus()`); retention/export (2.9,
  §6).
- Queue persistence across page loads (context-scoped by design).
- `session_identity.js` / `session_conditions.js` / `game_records.js` in
  the manifest (that's §3's contract).
- Any gameplay change in content.js beyond the instantiation line; any
  change to chess_utils.js, sounds.js, sw.js, db.js.
- Manifest changes beyond the `js` list (no permissions/CSP/version).

## 7. Downstream needs this contract must serve

- **2.4:** consumes `{kind: 'event', event}` messages; implements the ack
  shapes in §2.6; commit-awaiting semantics before acking (DECISIONS.md
  #9a); wraps/documents the DataError surface (#9b).
- **2.5:** calls `sender.flush()` on its retry triggers; reads
  `pendingCount()`/`getStatus()`; owns timeouts and backoff (2.3 sets
  none).
- **2.7:** defines page/context start/end event *types*; may emit them
  through `BlindfoldSession.sender.emit()`.
- **2.8:** polls `getStatus()` for the session status indicator.
- **§3:** emitters call `BlindfoldSession.sender.emit({eventType,
  sessionId, gameId, payload, refs})` and use the returned envelope for
  linking (e.g. utterance→move refs).
- **§5:** creates sessions and passes `sessionId` per `emit()`; owns the
  Start-wiring that gives the sender its first session.

## 8. Reviewer notes

- If a reviewer argues the queue should be bounded: reject unless they
  show a PLAN requirement. Human-rate observations × page lifetime make
  unbounded safe; dropping would violate never-silently-drop, and §2.8
  surfaces persistent failure.
- If a reviewer argues for `runtime.connect` (Port): reject unless they
  show a throughput need. One-shot sendMessage matches the ack protocol
  and preserves MV3 idle semantics.
- If a reviewer argues the sender should validate payloads against
  Section-1 contracts: reject — validation is §2.4's (1.3 §2.8); the
  sender is a timestamping courier, and validating would couple it to
  every §3 payload shape.
- If a reviewer argues `clock_anchor` emission belongs to 2.7: reject —
  1.3 §7 explicitly assigns anchor capture + first-emission to the §2.3
  sender; 2.7 owns page/context start/end *types*, a different concern.
- Empirical risk to stress-test: real `sendMessage` from a content
  script to an SW with no listener resolves `undefined` (AC9 covers the
  no-listener path in the SW proxy); confirm the sender treats it as
  unacknowledged, not as success.
