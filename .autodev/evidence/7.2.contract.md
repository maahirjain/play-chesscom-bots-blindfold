# 7.2 contract — Verify promotions, castling, and en passant replay correctly from starting FEN and confirmed moves

**Planner:** section-7 planner subagent. **Date:** 2026-10-06.
**Scope:** PLAN.md §7.2. **Branch:** `autodev/logging-instrumentation`.
**Status:** CONTRACT ONLY. No implementation code written. PLAN.md unmodified.

## 1. What "verify" means

PLAN.md §7.2 requires demonstrating that a game containing special moves can be
**reconstructed** from the exported raw data: starting from the `gameStartingFen`
(in `metadata.json`, from the `game_started` event) and applying the confirmed
moves (in `events.jsonl`, `move_confirmed` events in `appendSeq` order), the
resulting position sequence must be correct — including:

- **Promotions:** `e7e8q` (or SAN `e8=Q`) must produce a queen on e8, not a pawn.
- **Castling:** `e1g1` (O-O) must move both king and rook; the intermediate
  squares' attack status must be respected (the replay uses chess.js, which
  enforces this).
- **En passant:** `e5d6` capturing a pawn that just double-moved must remove
  the captured pawn from the correct square.

"Replay correctly" means: the FEN after each special move, computed by applying
the confirmed move to the previous FEN with a standard chess library, matches
the known-correct FEN for that position. This is a **collection correctness
check** (the raw data is sufficient for reconstruction), not a shipped analysis
command.

## 2. What already exists

- `tests/game_records.test.js`: `move_confirmed` payload shape (AC5–AC10),
  including `from`/`to`/`promotion` fields.
- `tests/history_tracker.test.js` AC9: "unobservable promotion" — the tracker
  handles promotions the DOM doesn't disambiguate.
- `chess.min.js`: vendored chess.js, available for replay in tests.
- The `game_started` event carries the starting FEN (1.4.1).

**Gaps identified:**
1. No end-to-end replay test exists. The pieces (FEN + confirmed moves +
   chess.js) are all present, but no test chains them: FEN₀ → move₁ → FEN₁ →
   … → FENₙ with special moves, asserting each FEN.
2. The `promotion` field's vocabulary (e.g. `'q'` vs `'Q'` vs `'queen'`) needs
   pinning against what chess.js accepts.

## 3. Verification plan

### V1 — static/unit (Node)

- [ ] **AC1.** Promotion replay: starting FEN with a pawn on e7; confirmed
  move `e7e8` with `promotion: 'q'`; assert the resulting FEN has a white
  queen on e8 and correct side-to-move / castling / en-passant fields.
- [ ] **AC2.** Kingside castling replay: starting FEN with intact castling
  rights; confirmed move `e1g1`; assert king on g1, rook on f1, castling
  rights updated.
- [ ] **AC3.** Queenside castling replay: same for `e1c1` (king c1, rook d1).
- [ ] **AC4.** En passant replay: position after `e2e4 d7d5`; confirmed move
  `e4d5`... wait — en passant requires the specific sequence: e.g. white pawn
  e5, black plays `d7d5`, white captures `e5d6` en passant. Assert the black
  pawn is removed from d5 (not d6) and the white pawn lands on d6.
- [ ] **AC5.** Full-game replay: a short game (10–15 plies) containing one
  promotion, one castling, and one en passant, replayed from `gameStartingFen`
  through all `move_confirmed` events; assert the final FEN matches the
  known-correct value.
- [ ] **AC6.** Promotion vocabulary: assert the `promotion` field value in
  `move_confirmed` is accepted by chess.js (pin the exact mapping; document
  any normalization the collection pipeline applies).

### V2 — not required (pure data replay; V1 suffices)

### V3 — deferred to owner device (7.13 context)

- [ ] **AC7.** On the real device (7.13): export a real game containing a
  special move; replay from the ZIP's `metadata.json` + `events.jsonl`;

## 4. Non-goals

- Shipping a replay/analysis command in the extension (7.13 explicitly says
  the reconstruction is "a collection correctness check, not a shipped
  analysis command" — the test-only replay harness must not become product
  code).
- Validating chess.js itself (vendored library; trust its move application).
- Detecting illegal special moves (the bot game won't produce them; the
  collection records what happened).
