## 3. Contract behaviors — verified against the code

**(a) Marker emits with correct session/game IDs and trimmed note (or null).** `onMarkerClick` (session_controls.js) reads `activeSessionId`/`activeGameId` (the live slots), trims the input, emits `{note: trimmed === '' ? null : trimmed}` via `opts.sender.emit` — the same pattern as `emitPageStart`. Timestamping is the sender pipeline's job (no 5.8 timing code). V1 AC2 tests pin the trimmed note and null cases; V2 AC7 confirms end-to-end through the real SW writer.

**(b) Idle → disabled, nothing emitted.** `setMarkerEnabled(false)` is called on all abort paths, all four inline Start-chain aborts, Stop completion, and boot-idle. `onMarkerClick` defensively re-checks `phase !== CONTROL_PHASE_ACTIVE` before doing anything. V1 AC3 pins disabled-while-idle and no-emission; V2 AC8 confirms in real Chrome.

**(c) Emit failure preserves text and surfaces honestly.** Both the validation-failure and emit-failure catch blocks set `marker-failed:<ErrorName>` on the button title and return *without* clearing the input. Nothing throws out of the handler (3.2 SF-1). V1 AC4 pins this with a throwing sender: text preserved, title surfaced, control still functional.

**(d) Marker doesn't disturb session state.** `onMarkerClick` touches no phase, no slots, sends no stop-channel message, and doesn't touch the 5.6 badge. V1 AC5 pins phase-stays-active, slots-unchanged, zero `recorder-stop-streams` messages.
