## What was implemented (per contract, no deviation in product code)

**New module `track_monitor.js`** (DOM-free, repo module pattern):
`createTrackMonitor({emitEvent, getChunkState})` → `{attachStream,
detachStream, onChunkTerminalState, emitRestartDiscontinuity,
getMonitoredKinds, getMonitoredTracks}`. Owns the three `*_EVENT_TYPE`
constants (`recorder_track_state_changed`, `recorder_error`,
`stream_discontinuity`) and the exact-keys payload constructors
(`createTrackStatePayload`, `createRecorderErrorPayload`,
`createDiscontinuityPayload`), all passing `EVENT_TYPE_RE`.

- `attachStream({streamKind, stream, recorder, segmentId})` reads each
  track's initial `{muted, ended}`, emits one baseline event per track,
  and installs `onmute`/`onunmute`/`onended` (+ `recorder.onerror`).
  Every handler body is try/catch-guarded; a throwing `emitEvent` is
  tolerated; malformed tracks (non-object, missing/non-audio/video
  kind) are skipped. Every transition emits (no debounce); after
  `onended` the track's listeners are detached and the chained
  `stream_discontinuity{reason:'track-ended'}` follows the observation
  event, same tick. `recorder_error` carries the verbatim
  name/message/state, then `stream_discontinuity{reason:'recorder-error'}`.
- `onChunkTerminalState({streamKind, terminalState})` — the
  chunk_writer seam target: maps the three terminal states to the
  identical reason codes (identity mapping), `lastChunkIndex`/`detail`
  from `getChunkState()` (detail only for `chunk-write-error`).
  Unknown states/kinds ignored, never thrown.
- `emitRestartDiscontinuity({streamKind, newSegmentId,
  supersededSegmentIds})` — `reason:'restart'`, `lastChunkIndex: null`
  (the superseded generation's last index is not observable from the
  new document — unknown is null), `refs` = `{segmentId: newSegmentId}`
  or null when that kind failed.
- `getMonitoredTracks(streamKind)` — 4.9/§7 introspection seam (the
  V2 harness forces `track.stop()` on a real track); test-only.

**`chunk_writer.js`**: optional `onTerminalState({streamKind,
terminalState})` factory option (TypeError when non-function;
absent → 4.8 behavior unchanged). `notifyTerminalState()` fires
exactly once per poll generation at the two terminal-transition
points (`noteMiss` → `chunk-stalled`, `failWrite` →
`chunk-quota-exceeded`/`chunk-write-error`), wrapped so a throwing
callback cannot break the chunker. `STATUS_STOPPED` is not a 4.9
terminal state (Stop is 4.13's territory).

**`format_support.js`**: additive `getManifestRecordsBySession(sessionId)`
→ `DB.getAll('recording_manifest', {index:'bySessionId', lower, upper})`
(the 4.5-created index); `[]` when none. No schema change, no
`DB_VERSION` bump.

**`recorder.js`**:
- `getTrackMonitor()` — lazy, shared-namespace-resolved,
  test-injectable via `o.trackMonitor`; constructed with
  `emitEvent: emitRecorderEvent` (session-gated, clock-stamped) and a
  lazy `getChunkState` thunk over the chunk writer. Absence is a wiring
  defect → plain Error.
- `handleStartStreams` wiring order: (1) `checkRestartSuperseded()`
  reads the manifest *before* starting (pre-existing unfinalized
  records → `{streamKind:[segmentIds]}`; best-effort — a failed read
  degrades to "no restart"); (2) `starter.startStreams()` unchanged;
  (3) 4.8 chunking kickoff unchanged (the writer now carries the
  monitor's `onTerminalState` via a defensive thunk); (4)
  `monitor.attachStream` per successfully started kind;
  (5) `emitRestartDiscontinuity` per affected kind. Steps 3–5 are
  independently best-effort: monitoring can never fail the streams,
  the chunking, or the channel response.
- `MANIFEST_FINALIZED_FIELD = null` — 4.13's marker name is 4.13's to
  define; until defined the exclusion matches nothing.
- The auto-boot stashes `globalThis.__blindfoldRecorderForTests`
  (documented V2 introspection seam for the sw-track-monitor harness;
  test-only, never read by product code).
- `recorder.js` still references zero media-capture APIs (the 4.1
  boundary holds — V1-pinned).

**`recorder.html`**: loads `track_monitor.js` after `chunk_writer.js`.

## Honest limitations

- `sendEventMessage` is best-effort (documented in the contract §1):
  a failed send warns and drops the event; chunk/manifest records are
  the backstop for gap detection. No retry queue in 4.9.
- Mute flaps are logged per transition (no debounce) — a flapping
  device produces one event per transition, by raw-collection design.
- The restart pre-check runs on every `recorder-start-streams`; with
  §5 minting fresh sessionIds per session, false positives require
  out-of-contract sessionId reuse (documented in the contract).
- The contract file itself ends mid-sentence in AC9 (line 330 carries a
  literal `...[truncated 2287 chars]` marker — the planner's write was
  cut off; AC9's remainder, AC10, AC11, §7–§8 are missing from the
  file). AC1–AC8 are complete and fully implemented; AC9 was
  implemented from its visible text (force `track.stop()` → both
  events in the events store; kill/recreate → restart discontinuity)
  plus the AC4 V1 behavior; AC10 is the standard regression set; AC11
