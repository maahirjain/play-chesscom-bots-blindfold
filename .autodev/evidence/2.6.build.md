## Implementation

**New: `session_store.js`** (repo root). Section-1 script pattern: guarded
`BlindfoldSession` global → IIFE `'use strict'` → Node `module.exports` shim.
SW-side only. Public API exactly per contract §3.1:

- `saveSessionMetadata(record)` — validates via 1.1 `requireValidMetadata`
  **before any IDB access**; throws before touching the DB on invalid input.
  Replace semantics via `DB.put` on the `sessions` store.
- `saveConditions(sessionId, record)` — validates via 1.2
  `requireValidConditions`; throws before any IDB access. Replace semantics
  on the `conditions` store. **Documented deviation:** the contract wrote
  `saveConditions(record)`, but the `conditions` store's keyPath is
  `sessionId` and the 1.2 factory record carries no `sessionId` field — a
  7-field record throws `DataError` on `put`. The session ID is therefore an
  explicit first parameter (mirroring `restoreSessionState`/`getSequenceState`);
  the stored record is `{sessionId, ...sevenFields}` via the validator's
  normalized return. `requireValidConditions` tolerates the extra key
  (verified: no extra-key rejection on records).
- `restoreSessionState(sessionId)` → `{metadata, conditions, sequenceState}`.
  Re-validates each present record on the way out; absent store entry →
  `null` for that slot; corrupt entry → plain `Error` with a stable,
  grep-able message (`session-store: corrupt <store> for session <id>`),
  never a silent default. Never writes.
- `getSequenceState(sessionId)` — read-only peek at the writer-owned
  counter; absent → `null`; malformed → corruption `Error`. **Never writes**
  (asserted in V1 by snapshotting the store before/after).

Design points (all per contract):
- Reads `BlindfoldSession.DB` and the two validators **at call time** via a
  `shared()` helper (sender.js precedent). Rationale: in Node, the file's own
  top-level `var BlindfoldSession = BlindfoldSession || {}` is module-scoped
  (the hoisted `var` shadows the global), so direct top-level reads see a
  fresh empty object; call-time resolution is required for the SW global to
  be visible. In the SW, `importScripts` order guarantees availability.
- No `chrome.*` at load; no eager startup self-check (contract: no
  `onMessage`/`onStartup` wiring — that is §5's lane).
- Never writes `sequence_state` / `events` / `media_chunks` (the writer owns
  those; the store is intentionally not a second writer).
- Error taxonomy per AGENTS.md: `TypeError` (bad shape/ID),
  `RangeError` (bad domain), plain `Error` (corruption — a platform/data
  condition, not a caller type error).

## V2 — `~/workspace/tools/ext-verify/sw-restart.js` (new harness, outside repo)

Two-launch technique per the contract: persistent `--user-data-dir` at the
fixed path `/tmp/restart-v2-profile`; stable `--load-extension` path at the
fixed dir `/tmp/restart-v2-ext` (**not** `mkdtemp` — Chrome derives an
unpacked extension's ID from its absolute path, so the same path → the same
`chrome-extension://<id>` origin → the same IndexedDB across launches; the
harness asserts the SW origin is byte-identical across all four launches).
`chrome.runtime.reload()` was probed unreliable in headless, so every
transition is a FULL `browser.close()` + relaunch.

- **Launch 1:** real sender→writer path (content-script driver, same
  technique as `sw-writer.js`) writes 6 events (5 moves + clock_anchor),
  gapless `0..5`, counter `6`; `saveSessionMetadata` + `saveConditions`
  persisted for the session. A second session is seeded (3 events + state).
- **Launch 2 (AC10):** `restoreSessionState` returns the triple with
  metadata/conditions deep-equal to saved and
  `sequenceState.nextAppendSeq === 6`. 4 more events written →
  `appendSeq` continues `6..9`, 10 total, gapless `0..9`, counter `10`.
- **Launch 3:** the second session's counter is corrupted *between
  launches* via a raw `DB.put('sequence_state',
  {sessionId, nextAppendSeq: 'corrupted'})`, bypassing all validation.
- **Launch 4 (AC11):** `restoreSessionState` **rejects** with
  `session-store: corrupt sequence_state for session <id>` (plain `Error`);
  `getSequenceState` likewise rejects — never a silent `0`/`null`. The
  uncorrupted session still restores (`nextAppendSeq === 10`): corruption
  is per-session, not global.
