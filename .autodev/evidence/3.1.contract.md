# Task 3.1 contract — Make confirmed history tracking reliable in chess_utils.js

PLAN.md §3.1 (human-owned; quoted verbatim, never modified):

> 3.1. Make confirmed history tracking reliable in chess_utils.js.
> 3.1.1. Compare move-list contents rather than only list length.
> 3.1.2. Validate each move before advancing the internal game state.
> 3.1.3. Emit one confirmed-move event per successfully observed history addition, including moves made by mouse.
> 3.1.4. Detect a revised history and record a revision rather than treating it as ordinary new play.
> 3.1.5. Distinguish a temporarily missing move-list element from a genuine reset or new game.
> 3.1.6. Mark moves discovered in a batch or recovered after reload as such; do not invent their original occurrence times.
> 3.1.7. Emit synchronization failures when the observed history cannot be reconciled with the internal board.

## 1. Current-state analysis

`chess_utils.js` (pre-existing gameplay code, 256 lines) currently:

- `observeMoves(onMoveListChange)` fires only when `half_moves.length`
  changes — **length-only comparison** (3.1.1). A same-length revision
  (takeback + different move) never fires the observer at all.
- `updateGame(game, count, half_moves)`: if the observed list is shorter
  than the internal count it calls `game.reset()` and zeroes the count —
  **any** shorter list (transient DOM glitch included) nukes internal
  state (3.1.5). New moves are applied via `game.move(san)` whose return
  value is **ignored** — an illegal/unparseable observed move silently
  increments the counter, desyncing the internal board with no record
  (3.1.2, 3.1.7). No events are emitted for anything (3.1.3/3.1.4/3.1.6).
- `content.js` drives it with a module-level `game`/`game_half_move_count`
  pair and speaks `half_moves[game_half_move_count]` before advancing.

What is *reliable* today: `getMoveList()` DOM scraping, `normalizeMove`,
`isMoveLegal`, board-click helpers, piece-set code — all untouched by
this task.

## 2. Design

### 2.1 `observeMoves` — content comparison (3.1.1)

Keep the signature `observeMoves(onMoveListChange)`. Replace the
length-only guard with an element-wise comparison against the last
observed array; fire only when contents differ. This catches same-length
revisions the current code misses entirely. The tracker (below) still
receives every *distinct* observed state, which is what its
suspect-window counting needs.

### 2.2 `createHistoryTracker(options)` — the reconciliation core

New factory in `chess_utils.js` (same module pattern as the rest of the
file: plain functions; the file predates the BlindfoldSession-namespace
convention — the tracker is exported on `BlindfoldSession` for
namespaced access and testability, following the 2.x precedent for new
APIs).

```js
BlindfoldSession.createHistoryTracker({
  gameId,            // uuid-v4 string or null (§2.8)
  emitEvent,         // (eventType, payload, refs) => envelope|{eventId} — MUST be synchronous
  onGameReset,       // () => void — genuine reset/new-game signal (§2.9)
  suspectThreshold,  // default 3 — consecutive non-reconciling observations before genuine reset
  desyncThreshold    // default 5 — consecutive unreconciled observations before position_checkpoint
});
```

- `gameId` binds the tracker to **one game**. The tracker owns a single
  internal `Chess` instance (created once; rewound via `reset()` +
  replay, never replaced — so `content.js` can hold one stable `game`
  binding for `sounds.js`'s bare-`game` references).
- `emitEvent` is caller-supplied (content.js wraps `sender.emit`,
  adding sessionId/gameId/sourceContext). The tracker calls it only for
  game-scoped events and only when `gameId` is non-null (§2.8). It must
  return the emitted envelope (or an `{eventId}`) — the tracker records
  confirmed-move eventIds for `history_revised.retractedMoveEventIds`.
  Synchronous by contract: marker-first sourceSeq ordering (1.4)
  depends on call order.
- Validation errors (bad options shape): `TypeError` per convention.

Methods:

- `observe(halfMoves)` → result object (all synchronous):
  ```js
  {
    confirmed: [{ san, from, to, promotion, eventId, preFen }],
      // newly confirmed moves, in order; preFen is the in-memory
      // pre-move FEN for sayMove (never persisted — not a stored
      // derivable value, just the speech path's existing input shape)
    revised: bool, recovered: bool, syncFailed: bool, reset: bool
  }
  ```
  `halfMoves` must be an array; non-string elements are a caller
  `TypeError`. Empty/whitespace-only string elements are *observation
  anomalies* → `history_sync_failed` (`malformed_observation`), not a
  caller error.
- `getGame()` → the internal `Chess` instance (stable across resets).
- `getConfirmedCount()`, `getState()` → `'tracking' | 'suspect' |
  'desynced' | `'ended'` (for tests and §5).

### 2.3 Validation before advancing (3.1.2)

For each observed SAN beyond the confirmed count, in order:

1. Try `internalGame.move(rawSan)`. The raw observed string is tried
   first (preserve original observations; the persisted
   `move_confirmed` payload uses the canonical `{from, to, promotion}`
   from the move object, never the raw string).
2. If raw fails, try the existing `normalizeMove(internalGame, rawSan)`
   as a Chess.com display-quirk fallback (handles `oo`/`b5`-ambiguity
   renderings). The fallback can only *reduce* false sync failures; it
   never changes a successfully parsed move.
3. If both fail → do NOT advance the counter; go to the bridge test
   (§2.7).

A promotion-shaped SAN without a determinable piece (stripped of `+`/`#`,
matches `/[a-h][18]=?$/`, validation failed) → `unobservable_promotion`
sync failure — never a `move_confirmed` with a guessed or null
promotion (1.4 design decision).

### 2.4 Reconciliation algorithm

State: confirmed list `C` (each `{san, from, to, promotion, eventId}`),
internal board `B`, `suspectCount`, `desyncCount`, `lastCheckpointFen`,
`ended` flag. On `observe(O)`:

1. If `ended`, return `{reset: true}` and ignore (the host must install
   a new tracker for the new game).
2. Compute the longest common prefix `P` of `O` and `C` by SAN string
   equality.
3. **Clean append** (`|P| == |C|`, `|O| > |C|`): validate §2.3 each new
   SAN. All succeed → confirm. Batch marking (§2.5) applies when
   `|O|-|C| > 1`, **or** when this is the first-ever observation and
   `|O| > 0` (even a single pre-existing move was not observed
   occurring): emit `history_recovered` marker FIRST (§2.6), then the
   moves with `refs: {recoveryEventId}`.
4. **Takeback** (`|P| < |C|`, `O` is a strict non-empty prefix of `C`):
   emit `history_revised` (`revisionKind: 'takeback'`,
   `retractedMoveEventIds: C[|O|..].eventIds` — a suffix by
   construction, satisfying 1.4's suffix rule; `observedHistoryLength:
   |O|`; `expectedMoveCount: 0`) marker-first, then rewind `B`
   (`reset()` + replay of `O`, which was previously validated) and
   truncate `C` to `O`.
5. **Correction** (`|P| < |C|`, `O` diverges at `|P|`): reset `B` to
   replay of `P`, validate `O[|P|..]` per §2.3. All succeed → emit
   `history_revised` (`'correction'`, retracted `C[|P|..]`,
   `observedHistoryLength: |O|`, `expectedMoveCount: |O|-|P|`)
   marker-first, then replacement `move_confirmed`s with
   `refs: {revisionEventId}`. Any failure → `history_sync_failed`
   (`unreconciled_revision`) and §2.7.
6. **Suspect** (`O` empty, or shorter-divergent — not a strict prefix):
   `suspectCount++`; no event yet. If a later observation reconciles
   (steps 3–5 apply cleanly) → `suspectCount = 0`, resume silently (the
   transient left no gap in the confirmed stream). If `suspectCount >=
   suspectThreshold` consecutive non-reconciling observations →
   genuine reset/new game: reset `B` and `C`, set `ended`, call
   `onGameReset()`. **No 3.1 event is emitted for the reset itself** —
   3.5.2 owns recording detected resets; 3.1's job (3.1.5) is the
   *distinction*, delivered via the callback.
7. Empty `O` with empty `C` (page load, list not rendered): no-op.

Rationale for immediate takeback (step 4) vs suspect-waiting: a clean
strict prefix is semantically a takeback; a transient shorter-prefix
glitch that self-corrects is repaired by the follow-up correction
revision, and the stream stays honest about what the DOM showed. The
suspect window is reserved for the genuinely ambiguous
divergent/empty cases 3.1.5 names.

### 2.5 Batch and recovery marking (3.1.6)

- First-ever observation with `|O| > 0` and `|C| == 0` →
  `recoveryReason: 'page_reload'` (reload and fresh-navigation-to-mid-game
  are indistinguishable and semantically identical: pre-existing history
  recovered on attachment).
- Any other multi-move gap with a clean prefix → `'late_attachment'`
  (observer attached late or Chess.com batched a DOM update).
- Marker-first: `history_recovered` at sourceSeq k, the N moves at
  k+1…k+N with `refs: {recoveryEventId}`; `expectedMoveCount: N` lets
  consumers detect a truncated batch.
- **No invented times, ever.** Batch-move envelopes carry the sender's
  observation-time stamp (`monotonicMs` at `emit()`); the marker
  explains the batch. Consumers must never interpret envelope times as
  occurrence times. The contract forbids backdating.

### 2.6 Confirmed-move emission (3.1.3)

One `move_confirmed` per validated addition, payload built by 1.4's
`createMovePayload({from, to, promotion})` from the chess.js move
object. **Mouse moves are included by construction**: the DOM observer
cannot distinguish input modality, and no modality filter is applied
(3.2.7's rejected-mouse-attempts limitation concerns *unconfirmed*
attempts, which never reach the move list).

### 2.7 Synchronization failures and the checkpoint gate (3.1.7)

New 3.1-owned event type (1.3 §2.2: each task owns its vocabulary):

```js
BlindfoldSession.HISTORY_SYNC_FAILED_EVENT_TYPE = 'history_sync_failed';
BlindfoldSession.SYNC_FAILURE_REASONS = Object.freeze([
  'illegal_observed_move',   // SAN failed validation and the bridge test failed
  'unobservable_promotion',  // promotion-shaped SAN, piece indeterminable (1.4 rule)
  'unreconciled_revision',   // correction replacements failed validation
  'malformed_observation',   // empty/whitespace move-list element
  'internal_desync'          // observed history replays clean but internal board diverged
]);
```

Payload (exact keys): `{reason, plyIndex, observedSan, internalFen}` —
the offending observed SAN (raw, preserved), the ply index in the
observed list, and the last-known-good internal FEN. `refs: null`.
Game-scoped (non-null `gameId` required, like all 1.4 types).

Bridge test (on any validation failure): replay the *entire* observed
list from the initial position on a scratch `Chess`. If it replays
clean → the observation is self-consistent and the internal board is
stale → adopt the replayed state (`internal_desync` recorded; the
observation wins — "preserve original observations") and confirm the
new moves. If the replay fails at the same ply → the observation is
genuinely inconsistent → `history_sync_failed`, freeze `B` (never
advance on unvalidated data), enter `desynced` state.

Desync watch: each subsequent observation retries full reconciliation.
`desyncCount` consecutive failures `>= desyncThreshold` → emit
**one** `position_checkpoint` (1.4's `createPositionCheckpointPayload`:
`{fen, reason: 'unreconciled_history', fenSource: 'observed'}`) where
`fen` is the **last-known-good** internal FEN — the best-effort
observed position, honestly labeled by the preceding `history_sync_failed`
(which carries the divergent evidence). This satisfies 1.4's strict
gate: (1) a sync failure was observed *and recorded*; (2) the gap is
unbridgeable (replay from initial — the tracker's game_started
equivalent — failed on `desyncThreshold` consecutive observations; the
"from the last checkpoint" leg is checked against `lastCheckpointFen`
when one exists); (3) the FEN is best-effort observed, never invented.
No repeat checkpoints; the tracker keeps trying to reconcile.

### 2.8 The gameId seam (§5 dependency)

- `BlindfoldSession.activeGameId = null;` — runtime slot, **§5-owned**
  (mirrors 2.7's `activeSessionId` precedent). Declared in
  `chess_utils.js` next to the tracker with a §5-ownership comment.
- `gameId: null` → the tracker advances the internal board (gameplay
  must work — the blindfold player needs the position) but emits **no**
  game-scoped events (1.4 forbids null-gameId for these types).
- §5 creates one tracker per game (constructor-bound `gameId`); on
  `onGameReset`, §5 mints the new game identity and installs a new
  tracker. There is deliberately **no** `setGameId` — rebinding is a
  new-tracker operation, which keeps the confirmed sequence and the
  game identity trivially consistent. A fresh tracker observing
  pre-existing history emits it as a `page_reload` batch — the stream
  stays complete.
- Until §5 exists, `content.js` passes
  `BlindfoldSession.activeGameId || null` → track-but-don't-emit.
  Gameplay (board, speech) works; recording waits for §5. This is the
  honest phased-mission seam, not a defect.

### 2.9 content.js wiring (minimal)

```js
const historyTracker = BlindfoldSession.createHistoryTracker({
  gameId: BlindfoldSession.activeGameId || null,
  emitEvent: (eventType, payload, refs) =>
    BlindfoldSession.sender.emit({
      eventType,
      sessionId: BlindfoldSession.activeSessionId,
      gameId: BlindfoldSession.activeGameId,
      payload,
      refs: refs || null,
    }),
  onGameReset: () => { /* §5: mint new game + new tracker */ },
});
let game = historyTracker.getGame(); // stable instance; sounds.js's bare `game` keeps working

observeMoves((half_moves) => {
  latest_half_moves = half_moves;
  const result = historyTracker.observe(half_moves);
  for (const m of result.confirmed) {
    sayMove(new Chess(m.preFen), m.san);
  }
  applyCurrentPieceSet();
  announceResultIfOver();
});
```

Behavior deltas (documented, defensible): previously only the first
new move was spoken (`half_moves[game_half_move_count]`); now each
newly confirmed move is spoken in order (`interrupt: true` keeps the
latest audible). `game_half_move_count` is removed (the tracker owns
the count).

### 2.10 `updateGame` removal (flagged for reviewer)

`updateGame(game, game_half_move_count, half_moves)` is superseded by
the tracker and **removed**. This is a deletion from a main-origin
file, flagged explicitly: the function's contract (silent
reset-on-shorter, unvalidated advance) is exactly what 3.1.1/3.1.2/3.1.5
replace; keeping it as a wrapper is impossible (the tracker owns its
game instance) and keeping it as dead code is worse. `observeMoves`,
`getMoveList`, `normalizeMove`, `isMoveLegal`, and all board-click /
piece-set helpers are untouched.

### 2.11 Constants

`suspectThreshold` / `desyncThreshold` are constructor options
(defaults 3 / 5) — injectable for tests, no namespace constants needed.

## 3. Acceptance criteria

V1 — static/unit (`tests/history_tracker.test.js`; DOM-free: the
tracker takes SAN arrays; `Chess` from the vendored `chess.min.js` via
`globalThis`):

- [ ] **AC1.** `observeMoves` fires on content change, not length-only:
  same-length substitution (e.g. `['e4','e5']` → `['e4','c5']`) fires;
  identical re-render does not. (Requires a minimal DOM/MutationObserver
  stub — the only DOM-coupled test; everything else is DOM-free.)
- [ ] **AC2.** Each observed move validated before the internal board
  advances: feed `['e4', 'THIS_IS_NOT_A_MOVE']` — the invalid move is
  not applied (`getGame().fen()` unchanged past e4), the confirmed
  count does not advance, and a `history_sync_failed`
  (`illegal_observed_move`) is emitted.
- [ ] **AC3.** One `move_confirmed` per validated addition with
  canonical `{from, to, promotion}` (e.g. e2→e4 yields
  `{from:'e2', to:'e4', promotion:null}`); castling yields king from/to;
  promotion yields lowercase piece. Mouse moves need no special-casing
  (modality-indistinguishable by construction — assert via code path,
  not a separate test).
- [ ] **AC4.** Same-length revision `['e4','e5','Nf3']` →
  `['e4','e5','Bc4']`: exactly one `history_revised` (`correction`)
  emitted BEFORE the replacement `move_confirmed`; `retractedMoveEventIds`
  is the single retracted Nf3 eventId (suffix rule); the replacement
  carries `refs: {revisionEventId}`; internal board matches the revised
  line.
- [ ] **AC5.** Takeback `['e4','e5','Nf3']` → `['e4','e5']`: one
  `history_revised` (`takeback`, `expectedMoveCount: 0`), internal
  board rewound to post-e5, no `move_confirmed` emitted.
- [ ] **AC6.** Transient vs genuine (3.1.5): confirmed 4, observe
  divergent-short twice → no event, state `'suspect'`; third
  consecutive divergent → `onGameReset` called, state `'ended'`,
  further `observe()` calls ignored. And: divergent-short once then a
  reconciling observation → suspect cleared, no event, stream
  continuous.
- [ ] **AC7.** Batch: first observation `['e4','e5','Nf3']` →
  `history_recovered` (`page_reload`, `expectedMoveCount: 3`) at
  sourceSeq k, three `move_confirmed`s at k+1…k+3 with
  `refs: {recoveryEventId}`. Late batch (empty first, then 3) →
  `'late_attachment'`. Emission order asserted via the stub's call log.
- [ ] **AC8.** No invented times: no 3.1 payload carries a time field
  (1.4 forbids them — assert via the factories); batch moves are
  emitted synchronously inside a single `observe()` call (one
  observation tick — assert via the stub's call log showing the marker
  and all batch moves in one synchronous burst); the contract forbids
  backdating, and the envelope's `monotonicMs` is the sender's
  observation stamp, never rewritten by the tracker.
- [ ] **AC9.** Unobservable promotion: observed SAN `'e8'` (or `'e8='`)
  in a promotion position → `history_sync_failed`
  (`unobservable_promotion`); never a `move_confirmed` with
  `promotion: null` for that ply.
- [ ] **AC10.** Checkpoint gate: force persistent desync (e.g. repeat
  the illegal SAN for `desyncThreshold` observations) → exactly one
  `position_checkpoint` (`unreconciled_history`, last-known-good FEN,
  `fenSource: 'observed'`); further observations add no second
  checkpoint; a reconciling observation resumes tracking.
- [ ] **AC11.** `gameId: null` → board advances, `getConfirmedCount()`
  advances, but `emitEvent` is never called.
- [ ] **AC12.** Malformed element (`''` / `'   '`) → `history_sync_failed`
  (`malformed_observation`); non-string element → `TypeError`.
- [ ] **AC13.** Diff discipline: `chess_utils.js` gains the tracker +
  content-compare + `activeGameId` slot and loses `updateGame` (only
  planned deletion); `content.js` wiring is the §2.9 block only;
  `normalizeMove`/`isMoveLegal`/board-click/piece-set helpers
  byte-identical; no other product files change.
- [ ] **AC14.** Payload factories reused: `move_confirmed`,
  `history_recovered`, `history_revised`, `position_checkpoint`
  payloads built via 1.4's `create*Payload` (assert exact keys through
  the factories in tests).

## 4. Non-goals

- 3.2 (move-input instrumentation: keystrokes, submitted text,
  validation outcome, dispatch) — untouched.
- 3.3 (visibility/assistance), 3.4 (speech), 3.5 (lifecycle events:
  game resets *recording* is 3.5.2's; 3.1 only *detects* via
  `onGameReset`).
- §5 session/game lifecycle wiring (game_started emission, activeGameId
  management, tracker-per-game installation).
- §6 export; §7 acceptance.
- No analysis, metrics, or reconstructed-position persistence beyond
  the in-memory board the gameplay already requires.
