## Ack discipline: verified on every path

## Findings

### NOTEs (no code impact)

- **NOTE-1 — Reentrant transport can double-send the head (not event loss).**
  If a transport synchronously calls `sender.emit()` inside the send, the
  inner `runPump` re-sends the in-flight head (verified: same `eventId`
  sent twice) and the outer `pumpPromise = myPromise` assignment clobbers
  the inner run's slot. End state still drains consistently, and the
  duplicate is absorbed by §2.4's dedup-by-`eventId` (PLAN §2.4), so there
  is no data corruption. No realistic transport re-enters:
  `chrome.runtime.sendMessage` never invokes sender code synchronously,
  and no repo test mock does. A fully reentrancy-proof pump would need a
  different architecture (naive `inFlight` flag makes it worse — the inner
  run's promise would hang forever); not worth the complexity for a
  non-threat. Documented here so §2.4/§2.5 authors know the invariant's
  boundary: **transports must not call `emit()` synchronously.**
- **NOTE-2 — Hung transport stalls the pump; `flush()` joins the stall.**
  If a transport promise never settles, the head stays unacknowledged and
  every future `flush()` returns the same in-flight promise. The contract
  assigns timeouts/backoff to §2.5 — carrying forward explicitly: **the
  2.5 contract should add a send timeout** so a hung SW cannot wedge the
  sender for the page lifetime.
- **NOTE-3 — `anchoredSessions` grows per distinct sessionId.** Bounded by
  page lifetime and realistic session counts (one per Start click); each
  entry is one boolean. Acceptable; no action.
- **NOTE-4 — No idempotency guard on `BlindfoldSession.sender` assignment.**
  If `content.js` ever re-executed in the same world, a second sender
  would orphan the first's queue/anchor (two `sourceSeq` streams). Worlds
  are per-document-load in practice. Suggest §5 consider
  `BlindfoldSession.sender = BlindfoldSession.sender || ...createSender()`
  when it owns session wiring — not a 2.3 defect.
- **NOTE-5 — V2 adaptation (SW-context → real content-script world) is
  honest and stronger.** The contract's AC8 was empirically unimplementable
  (Chrome rejects SW→SW `sendMessage`); the harness runs the sender in a
  real isolated world against the real `sendMessage`, asserting
  byte-identical product files in-harness (`test-ext ${f} byte-identical`
  checks for all four). The /tmp manifest copy gains only a test entry;
  nothing test-only ships in the repo. AC8/AC9 intent fully preserved.
- **NOTE-6 — Test evolution in `tests/db.test.js` / `tests/manifest_sw.test.js`
  is honest.** Both diffs replace inherently transient git-relative
  assertions with cumulative invariants, each with an explanatory comment;
  the exact js list is pinned in `tests/sender.test.js`, and the
  `web_accessible_resources` byte-identity is preserved. No weakening.
- **NOTE-7 — Unbounded queue is contract-justified; 2.8 must surface
  persistent failure.** `getStatus()` returns exactly
  `{pendingCount, lastError, transportAvailable}` — sufficient for the
  §2.8 indicator. The never-silently-drop invariant holds: page-unload
  loss is detectable via `sourceSeq` gaps, not hidden.
