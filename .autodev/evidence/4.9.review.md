## NOTEs (informational; none fails an AC)

1. **Eager payload construction.** `emitState`, `emitDiscontinuity`,
   `onChunkTerminalState`, and `emitRestartDiscontinuity` construct
   their payloads as arguments to `safeEmit`, i.e. *outside* the
   guarded wrapper — a payload-constructor throw would bypass the
   try/catch. The throw surface is unreachable with internal inputs
   (all values validated or guarded: `requireStreamKind` at attach,
   `readMuted`/`readEnded` guarded to booleans, `chunkSnapshot`
   guarded), and the outer handlers are guarded anyway. Stylistic
   fragility only.
2. **Coarse best-effort wrap in `recorder.js`.** The monitor-attach
   loop and `emitRestartDiscontinuities` share one try/catch
   (`recorder.js:1009-1029`): a single kind's `attachStream`
   validation throw (unreachable with 4.6-minted uuid-v4 segmentIds,
   but the contract calls these "caller bugs") would skip the
   remaining kinds *and* the restart events. Contracted best-effort
   behavior holds; per-kind granularity would be more robust if
   4.13's contract touches this area.
3. **Co-occurring discontinuities.** A track that ends *and* whose
   recorder errors yields two discontinuity events (`track-ended` +
   `recorder-error`) — the taxonomy permits this (different sources,
   different consumers); 4.13's re-segmentation must tolerate
   co-occurring flags for one stream.
4. **Silent ignore of unknown terminal states.** `onChunkTerminalState`
   ignores unknown states/kinds without throwing (contracted). A
   future chunker terminal state added without updating
   `CHUNK_TERMINAL_STATES` would be silently dropped — the widening
   must be deliberate, per the exact-keys convention's spirit.
5. **`getMonitoredTracks` exposes live track references.** Documented
   test-only (the V2 harness's `track.stop()` seam); product code
   never calls it (grep-verified). The `__blindfoldRecorderForTests`
   seam is likewise write-only in product code
   (`recorder.js:1366`), read only by tests.
6. **Restart pre-check runs on every `recorder-start-streams`.**
   With §5 minting fresh sessionIds per session this is cheap and
   correct; a false positive requires out-of-contract sessionId
   reuse (contract §8 documents this).
7. **`sendEventMessage` stays best-effort.** A dropped
   discontinuity event leaves the chunk/manifest records as the
   backstop (contract §1 known limitation); §7/4.14's gap-detection
   comparison is the recovery, not 4.9's.
