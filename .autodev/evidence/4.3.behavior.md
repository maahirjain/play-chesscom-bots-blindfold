## Review SF-1 repair — verified

`grep -c tabPermissionState capture_selection.js` → **0**: the dead
write-only state is fully removed. The replacement comment documents the
deliberate design: permission state is never cached in the selector;
every consumer re-derives it via the SW broker (query/probe outcomes),
because the browser-side grant is revocable at any time. Probed: a
throwing storage makes `select('tab')` reject with the in-memory
selection still `null` and zero emissions (no phantom selection).
