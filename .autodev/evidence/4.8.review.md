## Adversarial focus-area findings

1. **chunkIndex race fix — sound.** The reservation is truly
   synchronous-before-acceptance (index incremented before `readDb()`
   / `db.put()` are even attempted). The three post-reservation
   failure exits (`readDb()` throw, sync `db.put` throw, async
   rejection) all route to `failWrite` **after** the reservation, so a
   failed write leaves a gap, never a duplicate. 4.13's "reads in key
   order" holds with gaps — IDB compound-key ordering is by
   `[segmentId, chunkIndex]` regardless of contiguity (see NOTE 6 for
   the 4.13-side implication).
2. **Polling discipline — sound.** No unhandled rejection can kill an
   interval; the `awaiting` guard is race-free (single-threaded JS:
   `tick` either sets `awaiting` or returns). The silence analysis
   above confirms stalling cannot false-positive on quiet audio.
3. **Quota fail-closed — sound and contract-conformant.** Recorder
   keeps recording while chunks are lost — the contract's explicit,
   documented decision (visibility via 4.14 over silent truncation).
   See NOTE 4.
4. **Auto-start can't fail streams — sound.** The entire kickoff,
   including `getChunkWriter()`'s plain-`Error` wiring-defect throw,
   is inside the swallowing try/catch; the channel response is the
   starter's result regardless. See NOTE 2 for a robustness nit.
5. **No schema change — verified.** `db.js` untouched; store is the
   2.2 creation; `DB_VERSION` stays 2.
6. **4.13 seam — sound with a gap (NOTE 1).** `stopForStream()`/
   `stopAll()` stop loops via `stopLoop()` but leave `p` in `polls`
   and the `ondataavailable` handler attached, so the final `stop()`
   flush flows through `onDataAvailable` → `storeChunk` like any other
   chunk. Traced: no path drops it. `addEventListener` (not
   `ondataavailable` assignment) is preferred, so the handler coexists
   with any listener 4.13 attaches.
7. **No new event types / messages — verified** via the passing
   `MSG_*` vocabulary snapshot and absence of new event-name strings.
8. **Changed-files discipline — clean** (see AC7).

## NOTEs (informational; none fail an AC)

1. **4.13 has no awaitable for the final flush.** The contract only
   requires 4.8 to *document* the await-before-finalize seam, which
   it does — but 4.8 exposes no pending-write counter or flush
   callback, so 4.13's planner must design its own await (e.g. poll
   `getChunkState().lastWriteAtUtc`/`lastChunkIndex`, or add a
   `pendingWrites` field to the §6 state shape). Recommend the 4.13
   contract address this explicitly rather than discovering it
   mid-build.
2. **Per-kind kickoff is not individually guarded.** In
   `handleStartStreams`, if `writer.startForStream` threw for one
   streamKind, the `for` loop would skip the remaining kinds.
   Defensive-only today (`startForStream` throws only on validation
   errors, and its inputs come from 4.6's validated registry), but a
   per-kind try/catch would make "chunking can never fail the
   streams" robust against future validation tightening.
3. **Late `dataavailable` after terminal failure still attempts a
   write.** After `chunk-quota-exceeded`, a late event re-attempts the
   write, fails again, and re-records the same state (no spin — the
   loop stays stopped). After `chunk-stalled`, a late chunk is stored
   while the status stays stalled. Both are honest; neither violates
   fail-closed.
4. **Quota semantics for §7.** "The recording keeps running" means
   post-quota audio/video is irrecoverably lost while the recorder
   runs — visible, but lost. Long-session quota behavior is the
   AC12/§7 observation item; the owner should know a full disk yields
   a visibly-degraded (not silently-complete) recording.
5. **V2 not independently re-run by this reviewer.** AC9–AC11 rest on
   the build evidence's harness runs (documented honestly, including
   the harness-injected-timer caveat on AC10). The coordinator's
   behavioral verifier re-runs all harnesses fresh.
6. **4.13 must not assume contiguous `chunkIndex`.** Failed writes
   leave gaps by design (the correct trade: gaps are honest,
   duplicates would be data loss). 4.13's concatenation must iterate
   in key order and tolerate gaps — flag for the 4.13 planner.
7. **Deviation 2 (injected `setTimeout`/`clearTimeout`/`random`) is
   test-surface expansion only** — defaults are the real globals in
   the document; no behavior change, documented in the build report.
