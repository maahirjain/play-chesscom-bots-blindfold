# Task 4.1 build report — dedicated extension recording context

PLAN.md §4.1: "Create a dedicated extension recording context that remains
alive across Chess.com page refreshes; do not host recording solely in the
content script or a transient popup."

Status: BUILT per `.autodev/evidence/4.1.contract.md` (AC1–AC7 V1,
AC8–AC11 V2, AC12 V3-deferred to §7). PLAN.md unmodified. STATE.json
untouched (coordinator-owned). Nothing committed (coordinator-owned).

## What was built

**New files**
- `recorder.html` — offscreen document shell; loads `recorder.js` only.
- `recorder.js` — the recording-context module (repo house convention:
  dependency-free classic script → guarded `BlindfoldSession` global →
  IIFE `'use strict'` → Node `module.exports` shim). Owns: uuid-v4
  `bootId` + UTC-ISO `bootTime` per document boot, best-effort
  `recorder-ready` announcement, the `{kind:'recorder', msg, v:1}` envelope
  validator, and the `recorder-ping` → `recorder-pong` responder (pong
  carries `ok`, `bootId`, `state:'idle'`, and the `performance.now()` hook
  for 4.10/4.12). Unknown kinds/msgs are ignored (no response);
  unknown protocol versions are rejected with `{ok:false}` — never thrown.
  Auto-boots only in a real document context (`typeof document !==
  'undefined'`); inert in Node and never loaded by the SW. **No capture
  code** — pin-tested absent (comments stripped before the token scan).
- `recording_host.js` — SW-side supervisor (same module convention; loaded
  via `importScripts` in `sw.js`). `createRecordingHost(chromeNs, opts)`
  factory (DOM-free, fully injectable for Node tests) owning:
  - `ensureRecordingContext()` — idempotent, retry-safe: `hasDocument()`
    first, concurrent calls collapse onto one in-flight creation, a
    create-race loser is adopted via re-check instead of failing, then a
    ping re-syncs `lastKnownBootId`. On a platform without
    `chrome.offscreen`: `{ok:false, reason:'offscreen-unavailable'}`
    (plain data, never throws).
  - `pingRecorder({timeoutMs})` — resolves the pong; rejects with plain
    `Error('recorder-unreachable')` on timeout (default 5 s, injectable)
    or send failure, so "document gone" is a normal branch.
  - SW-side `recorder-ready` listener (re-syncs in-memory state;
    lenient-on-input, version-rejecting).
  - `start()` — installs the listener, kicks a lazy ensure, **never
    throws** at SW startup.
  - Self-sufficient: does not import recorder.js (its envelope check is
    local), so the SW has no cross-module dependency on the offscreen
    module.
- `tests/recording_host.test.js` — 31 V1 tests (AC1–AC7) with an injected
  `chrome` mock and manual timers.

## Deviations

1. **AC10 mechanism** (harness-only, documented in DECISIONS.md): forcing a
   true SW-process death via CDP proved flaky in this environment —
   `Target.closeTarget` kills the worker but wake-up is unreliable, and a
   DevTools-attached browser does not apply the 30s idle timeout (100 s of
   idle did not terminate the SW). V2 therefore proves re-discovery with a
   fresh host (blank in-memory state) against the real document instead of
   a true process restart. The product code path is identical
   (`start()` → `ensureRecordingContext()` → `hasDocument()` + ping); the
   true process boundary is a §7/owner-device observation (contract AC12).
   The AC9 chess.com-vs-localhost substitution is likewise documented in
   the harness (identical mechanism: offscreen documents are independent of
   every content tab).
2. **No deviations in product code**: the implementation follows the
   contract exactly (single document, full reason set up front, no capture
   code, only the `"offscreen"` permission, channel namespacing, no new
   pipelines).
