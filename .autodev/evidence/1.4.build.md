  `GAME_RESULTS` (1-0, 0-1, 1/2-1/2, *), `TERMINATION_REASONS` (9 grounded
  values), `EVIDENCE_SOURCES`/`FEN_SOURCES` (observed, manual),
  `PROMOTION_PIECES` (q, r, b, n).

  vendored chess.js `validate_fen` field-1/4 rules (8 ranks summing to 8,

- `isSquare`/`isPromotion`; factories `createGameStartedPayload`,
  `createMovePayload`, `createHistoryRecoveredPayload`,
  `createHistoryRevisedPayload`, `createPositionCheckpointPayload`,
  `createGameEndedPayload` with matching `requireValid*` validators.
- Key shapes exactly as specified: `{fen}` (1), `{from,to,promotion}` (3,
  promotion defaults to `null`, `undefined` → TypeError),
  `{recoveryReason,expectedMoveCount}` (2),
  `{revisionKind,retractedMoveEventIds,observedHistoryLength,expectedMoveCount}` (4),
  `{fen,reason,fenSource}` (3),
  `{result,terminationReason,evidenceSource,observedText}` (4).
- `retractedMoveEventIds`: defensively copied then frozen; non-array or
  empty → TypeError; non-string/malformed-UUID element → TypeError
  (mirrors 1.1/1.3 "malformed ID" convention); duplicates → RangeError.
- `observedText`: whitespace-only normalizes to `null` in the factory
  (1.1/1.2 empty→null convention); raw non-empty strings preserved
  verbatim as evidence. `terminationReason`/`observedText` nullable:
  `result:'*'` + `terminationReason:null` is the valid unknown-ending

- Error conventions: TypeError = wrong type/shape (incl. malformed IDs,
  `undefined` promotion, missing keys); RangeError = value outside the
  domain (bad FEN fields, bad squares, from===to, bad vocabulary,
  duplicates, negative/non-integer counts). No plain-`Error` path is
  needed (no ID generation/randomness in this module).

  `recoveryEventId`/`revisionEventId` as the only two refs roles,

## Deviations from the contract

None material. Three test-side judgment calls (all module behavior
matches contract intent):

1. **Extra input keys on factories are ignored, not rejected** (test
   AC1 block). The 1.1/1.3 convention (e.g. `createClockAnchor`,
   `createSessionMetadata`) builds a fresh record from whitelisted
   fields; `requireValid*` still rejects extra keys on the record
   itself. (1.2's `createInitialConditions` instead rejects extra
   input keys — a documented 1.2 deviation.) Test documents this.
2. **Error split for `retractedMoveEventIds`** (contract AC12 left the
   TypeError/RangeError split open): non-array/empty/malformed-UUID
   → TypeError; duplicates → RangeError. Rationale in module comments.
3. **"No Chess/chess.js references" static check** is implemented as
   load-time-dependency check (no `require(`, no `new Chess`, no `.Chess`)
   on comment-stripped source; prose comments explaining *why* there is
   no dependency are allowed. A `chrome.`-style literal token was
   avoided in comments to keep the raw-source check consistent with the
   1.1 convention.
