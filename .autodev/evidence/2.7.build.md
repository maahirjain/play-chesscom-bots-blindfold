# Task 2.7 build report — page/context start and clean-end events; unclean-discontinuity marking

Implements `.autodev/evidence/2.7.contract.md` (18 ACs: AC1–AC15 V1,
AC16–AC17 V2, AC18 V3-deferred to §7/owner device).

## Implementation summary

**New module `lifecycle.js`** (module convention: dependency-free classic
script → guarded `BlindfoldSession` global → IIFE `'use strict'` → Node
shim):
- Constants `PAGE_START`/`PAGE_END_CLEAN`/`PAGE_DISCONTINUITY` (task-owned,
  per the 1.3 precedent; `event_envelope.js` untouched).
- Strict validators: `requireValidPageStartPayload` (exactly `{}`),
  `requireValidPageEndPayload` (exactly `{reason:'pagehide'}`),
  `requireValidDiscontinuityPayload` (exactly
  `{orphanedSegmentId,newSegmentId}`, uuid-v4),
  `requireValidDiscontinuityRefs` (exactly `{orphanedStartEventId}`,
  uuid-v4). Extra keys rejected (TypeError); bad domain values → RangeError.
- Content-side: `emitPageStart`/`emitPageEndClean` (thin wrappers over an
  injected sender; gameId null; eager — the sender's own lazy anchor lands
  at sourceSeq 0, the lifecycle event at 1), `installPageEndHook`
  (pagehide listener; skips bfcache `persisted`; emits only when
  `activeSessionId` is a non-empty string; never throws; never `flush()`),
  and the `activeSessionId = null` §5 seam.
- SW-side: `afterEventStored(event, ack)` (undefined unless a committed
  `page_start`; never sync-throws), `notePageStartStored` (defensive
  validation → resolved no-op on malformed; per-session promise-chain
  serialization so concurrent page_starts never double-mark and the chain
  survives a rejection), `detectOrphans` (reads the session's event stream
  via `DB.getAll({index:'bySessionId'})`; partitions anchors/ends/markers/
  starts; flags starts with no end, no marker, and a passing temporal
  guard; writes one `page_discontinuity` per orphan via
  `BlindfoldSession.writeEvent` — zero raw IDB writes, sole-writer
  invariant holds), `ensureSwAnchor` (lazy per-(SW-instance,session) clock
  anchor at sourceSeq 0; write failure rejects — self-heals on the next
  start).

**`writer.js`**: the §3.2 generic post-commit hook — `fireAfterEventStored`
helper + call sites after `sendResponse(ack)` and after the failure-path
`sendResponse(failAck)` (the hook filters on `ack.ok` itself); type-agnostic
(never inspects event types); failures swallowed so the ack path never
breaks. Header's 2.7 absent-line removed.

**`sw.js`**: importScripts gains `'lifecycle.js'` last; header documents the
detector and drops 2.7 from the absent list.

**`content.js`**: exactly one added line —
`BlindfoldSession.installPageEndHook(BlindfoldSession.sender);`.

**`manifest.json`**: content_scripts js gains `'lifecycle.js'` after
`'sender.js'`; nothing else changed.

## Deviations from the contract

None material. Two implementation notes:
- The contract's §3.2 snippet showed the hook on the success path only;
  the build also fires it on the failure path ("any ack — the hook itself
  filters on `ok`"), implemented as a named helper to avoid duplicating the
  try/catch. The AC15 pin asserts both call sites and type-agnosticism.
- `requireSender` rejects non-object senders with a single TypeError
  branch (contract-conformant).
