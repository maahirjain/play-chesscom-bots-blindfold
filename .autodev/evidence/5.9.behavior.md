## 3. Contract behaviors — verified against the code

I read the implementation directly (session_controls.js `handleGameReset`, content.js `handleGameResetEvent`), not just the build report.

### (a) New gameId minted on mid-session reset — ✓
- `handleGameReset()` mints via `BS.newGameId()` (UUID v4, no fallback) only after
  the phase-ACTIVE and metadata-present checks pass.
- AC1 test pins: uuid-v4 format regex, distinct from old gameId, `gameIds` goes
  length 1 → 2 (appended, not replaced), slots updated to the new gameId.

### (b) Boundary preserved (game_reset under old gameId before switch) — ✓
- content.js `handleGameResetEvent`: `gameLifecycleRecorder.recordGameReset(...)`
  is called **synchronously before** the async `handle.handleGameReset()` promise
  chain that mints the new identity. The code comment is explicit: "The game_reset
  event goes out under the OLD gameId — it is the boundary marker; the new
  identity does not exist yet."
- `activeGameId` is unchanged at emission time, so the event is guaranteed under
  the old gameId. Subsequent emissions read the new gameId only after
  `setSlots(sid, newGameId)` succeeds.

### (c) SessionId unchanged — ✓
- The implementation captures `sid = activeSessionId` before the channel calls and
  passes `{sessionId: sid, gameId: newGameId}` to `recorder-set-session`.
- AC2/AC3 test pins this with `assert.strictEqual(setSessionCalls[0].sessionId, sessionId)`
  (byte-identical, not just deep-equal) and asserts `session-save` precedes
  `set-session` via transport-call ordering.

### (d) Fail-closed on errors — ✓
- Phase not ACTIVE → `{ok:false, error:'not-active'}` (AC5).
- No metadata (5.1 no-fields path, boot-adopted session) → `{ok:false, error:'no-metadata'}` (V2 AC7).
- `newGameId()` throws → `mint-failed`; `addGameToSession` throws → `metadata-invalid`.
- `session-save` fails → `{ok:false, error:'session-save-failed'}`; old gameId stays
  active, no recorder re-set sent, phase stays active (AC4).
- Recorder re-set refused (`session-active` — another tab won the TOCTOU race) →
  `{ok:false, error:'set-session-failed:session-active'}`; old gameId stays (AC4b).
- Note (per-contract, not a defect): on set-session failure *after* a successful
  session-save, the metadata persists with the unadopted gameId. The contract §3
  explicitly specifies no rollback: "a persisted-but-unadopted gameId is honest
  raw data (the metadata records a detected game; §6 exports what was observed)."

### (e) No-op when not ACTIVE — ✓
- AC5: idle → `{ok:false, error:'not-active'}`, zero channel traffic, slots stay null.
- The implementation checks `phase !== CONTROL_PHASE_ACTIVE` first, covering idle,
  STARTING, and STOPPING (fail-closed per contract §2).

emitted under the old gameId as the boundary, and honest fail-closed behavior on
