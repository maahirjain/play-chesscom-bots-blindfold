### AC1 — Separation: recorder.js holds no page-bound references (2 tests)

- **Test 1:** `recorder.js does not query the chess.com page DOM` — Source scan
  asserts no references to `wc-chess-board`, `chess-board`, `.move-list`.
  `querySelector` is allowed only if not targeting page DOM.
- **Test 2:** `recorder.js capture path uses no page-specific chrome.tabs calls` —
  Any `chrome.tabs` usage must be for `ownerTabId`/`sender.tab` (5.5 guard),
  not for capture.

**Result:** PASS. The offscreen recorder is architecturally separated from
the page. No page-bound references exist in the recording lifecycle.

### AC2 — No teardown on content-script unload (2 tests)

- **Test 1:** `content.js has no beforeunload/unload handler` — Asserts no
  `beforeunload` string and no `addEventListener('unload')` patterns.
- **Test 2:** `session_controls.js has no beforeunload/unload handler that
  stops streams` — The `MSG_STOP_STREAMS` send (line 1726) is verified to
  be in the Stop button handler context, not an unload hook. Surrounding
  10 lines checked for unload patterns.

**Result:** PASS. A page refresh does not trigger a stop. The recorder
keeps running when the page goes away.

### AC3 — Re-binding: reload with same session ID is idempotent (3 tests)

Uses the `duplicate_start.test.js` harness pattern (real `onRuntimeMessage`
dispatch with injectable selectors).

- **Test 1:** `same session ID re-set is allowed` — Initial set-session
  succeeds; reload re-set with same SID (different tab ID) succeeds.
- **Test 2:** `re-set does not mint a new session or stop streams` — After
  reload re-set, a DIFFERENT session ID is still refused with
  `'session-active'` (5.5 guard intact).
- **Test 3:** `recorder keeps no per-page state` — Guard discriminates on
  sessionId equality, not tab identity. Same SID + different tab → allowed;
  different SID + same tab → refused.

**Result:** PASS. The 5.5 duplicate-Start guard is the re-binding mechanism:
same session ID → idempotent re-set; different session ID → refused.
