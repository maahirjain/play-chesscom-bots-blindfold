# 6.3 contract — Export media-sync.json with media filenames, formats, clock anchors, segment offsets, and known gaps

**Planner:** task planner subagent. **Date:** 2026-10-06.
**Scope:** PLAN.md §6.3. **Branch:** `autodev/logging-instrumentation`.
**Status:** CONTRACT ONLY. No implementation code written. PLAN.md unmodified.
STATE.json untouched (coordinator-owned).

## 1. Scope

PLAN.md §6.3: "Export media-sync.json with media filenames, formats,
clock anchors, segment offsets, and known gaps."

**PLAN evidence:** the §(a) export table defines media-sync.json's raw
data: "Media/segment IDs and filenames, actual formats, links to clock
anchors, alignment offsets/timecodes, synchronization markers, and
discontinuities. References underlying events where possible rather
than duplicating their payloads."

**What 6.3 does:** Add a pure builder function (in the SW-side
`exporter.js` module, per the section architecture and 6.1's
precedent) that takes the session's recording-manifest records, the
session's clock anchors, 5.10's stop verdict, the 6.5 filename
mapping, and optional chunk statistics, and returns the exact
`media-sync.json` string for the bundle.

**What 6.3 does NOT do:** It does not read IndexedDB itself (6.6's
orchestration reads the `recording_manifest` store and the
`clock_anchor` events and passes plain records in — the builder is
pure and Node-testable). It does not read media chunks (6.4's job).
It does not generate filenames (6.5's naming function does that; 6.3
consumes its output mapping). It does not touch metadata.json (6.1),
events.jsonl (6.2), or the ZIP (6.6).

## 2. Inputs

The builder function signature (names at the builder's discretion):

```
buildMediaSyncJson({ manifestRecords, clockAnchors, stopVerdict, segmentFiles, chunkStats, nowUtcIso })
```

| Input | Source | Required? |
|-------|--------|-----------|
| `manifestRecords` | `recording_manifest` bySessionId (18-key records) | Yes — may be empty (a session with no media exports `"segments": []`; honest, not an error) |
| `clockAnchors` | `clock_anchor` event payloads for the session (`{segmentId, utcEpochMs, monotonicMs}`), extracted by 6.6's orchestration from the events stream (6.1's `gameStartingFens` precedent) | Yes — may be empty (missing anchors are reported as gaps, never fabricated) |
| `stopVerdict` | 5.10's retained `{stopResp, flushResult, verdict, warnings}` passed in the `export-request` message | No — absent → `knownGaps` carries `'stop-verdict-unavailable'`; per-segment facts still exported (never fabricate 'complete') |
| `segmentFiles` | `{segmentId: filename}` mapping from 6.5's naming function (run by 6.6's orchestration before 6.3) | No — absent entries → `"filename": null` for that segment (honest) |
| `chunkStats` | `{segmentId: {chunkCount, chunksAfterFinalize}}`, computed by 6.6's orchestration while reading chunks for 6.4 | No — absent → `chunkCount`/`chunksAfterFinalize` are `null` (unknown, not zero) |
| `nowUtcIso` | Injected clock for the labeled `exportedAtUtc` (6.1 precedent, test seam) | No — defaults to real UTC ISO |

All inputs are plain data. The function performs no I/O, mints no IDs.

## 3. media-sync.json schema (exact)

Top-level keys, in this order (stable output for 6.7's byte-identity):

```jsonc
{
  "segments": [
    {
      "segmentId": "<uuid>",            // manifest record, verbatim
      "streamKind": "microphone|screen|webcam",
      "segmentNumber": "<number|null>", // 4.13's finalize numbering; null = never finalized (honest)
      "filename": "<string|null>",      // from segmentFiles; null when unmapped
      "format": "<mime|null>",          // actualMimeType verbatim; null when empty/absent
      "fileExtension": "<string>",      // manifest verbatim
      "finalized": "<bool>",            // segmentNumber !== null
      "finalizedAtUtc": "<iso|null>",   // manifest verbatim
      "createdAtUtc": "<iso>",          // manifest verbatim
      "streamStartedAtUtc": "<iso|null>",       // manifest verbatim (4.6)
      "streamStartedAtMonotonicMs": "<number|null>", // manifest verbatim (4.6)
      "clockSegmentId": "<uuid|null>",  // manifest verbatim (4.10 link)
      "clockAnchor": {                  // the anchor for clockSegmentId, or null
        "segmentId": "<uuid>",
        "utcEpochMs": "<number>",
        "monotonicMs": "<number>"
      },
      "mediaStartWallUtcMs": "<number|null>",
      // Computed alignment offset: the wall-clock time of this
      // segment's media-time zero (the 4.6 start() call time, per
      // 4.12 §3.1: timecode 0 ≈ streamStartedAtMonotonicMs).
      // Formula (timecode.js canonical):
      //   anchor.utcEpochMs + (streamStartedAtMonotonicMs - anchor.monotonicMs)
      // null when the anchor is missing or either side is unusable
      // (unknown is null, never a guess).
      "chunkCount": "<number|null>",    // from chunkStats; null when unknown
      "chunksAfterFinalize": "<number|null>",
      // Chunks that landed after finalization (architecture §5:
      // included in the segment's file; noted here when nonzero).
      "gaps": ["<gap-string>", ...]     // per-segment known gaps (§4)
    }
  ],
  "knownGaps": ["<gap-string>", ...],   // session-level known gaps (§4)
  "stopVerdict": "complete|complete-with-warnings|unknown",
  "exportedAtUtc": "<iso>"             // export time — labeled export
                                       // metadata, not session data (6.1 precedent)
}
```

**Segment ordering** (deterministic for 6.7): grouped by streamKind
in `EXPORTER_STREAM_KINDS` order (`microphone`, `screen`, `webcam`);
within a kind, by `segmentNumber` ascending with `null`s last; then
`createdAtUtc` ascending; then `segmentId` lexicographically.

**Field rules (raw-data discipline):**
- Manifest facts are copied verbatim — never re-derived (the
  `fileExtension` is copied, not re-derived from the MIME type,
  per finalizer.js's own comment).
- `clockAnchor` is the matching anchor payload looked up by
  `clockSegmentId`; when the link is null or no anchor matches, it
  is `null` and a gap is recorded (§4) — never a fabricated anchor.
- `mediaStartWallUtcMs` is the ONE computed value in this file, and
  it is here because PLAN §6.3 explicitly requires "segment
  offsets" and the §(a) table requires "alignment offsets/
  timecodes". The computation is the timecode.js canonical formula
  (§3 above), documented in the schema. This is an export-time
  alignment aid, not a stored collection value (4.12's
  no-persist rule governs the stores, not the export bundle).
  Every other value is a copied fact.
- `stopVerdict` echoes 5.10's verdict string; `'failed'` is refused
  upstream by 6.6's orchestration (6.1 precedent) and never reaches
  this builder — if it does, the builder throws plain `Error`
  (fail-closed, like 6.1's `session-not-complete`).

## 4. Known gaps

### 4.1 Session-level `knownGaps`

- From 5.10's verdict warnings, verbatim: `<kind>-flush-timed-out`,
  `<kind>-failed:<error>`, `<kind>:missing-stream-result`,
  `<N>-events-undelivered`, `stop-response-malformed`,
  `flush-result-unknown` (the exact warning vocabulary from
  5.10's build report).
- Absent `stopVerdict` → `["stop-verdict-unavailable"]` (gaps
  unknown; the per-segment facts below still export).
- Empty (no warnings, verdict `'complete'`) → `[]`.

### 4.2 Per-segment `gaps`

Facts derived from the segment's own records (strings, stable
vocabulary):

- `"unfinalized"` — `segmentNumber` is null (4.13 never numbered
  it; 6.5 numbers the *filename* on the fly per architecture §5,
  but the sync file reports the stored fact).
- `"flush-timed-out"` — `stopVerdict.stopResp.streams[streamKind]
  .flushTimedOut === true` (the response-only 4.13 fact 5.10
  surfaced; applied to every segment of that kind — it is a
  kind-level fact, labeled as such by the kind key, not
  misattributed to one segment).
- `"stream-failed"` — `stopVerdict.stopResp.streams[streamKind].ok
  === false`.
- `"chunks-after-finalize:<N>"` — `chunksAfterFinalize > 0`.
- `"missing-clock-anchor"` — `clockSegmentId` non-null but no
  matching anchor in `clockAnchors`.
- `"missing-stream-start-time"` — `streamStartedAtMonotonicMs`
  null/unusable (alignment offset uncomputable).

No gap strings are invented beyond this vocabulary; an empty array
means no known gaps for that segment.

## 5. Malformed input (fail-closed, never silent)

- `manifestRecords` not an array, or any record not a plain object
  with a non-empty `streamKind` → `TypeError` (6.1's
  `requireValidManifestRecords` precedent).
- `clockAnchors` not an array, or any entry not a plain object
  with string `segmentId` and numeric `utcEpochMs`/`monotonicMs`
  → `TypeError`.
- `stopVerdict` malformed per 6.1's `requireValidStopVerdict`
  (unrecognized non-`'failed'` verdict → `TypeError`; `'failed'`
  → plain `Error`, fail-closed).
- `segmentFiles`/`chunkStats` present but not plain objects →
  `TypeError`. Their per-segment entries are validated lightly
  (filename must be a non-empty string when present; counts must
  be non-negative integers when present) — malformed entries
  throw rather than silently dropping a segment's filename.

## 6. Acceptance criteria

### V1 — static/unit (Node, no IndexedDB)

- [ ] **AC1.** Golden-shape test: fixture with two kinds × two
  segments (one finalized, one `segmentNumber: null`), matching
  anchors, a `flushTimedOut` verdict, and a filename mapping
  produces byte-exact media-sync.json matching the §3 schema —
  segment order, key order, and the computed
  `mediaStartWallUtcMs` all pinned.
- [ ] **AC2.** Known gaps: fixture with `flushTimedOut: true` on
  webcam, `pending: 3` undelivered events, and a failed screen
  stream surfaces all three in `knownGaps` verbatim plus the
  per-segment `"flush-timed-out"` / `"stream-failed"` entries;
  `chunksAfterFinalize: 2` yields `"chunks-after-finalize:2"`.
- [ ] **AC3.** Absent stopVerdict → `knownGaps` is
  `["stop-verdict-unavailable"]`, `stopVerdict` is `"unknown"`,
  per-segment manifest facts still export (never fabricated
  `'complete'`).
- [ ] **AC4.** Missing anchor: segment with non-null
  `clockSegmentId` and no matching anchor → `"clockAnchor":
  null`, `"mediaStartWallUtcMs": null`, gap
  `"missing-clock-anchor"` — never a fabricated anchor or offset.
- [ ] **AC5.** Unfinalized segments: `segmentNumber: null` →
  `"finalized": false`, gap `"unfinalized"`, still listed (not
  omitted); `filename` comes from `segmentFiles` regardless of
  finalization.
- [ ] **AC6.** Purity: no I/O, no IndexedDB, no ID minting; the
  only clock read is the labeled `exportedAtUtc` (injected
  `nowUtcIso`); inputs not mutated (frozen-output or copy
  assertion); `TypeError` on malformed input, plain `Error` on
  `'failed'` verdict.
- [ ] **AC7.** Diff discipline: new code lives only in
  `exporter.js` (+ its test file); no changes to stores, writer,
  manifest, finalizer, or content scripts; no new event
  types/messages/stores/permissions (6.6 owns the permission +
  message); PLAN.md unmodified.

## 7. Explicit non-goals

- Reading IndexedDB or media chunks (6.6's orchestration / 6.4 do
  that; 6.3 is pure).
- Generating filenames (6.5's naming function; 6.3 consumes its
  `{segmentId: filename}` mapping).
- Computing `chunksAfterFinalize` (6.6's orchestration counts
  while reading chunks for 6.4; 6.3 consumes the counts).
- ZIP packaging, download, permission, affordance (6.6).
- Transcoding, playback, or bundle preview.
- metadata.json / events.jsonl (6.1, 6.2).
- Interpreting gaps (no "the recording is unusable" — raw facts
  only; the verdict string is 5.10's, echoed verbatim).

## 9. Open questions for the builder

1. **`flush-timed-out` attribution:** the contract applies the
   kind-level fact to every segment of that kind. If the builder
   finds a more precise attribution in the finalizer records
   (e.g., only the active segment at Stop), document it — but do
   not guess; kind-level labeling is the honest default.
2. **Offset precision:** `mediaStartWallUtcMs` is a float
   (millisecond fractions from `performance.now()`); the builder
   must not round it (rounding is a lossy transformation —
   analysis code rounds if it wants to).
