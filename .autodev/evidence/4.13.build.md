## Summary

Implemented the Stop half of the recording lifecycle. On the new
`recorder-stop-streams` channel message, the new `finalizer.js` module:

1. Guards (`no-session`, `start-in-progress`) before any device/media action.
2. Emits the 4.11 stop sync marker (failure → `markerId:null`, never a Stop failure).
3. Waits `STOP_MARKER_WAIT_MS = 1000` once globally for the double-beep capture.
4. Stops 4.8's chunk poll loops (the `ondataavailable` handler stays attached — the 4.8 seam — so the final `stop()` flush is stored).
5. Calls `recorder.stop()` per recording stream (skipped when not `'recording'`; `InvalidStateError` race → skip).
6. Awaits the final flush: polls `recorder.state` → `'inactive'` (≤5 s, 100 ms cadence), then a 1 s write grace. Timeout → honest `flushTimedOut:true`, still finalizes.
7. Detaches the 4.9 track monitor **before** stopping tracks (a clean Stop is not a discontinuity).
8. Stops tracks per-track (try/catch each) and discards the 4.6 registry entries (new `discardActiveStream` seam in `stream_starter.js`).
9. Runs the finalize pass: splits discontinuous segments (§4), numbers per `(sessionId, streamKind)` chronologically 1-based (§3), marks `finalizedAtUtc` (§2).

"Finalize" closes the segment's chunk set — 4.13 never assembles media files (§6.4), never ZIPs (§6.6), never writes to downloads/OPFS (V1 code-scan pinned).

## Design decisions (see DECISIONS.md ## 4.13 for the full list)

- **Module name `finalizer.js`**: the contract (§1, §8, AC8) is authoritative over the spawn brief's `stream_stopper.js`.
- **Atomic split re-key via raw indexedDB**: `BlindfoldSession.DB` exposes only `put`/`get`/`getAll` — no delete, no multi-store transaction — so the finalizer uses injected `indexedDB` directly for the single readwrite transaction over `['media_chunks', 'recording_manifest']`. Targeted `delete([seg,idx])` + `put(rekeyed)` by explicit key; no cursor, no IDBKeyRange.
- **`finalizedAtUtc` is 4.9's reserved field**: 4.9's `isManifestRecordFinalized()` exclusion works with no other 4.9 change.
- **Backfill on read**: records written by older extension versions (16 keys) get missing keys backfilled to `null` before validation — null is the honest "not observed" (the 4.6/4.7 nullable-field precedent). Real corruption (e.g. null `segmentId`) still fails validation.
- **Failed kinds are excluded from the finalize pass**: their segments stay unfinalized for a later retry (a later Stop re-attempts them).
- **Crash-recovery finalizes orphans without a marker** (no media to align to); double Stop is the exact `nothing-to-finalize` no-op.

## Deviations from the contract

1. **Module name** (`finalizer.js` vs brief's `stream_stopper.js`): contract wins. No functional impact.
2. **AC8's file list omits `format_support.js`**, but AC2 requires the MANIFEST_KEYS 16→18 widening (which lives in `format_support.js`). The change was made; the contract's file list is inconsistent. Flagged for the reviewer.
3. **Test helper `makeSplitWorld`**: the split tests use a minimal direct-construction helper rather than the full `makeWorld` — during development, `makeWorld`'s db sharing proved fragile for the split path (the finalizer read 0 events despite the test db having 1). Direct construction with an explicitly shared db is deterministic. The non-split tests use the full `makeWorld`.

## Honest limitations

- **The mid-segment split path is V1-pinned only.** Post-gap media (a real `track-ended` mid-recording with the recorder surviving) is not forceable headless. The V2 harness documents this; the split logic (gap detection, atomic re-key, linker, numbering) is covered by 36 unit tests with a faithful fake IDB.
- **Stop double-beep audibility in the recording** needs human ears (§7/AC11). V2 proves the marker is emitted (event log), the 1000 ms window is waited, and the markerId links the response to the events.
- **Old-record backfill**: records written by pre-4.13 extension versions get the two new keys backfilled to `null` at finalize time. This is deliberate (null = not observed), not silent data loss.
