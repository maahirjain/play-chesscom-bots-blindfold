# Task 3.4 contract — Instrument speech in sounds.js

PLAN.md §3.4 (human-owned; quoted verbatim):

> 3.4. Instrument speech in sounds.js.
>
> 3.4.1. Give each utterance an ID linked to its move, help request, or game-result event.
> 3.4.2. Record utterance start and end callbacks.
> 3.4.3. Record cancellation requests and speech errors, distinguishing requested cancellation from an observed completion.
> 3.4.4. Save spoken text only when its actual content cannot be reproduced from the referenced event and versioned speech logic.
> 3.4.5. Record initial voice/rate settings and subsequent changes needed to interpret delivery.

## 1. Current-state analysis (sounds.js, 313 lines)

Speech flow today:

- `speakText(text, {interrupt=true, rate=1})` — fire-and-forget. No
  callbacks attached. `interrupt:true` calls `speechSynthesis.cancel()`
  first. Sets `current_utterance`. Callers: `sayMove`, `announceResultIfOver`,
  help shortcuts `w/m/z/i/s`, `speakPosition`.
- `speakTextAsync(text, {interrupt=false, rate=1})` — promise-based;
  `onend`/`onerror` both resolve. Used only by `speakFullMoveList`
  (`i` shortcut), which chains one utterance per move-list line at
  rate 0.9. A `speech_timestamp` guard abandons the sequence logically
  (no `speechSynthesis.cancel()` — already-spoken utterances are unaffected).
- `stopAllSpeech()` — increments `speech_timestamp` and calls
  `speechSynthesis.cancel()`. Called by the Escape handler (content.js).
- `playIllegalMoveSound()` — `<audio>` element, not speech synthesis.
  **Out of scope** (not an utterance; no callbacks exist to record).
- Fixed synthesis params: `pitch = 1`, `volume = 1` everywhere;
  `rate` varies per call (1 default, 0.9 move list, 0.7 position readout).
  No voice selection UI — the browser default voice is always used.
- `sayMove(game_before_move, san)` derives text via `sanToSpeech` and
  stores `last_spoken_move_text` (already used by the `z` shortcut).
- `announceResultIfOver()` derives text via `getResultAnnouncement(game)`
  from the internal chess.js state. Called from the 3.1 move observer
  (content.js:108) after confirmed moves.
- sounds.js currently uses **no** `BlindfoldSession` namespace; its
  functions are plain globals. The 3.4 instrumentation must introduce the
  guarded-namespace + Node-shim pattern (3.1/3.2/3.3 precedent) for the
  tracker factory while keeping existing global speech functions working.

Link sources available today:

- 3.1 `result.confirmed[]` entries carry `eventId` (null when inert).
  content.js currently calls `sayMove(new Chess(m.preFen), m.san)` —
  the builder must thread `m.eventId` through.
- 3.3 `recordHelpRequest` returns the help_requested `eventId` (null when
  inert), but content.js's `recordHelpRequestSafe` wrapper **discards** it.
  The builder must capture and forward it.
- No `game_result` event type exists. `announceResultIfOver` is triggered
  by the terminal confirmed move. (3.5.3 owns Chess.com result observation;
  3.4 must not steal that scope.)

## 2. Design

### 2.1 New `createSpeechTracker` in sounds.js

DOM-free factory following the 3.1/3.2/3.3 recorder precedent:

```js
BlindfoldSession.createSpeechTracker({
  getSessionId: () => ...,   // thunk, read at call time (§5 seam)
  getGameId: () => ...,      // thunk, read at call time (§5 seam)
  emitEvent: (type, payload, refs) => ...,  // returns envelope w/ eventId
  speak: (utterance) => ..., // injected speech primitive (default: speechSynthesis.speak)
  cancel: () => ...,         // injected cancel primitive (default: speechSynthesis.cancel)
  getVoices: () => ...,      // injected (default: speechSynthesis.getVoices.bind)
  newUtterance: (text) => ..., // injected (default: (t) => new SpeechSynthesisUtterance(t))
})
```

- Emission gated on **non-empty sessionId AND gameId** via thunks
  (pre-§5 inert — the 2.7/3.1/3.2/3.3 §5-seam precedent). When inert,
  speech proceeds normally; no events; link IDs are null.
- **Failure isolation (3.2 SF-1 precedent):** every tracker call from a
  speech path is wrapped so instrumentation can never break speech,
  throw into page code, or reject unhandled.
- The tracker's `speak(text, opts)` is the single choke point the
  instrumented speech functions call. `opts.link = { trigger,
  moveEventId?, helpRequestEventId? }` (see §2.3).

### 2.2 Utterance lifecycle

Each utterance gets a **uuid-v4 `utteranceId`** (via the existing
`BlindfoldSession.newEventId`, not a new ID scheme — consistency with 1.3).

1. `speak()` creates the utterance, assigns callbacks, emits
   **`utterance_started`** (3.4.1, 3.4.2), then invokes the injected
   `speak` primitive.
2. `onstart` — no separate event (the started event is emitted at
   dispatch; the callback's firing is not separately observable in a
   useful way — document this).
3. `onend` → **`utterance_ended`** `{outcome: 'completed'}` if no cancel
   was requested for this utterance, else `{outcome: 'cancelled'}`.
4. `onerror` → **`utterance_ended`** `{outcome: 'error', errorName}` with
   the raw `SpeechSynthesisErrorEvent.error` string (e.g. Chrome's
   `'canceled'`), unless a cancel was requested → then
   `{outcome: 'cancelled'}` (3.4.3's requested-vs-observed distinction is
   made by **correlating the callback with the cancel request**, not by
   trusting the callback name alone).
5. Every call to the injected `cancel` primitive (our code's
   `speechSynthesis.cancel()`: `interrupt:true` speaks, `stopAllSpeech`,
   Escape) emits **`utterance_cancel_requested`**
   `{utteranceId, source}` for **each in-flight utterance** at cancel
   time — the request is recorded even if callbacks never fire.
   `source: 'user'` (Escape / stopAllSpeech) vs `'interrupt-replace'`
   (a new utterance preempting). The timestamp-guard abandonment in
   `speakFullMoveList` is **not** a cancel (no `cancel()` call) and
   records nothing — document this.

In-flight set: utterances created but not yet ended. `interrupt:true`
marks the previous in-flight utterances cancel-requested
(`'interrupt-replace'`) before creating the replacement.

### 2.3 Event types (3.4-owned constants in sounds.js; event_envelope.js untouched)

`EVENT_TYPE_RE` (`/^[a-z][a-z0-9_]{0,63}$/`) already accepts these.

- **`utterance_started`** — payload (exact keys):
  `{utteranceId, trigger, speechLogicVersion, rate, pitch, volume,
  voiceName, text}` where `text` is `string|null` per §2.5.
  `trigger ∈ {'move','help-request','game-result'}`.
  refs: **one** of `{moveEventId}` / `{helpRequestEventId}` (1.3
  camelCase `Id`-role convention). Game-result utterances link via
  `{moveEventId}` = the **terminal confirmed move's** eventId, with
  `trigger: 'game-result'` disambiguating from a move utterance
  (documented; no new game-result event — 3.5.3 owns result observation).
- **`utterance_ended`** — payload: `{utteranceId, outcome,
  cancelSource, errorName}`; `outcome ∈
  {'completed','cancelled','error'}`; `cancelSource ∈
  {'user','interrupt-replace',null}`; `errorName: string|null` (raw
  callback error, null unless outcome='error'). No refs (utteranceId
  is the join key).
- **`utterance_cancel_requested`** — payload: `{utteranceId, source}`;
  `source ∈ {'user','interrupt-replace'}`. No refs.
- **`speech_settings`** — emitted **once**, at the first utterance:
  `{voiceName, voiceCount, rate, pitch, volume}` = effective baseline
  (3.4.5 "initial settings"). Per-utterance rate/pitch/volume/voiceName
  on every `utterance_started` covers "subsequent changes needed to
  interpret delivery" — any deviation from baseline is self-describing.

### 2.4 speechSynthesis callback preservation

`speakTextAsync`'s promise must keep resolving on end/error exactly as
today. Instrumentation callbacks wrap (not replace) the existing
resolve handlers. `speakText` gains `onstart`/`onend`/`onerror`
attachments where it previously had none — behavior-neutral (no
user-visible change).

### 2.5 The 3.4.4 text-saving rule (precise)

`utterance_started.text` is `null` **unless the call site opts in** by
passing the text for saving. The contract enumerates the opt-in sites —
currently exactly one:

- `speakPosition()` when the board DOM is missing: the spoken text is
  the DOM-observation failure `"Board not found."`, which cannot be
  reproduced from any event. Save verbatim.

All other call sites (`sayMove`, result announcement, `w/m/z/i/s`
shortcuts, move-list lines) produce text **reproducible from the linked
event + versioned speech logic** and save nothing:

| call site | reproducible from |
|---|---|
| `sayMove` | linked `move_confirmed` `{from,to,promotion}` + `sanToSpeech` |
| result announcement | terminal game state (reconstructible per §6) + `getResultAnnouncement` |
| `w` "White's/Black's turn" | linked `help_requested` + ply parity from event stream |
| `m` result / "Game not over." | game state + `getResultAnnouncement` |
| `z` "Last move: …" | chained from the referenced `sayMove` text |
| `i` move-list lines | move history + `sanToSpeech` |
| `s` position readout | FEN (reconstructible) + `positionToSpeechText` |

To make "versioned speech logic" real, sounds.js gains
**`SPEECH_LOGIC_VERSION = '1'`** (frozen string, exported on
`BlindfoldSession`); every `utterance_started` carries it. **Bump rule
(documented in DECISIONS.md):** any change to `sanToSpeech`,
`getResultAnnouncement`, `positionToSpeechText`, `getDisambiguation`,
or the shortcut text templates requires bumping the version — otherwise
analysts cannot replay historical utterances.

### 2.6 Call-site threading (content.js, surgical)

- `sayMove(game_before_move, san_move, link)` gains an optional `link`
  param; content.js passes `{trigger:'move', moveEventId: m.eventId}`.
- `recordHelpRequestSafe` **returns** the eventId (currently discarded);
  each help handler passes `{trigger:'help-request',
  helpRequestEventId}` to its `speakText` call.
- `announceResultIfOver(link)` gains optional link; the move observer
  passes `{trigger:'game-result', moveEventId: <last confirmed move>}`
  (null-safe when no moves confirmed).
- `speakText(text, {interrupt, rate, link, saveText})` — `link` and
  `saveText` optional; existing callers without them behave exactly as
  today (unlinked, text not saved).
- `speakTextAsync` gains the same optional link plumbing for the
  `i`-shortcut move-list utterances (each line links the same
  helpRequestEventId).

### 2.7 Validators

Exact-keys payload validators per the 3.1/3.2/3.3 precedent
(`requireValidUtteranceStartedPayload`, `...EndedPayload`,
`...CancelRequestedPayload`, `...SpeechSettingsPayload`;
TypeError = wrong type/shape, RangeError = bad enum/domain value).
`sounds.js` gains the guarded `BlindfoldSession` namespace + Node shim
for the factory/validators/constants; the existing global speech
functions keep working unchanged.

## 3. Acceptance criteria

### V1 (static + unit, DOM-free via injected speech primitives)

- [ ] **AC1.** Every utterance created through the tracker gets a uuid-v4
  `utteranceId`; `utterance_started` carries exactly one link ref
  (`moveEventId` xor `helpRequestEventId`); game-result utterances use
  `moveEventId` of the terminal move with `trigger:'game-result'`.
- [ ] **AC2.** `utterance_started` payload has exactly the §2.3 keys;
  `speechLogicVersion` equals `SPEECH_LOGIC_VERSION`; per-utterance
  rate/pitch/volume/voiceName recorded.
- [ ] **AC3.** `onend` without cancel → `utterance_ended`
  `{outcome:'completed', cancelSource:null, errorName:null}`.
- [ ] **AC4.** `speechSynthesis.cancel()` with N in-flight utterances →
  N `utterance_cancel_requested` events with correct `source`
  (`'user'` vs `'interrupt-replace'`); subsequent callbacks correlate
  to `{outcome:'cancelled'}`.
- [ ] **AC5.** `onerror` without cancel request → `{outcome:'error',
  errorName:<raw>}`; with prior cancel request → `'cancelled'`
  (requested-vs-observed distinction).
- [ ] **AC6.** 3.4.4 rule: `text` is null for move/result/help utterances;
  `"Board not found."` is saved verbatim; the opt-in site list is pinned
  by test.
- [ ] **AC7.** `speech_settings` emitted exactly once (first utterance),
  with baseline voice/rate/pitch/volume.
- [ ] **AC8.** `speakTextAsync` promise still resolves on end AND error
  (no behavior change); `speakText` with no link behaves as before.
- [ ] **AC9.** Pre-§5 inertness: null/empty sessionId or gameId → speech
  works, zero events. Instrumentation throw → speech unaffected
  (failure isolation).
- [ ] **AC10.** Validators: exact keys; TypeError/RangeError per
  convention; `event_envelope.js` untouched; `playIllegalMoveSound`
  untouched (not an utterance).
- [ ] **AC11.** Diff discipline: only `sounds.js` + `content.js` among
  product files; `PLAN.md` unmodified; no §4 (recording) or 3.5 scope.

### V2 (integration, real Chrome)

- [ ] **AC12.** New `sw-speech.js` harness (repo-path argv required):
  scripted fake `speechSynthesis` proving started → completed,
  started → cancel_requested → cancelled, started → error with raw
  name, the text-saving rule, and `speech_settings` once. All green.

### V3 (deferred)

- [ ] **AC13.** Live `speechSynthesis` callback behavior on the owner's

## 4. Non-goals

- §4 recording (microphone/screen/webcam) — untouched.
- 3.5 lifecycle events — untouched.
- Transcription, analysis, or evaluation of speech content.
- Changing any spoken text, voice, rate, or UX behavior.
- `playIllegalMoveSound` (non-speech audio).
