# Task 4.14 contract — report per-stream recording status

PLAN.md §4.14 (line 181): "Report each stream's status separately so
microphone, screen, or webcam failure cannot masquerade as complete
recording."

Status: CONTRACT ONLY. No implementation code written. PLAN.md unmodified.
STATE.json untouched (coordinator-owned).

## 0. What 4.14 is (one paragraph)

4.6–4.13 built the recording pipeline; every stage exposes its state
through a narrow read seam (`getActiveStreams()` / `getStreamRecord()`,
`getChunkState()`, the manifest, the track monitor's live tracks).
**4.14 is the read-only query surface over those seams.** It answers,
per streamKind, the single question PLAN.md poses: *is this stream's
recording actually happening, and if not, what is its condition?* — so
that a dead microphone, a failed screen capture, or a stalled chunk
loop can never masquerade as a complete recording. 4.14 writes
nothing, starts nothing, stops nothing, emits no events, and builds no
UI. It is a library module plus one deliberate channel message so that
§5 (session lifecycle / readiness gating) and §6.3 (media-sync.json
export), both SW-side, can query offscreen-local live state.

PLAN reading note (flagged for the section-4 auditor): PLAN says
"report each stream's status separately." 4.14 reports facts per
stream; it does **not** define which streams are "required" and does
not compute readiness — that policy is §5's (the 4.6 carry-forward
"show readiness only after required media streams have started" is
answered by §5 reading 4.14's per-kind lifecycle and applying its own
required-set policy).

## 1. The status shape

`getStreamStatus(streamKind)` returns exactly this shape (exact-keys
discipline; unknown is null):

```
{
  streamKind: 'microphone' | 'screen' | 'webcam',
  lifecycle: 'idle' | 'recording' | 'stopped' | 'finalized',
  recorderState: 'recording' | 'inactive' | 'paused' | null,
  segmentId: string | null,
  segmentNumber: number | null,
  startedAtUtc: string | null,
  startedAtMonotonicMs: number | null,
  clockSegmentId: string | null,
  actualMimeType: string | null,
  fileExtension: string | null,
  audioContent: string | null,   // screenAudioContent for screen,
                                 // micAudioContent for mic, null for webcam
  chunk: {
    status: string,              // chunk_writer poll status
    lastChunkIndex: number | null,
    lastWriteAtUtc: string | null,
    consecutiveMisses: number,
    emptyPolls: number,
    lastErrorName: string | null,
    lastErrorMessage: string | null
  } | null,
  tracks: [ { trackKind: 'audio'|'video', muted: boolean,
              readyState: string } ],   // live read; [] when no live stream
  lastRecorderError: { errorName, errorMessage, atUtc } | null,
  lastDiscontinuity: { reason, atUtc } | null,
  finalizedAtUtc: string | null,
  unfinalizedSegments: number     // unfinalized manifest segments,
                                  // this kind + session
}
```

`getAllStreamStatuses()` returns `{ microphone, screen, webcam }`.

### 1.1 Lifecycle derivation (truth table)

| Condition | lifecycle |
|---|---|
| No live registry entry AND no unfinalized manifest segment for this kind+session | `'idle'` |
| Live registry entry present | `'recording'` (even if `recorderState` is `'inactive'` transiently — the fact is reported, not smoothed) |
| No live entry BUT ≥1 unfinalized segment exists | `'stopped'` (dead generation, or stopped-not-finalized — abnormal, and visible as such) |
| No live entry AND latest segment `finalizedAtUtc` non-null | `'finalized'` |

The derivation is mechanical and V1-pinned. There is no `'error'`
lifecycle: error conditions are facts in `chunk.*`,
`lastRecorderError`, `lastDiscontinuity`, and `tracks[]`, not a
smoothed state. (Smoothing is how failures masquerade; 4.14 does not
smooth.)

### 1.2 The masquerade cases, and where each surfaces

| Failure | Surfaces in |
|---|---|
| Stream failed at start (4.6 stage failure) | No registry entry; `unfinalizedSegments: 0`; `lifecycle: 'idle'` — and the start-streams response (4.6) is the durable record. The status does not invent a segment. |
| Track ended mid-session | `tracks[].readyState: 'ended'` (live read); `lastDiscontinuity.reason: 'track-ended'` |
| Recorder platform error, recorder alive | `lastRecorderError` verbatim |
| Chunk loop stalled / quota / write error (recorder still "recording") | `chunk.status` terminal + `lastErrorName`; `lastDiscontinuity.reason` — **the** critical masquerade case, fully covered |
| Offscreen document died | No live entries; `lifecycle: 'stopped'`; `unfinalizedSegments > 0` — honestly abnormal |
| Clean Stop + finalize | `'finalized'` with `finalizedAtUtc` |

## 2. Read sources (all offscreen-local; no event-log dependency)

| Field | Source (existing seam unless noted) |
|---|---|
| `lifecycle`, `recorderState`, live `segmentId`, `startedAtUtc`, `startedAtMonotonicMs` | `stream_starter.getStreamRecord()` (in-memory registry) |
| `chunk.*` | `chunk_writer.getChunkState()` (in-memory poll state) |
| `tracks[]` | `track_monitor.getMonitoredTracks()` — live track objects; `muted`/`readyState` read at query time |
| `lastRecorderError`, `lastDiscontinuity` | **NEW additive** `track_monitor.getStreamHealth(streamKind)` — in-memory retention of the last observed recorder error and discontinuity per kind (this document generation only). The monitor already observes both; retaining the last observation is a query over observed state, not a new pipeline. |
| `segmentNumber`, `finalizedAtUtc`, `clockSegmentId`, `actualMimeType`, `fileExtension`, `audioContent`, `unfinalizedSegments` | `format_support.getManifestRecordsBySession()` (existing; no new index, no schema change) |
| `queriedAtUtc` | injected `nowUtcIso` |

Deliberate honesty boundary: 4.14 reads **offscreen-local state
only**. The SW-side event log (4.9's durable health timeline) is not
queried — no channel round-trip, no async fan-out. The event log
remains §6.3's durable source at export time; 4.14 is the live
complement. After a document restart the in-memory health mirror is
empty by construction; the manifest (`unfinalizedSegments`,
`finalizedAtUtc`) tells the cross-generation story.

## 3. Runtime design

### 3.1 New module: `stream_status.js`

DOM-free, dependency-free, repo module pattern (`BlindfoldSession`
guarded global, IIFE, `'use strict'`, Node shim). Fully injected read
surface:

`createStreamStatus({ getStreamRecord, getChunkState,
getMonitoredTracks, getStreamHealth, getManifestRecordsBySession,
nowUtcIso })` → `{ getStreamStatus(streamKind),
getAllStreamStatuses() }`.

Read-only by construction: the injected surface contains no writer,
and a V1 code-scan pin forbids write/emit/control vocabulary in the
module (`put(`, `add(`, `delete(`, `sendMessage`, `emitEvent`,
`new MediaRecorder`, `.start(`, `.stop(`, `requestData(` in executable
code).

Type discipline per repo convention: `TypeError` on wrong type/shape
(including malformed streamKind), `RangeError` on bad domain value.
Never throws into the channel handler — the recorder.js wiring wraps
it like the other best-effort queries.

### 3.2 One new channel message: `recorder-get-status`

`MSG_GET_STATUS = 'recorder-get-status'` (`MSG_*` 23→24, deliberate).
SW → offscreen query (the `recorder-get-formats` precedent); the
offscreen handler:

1. Guards `no-session` (4.6/4.7 precedent) — `{ ok:false,
   error:'no-session' }` when no session is set.
2. Builds `createStreamStatus(...)` with the live lazy getters and
   returns `{ ok:true, sessionId, queriedAtUtc, statuses:
   getAllStreamStatuses() }`.

No new event types. No manifest widening (`MANIFEST_KEYS` stays 18).
No schema change (`DB_VERSION` stays 2). `recorder.html` loads
`stream_status.js` (same pattern as the other offscreen modules).

### 3.3 Additive `track_monitor.getStreamHealth(streamKind)`

Returns `{ lastRecorderError: {errorName, errorMessage, atUtc} |
null, lastDiscontinuity: {reason, atUtc} | null }` for the kind, or
null when the kind was never monitored. Updated at the same
observation points that already emit the events (no new listeners,
no new emissions). Cleared on `detachStream`/`attachStream`
(generation-scoped, honest).

## 7. Honest limitations

- In-memory health (`lastRecorderError`, `lastDiscontinuity`,
  live `tracks[]`) is generation-scoped: a document restart clears
  it. Cross-generation truth comes from the manifest
  (`unfinalizedSegments`, `finalizedAtUtc`) and the SW-side event
  log (§6.3 reads both at export).
- `recorderState: 'inactive'` with `lifecycle: 'recording'` is a
  real transient (between `recorder.stop()` and registry discard);
  4.14 reports it, does not smooth it.
- A stream that failed at start has no segment and no status beyond
  `'idle'` + the 4.6 start-streams response — by design, not a gap.
