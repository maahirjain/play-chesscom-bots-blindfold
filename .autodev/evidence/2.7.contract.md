# Task 2.7 contract — page/context start and clean-end events; unclean-discontinuity marking

PLAN.md §2.7 (human-owned, quoted verbatim): "Record page/context start and
clean-end events; mark an unclean discontinuity when recovery detects a
missing end."

## 1. Scope and definitions

**Page context** = one content-script instance lifetime = one 1.3 "context
segment" (one page load on chess.com). Each has a clockSegmentId (its clock
anchor, emitted as a `clock_anchor` event). 2.7 adds *semantic* lifecycle
events on top of the 1.3 time primitive:

| eventType | emitter | meaning |
|---|---|---|
| `page_start` | content script, eager at session start | "this page context began" |
| `page_end_clean` | content script, on `pagehide` (best-effort) | "this page context ended cleanly" |
| `page_discontinuity` | service worker, on detection | "a prior page context had no clean end on record when a newer one started" |

**Recovery** = the moment a new page context starts and the SW observes the
session's prior lifecycle state. Detection runs on *every* committed
`page_start`, not only after SW restarts: after an SW restart the SW has no
memory, but the DB does, so the next `page_start` subsumes the restart case.
No eager SW-startup check is needed — without a new page_start there is no
new information (the SW cannot distinguish "prior context crashed" from
"prior context alive in another tab" at startup).

**The marker's honest meaning.** `page_discontinuity` asserts exactly: "when
page context N started, page context M (older) had no `page_end_clean` and
no prior discontinuity marker on record." It does NOT claim "M crashed":
- M may be alive in a concurrent tab (unknowable from the SW; documented).
- M's end event may have lost the `pagehide` delivery race (designed-for
  case; conservative bias — see §2).
- A late-arriving end does NOT retract the marker (history is append-only;
  markers are point-in-time assertions).

## 2. The 2.5 tension — resolved

2.5 decided: **no unload/pagehide flush** — draining the queue at unload
cannot be guaranteed. 2.7 does NOT reintroduce it:

- `page_end_clean` is a *single best-effort emit* through the normal sender
  pipeline (`emit()` is synchronous through queueing; the pump races
  delivery). No `flush()` call at `pagehide`. Ever.
- Its loss is a **designed-for case**: the detector's trigger IS "no end on
  record". The marker is conservative by design — it may flag a clean reload
  whose end lost the race, but it never hides a real gap. For raw-data
  collection, a spurious gap flag (researcher investigates) is strictly
  better than a hidden gap.
- `pagehide` with `event.persisted === true` (bfcache) skips emission — the
  context isn't ending.

## 3. Design

### 3.1 New module: `lifecycle.js`

Follows the module convention (dependency-free classic script → guarded
`BlindfoldSession` global → IIFE `'use strict'` → Node shim; `shared()`
resolved at call time; TypeError/RangeError/plain-Error conventions).

Loaded in **both** contexts: `manifest.json` content_scripts js gains
`'lifecycle.js'` after `'sender.js'`; `sw.js` importScripts gains
`'lifecycle.js'` last. No new permissions. No DB schema change.

**Constants** (each task owns its `*_EVENT_TYPE`s — `event_envelope.js`
untouched, per the 1.3 precedent):
- `BlindfoldSession.PAGE_START = 'page_start'`
- `BlindfoldSession.PAGE_END_CLEAN = 'page_end_clean'`
- `BlindfoldSession.PAGE_DISCONTINUITY = 'page_discontinuity'`

**Validators** (strict, 1.x convention — extra keys rejected):
- `requireValidPageStartPayload(p)`: exactly `{}`.
- `requireValidPageEndPayload(p)`: exactly `{reason: 'pagehide'}`.
- `requireValidDiscontinuityPayload(p)`: exactly
  `{orphanedSegmentId, newSegmentId}`, both uuid-v4.
- `requireValidDiscontinuityRefs(r)`: exactly `{orphanedStartEventId}`,
  uuid-v4.

**Content-side emission** (thin wrappers over an injected sender):
- `emitPageStart(sender, sessionId)` → `sender.emit({eventType:
  PAGE_START, sessionId, gameId: null, payload: {}})`. gameId is null:
  page lifecycle is session-scoped. Eager — callable before any
  observation (unlike the lazy clock_anchor). Validates sender (object
  with `emit` function) and sessionId (uuid-v4); TypeError otherwise.
  Returns the envelope.
- `emitPageEndClean(sender, sessionId)` → same shape with
  `PAGE_END_CLEAN` and payload `{reason: 'pagehide'}`.
- `installPageEndHook(sender)`: no-op when `window` is undefined
  (SW/Node-safe). Otherwise registers one `pagehide` listener: skips when
  `e.persisted`, emits iff `BlindfoldSession.activeSessionId` is a
  non-empty string, never throws, never calls `flush()`.
- `BlindfoldSession.activeSessionId = null` — the §5 seam. §5 sets it at
  Start and clears it at Stop. Until §5 exists the hook is inert.

**SW-side detection**:
- `afterEventStored(event, ack)` — the consumer side of the writer's
  generic hook (§3.3). Returns `undefined` unless the event is a
  `page_start` with `ack.ok === true`; otherwise returns the
  `notePageStartStored(event)` promise. Never throws synchronously.
- `notePageStartStored(pageStartEvent)` → `Promise<void>`. Defensive
  validation first (malformed → resolved, never thrown). Then, **serialized
  per session** (promise chain per sessionId — concurrent page_starts for
  one session must not double-mark; the chain also dedups SW-anchor
  creation):
  1. `getAll('events', {index: 'bySessionId', lower: sid, upper: sid})`.
  2. Partition: `clock_anchor` → segmentId→utcEpochMs map;
     `page_end_clean` → ended segmentIds; `page_discontinuity` →
     already-marked orphan start eventIds; `page_start` → candidate list.
  3. Orphans = starts where `segmentId !== newSegmentId`, no end, no
     marker, AND (temporal guard) the orphan's anchor time is missing or
     strictly less than the new segment's anchor time. The temporal guard
     handles out-of-order arrival (a delayed older start must not flag a
     newer live segment); missing anchors fall back to flagging
     (conservative; a missing anchor is itself evidence of an unhealthy
     pipeline — anchors always precede page_start via the sender's
     stop-and-wait discipline).
  4. If no orphans → done (and no SW anchor is created — lazy means lazy).
  5. `ensureSwAnchor(sessionId)`: per-(SW-instance, session) clock anchor.
     If absent, `captureClockAnchor()` + `createAnchorEvent({sessionId,
     sourceContext: 'service_worker', sourceSeq: 0, anchor})` + write it
     via `BlindfoldSession.writeEvent`. Anchor-write failure → reject
     (no dishonest timestamp; the next page_start retries — self-healing).
     In-memory only: a new SW instance legitimately captures a new anchor
     (1.3 segment model — this is NOT 2.6's "no in-memory restore"
     violation; there is no durable state to restore, only segment-scoped
     identity).
  6. For each orphan, `createEvent({eventType: PAGE_DISCONTINUITY,
     sessionId, gameId: null, sourceContext: 'service_worker', sourceSeq:
     nextSwSeq(sessionId) (1, 2, …), clockSegmentId: anchor.segmentId,
     monotonicMs: performance.now() at creation, payload:
     {orphanedSegmentId, newSegmentId}, refs: {orphanedStartEventId}})`,
     validated by the §3.1 validators at construction, written via
     `BlindfoldSession.writeEvent`. Write failure → reject (self-heals
     next time). **No raw IDB writes to `events`/`sequence_state` from
     lifecycle.js** — the writer stays the sole writer (2.4/2.6 binding
     invariant); lifecycle.js is a *client* of `writeEvent`.

### 3.2 `writer.js` change — one generic hook

In the onMessage listener's ack path, after `sendResponse(ack)`:

```js
// 2.7: generic post-commit hook. Type-agnostic: the writer never
// inspects event types here. lifecycle.js consumes it for
// page_start → discontinuity detection. Fire-and-forget; hook
// failures must not break the ack path.
try {
  var nsHook = shared();
  if (nsHook && typeof nsHook.afterEventStored === 'function') {
    nsHook.afterEventStored(message.event, ack);
  }
} catch (hookErr) { /* never break the ack path */ }
```

Only when `ack` was produced (any ack — the hook itself filters on
`ok`). The hook runs after commit (acks come from `tx.oncomplete`), so
detection always sees the stored start.

### 3.3 `content.js` change — one line

After the sender-instantiation line:
```js
BlindfoldSession.installPageEndHook(BlindfoldSession.sender);
```

### 3.4 What 2.7 does NOT do

- No `page_start` emission wiring in content.js (no session exists at page
  load; §5 calls `emitPageStart` at Start and on page load during an
  active session).
- No SW start/end events (SW lifetime is 2.6's restore domain).
- No retraction of markers; no end-event backfill.
- No URL/focus/visibility recording (3.5.1's domain).
- No status UI (2.8); no retention/export changes (2.9/§6 — export passes
  markers through as ordinary events).

## 6. Notes for reviewer (stress-test these)

- **The marker's false-positive surface**: concurrent tabs, lost
  pagehide race, late end arrival. The contract claims conservative
  honesty, not crash detection. Is the documentation sufficient for the
  researcher's later interpretation?
- **The writer hook**: is the generic `afterEventStored` the right seam,
  or should lifecycle.js have its own listener? (Ordering with commit
  is the constraint — the hook fires post-`tx.oncomplete`.)
- **Temporal guard**: does comparing anchor `utcEpochMs` values
  correctly handle the out-of-order case without introducing clock-skew
  hazards? (Same-machine `Date.now()` at anchor capture; strict `<`.)
- **Per-session serialization**: is the promise chain sufficient to
  prevent double-marking under concurrent page_starts, given IDB
  transaction serialization?
- **SW anchor laziness**: the first discontinuity for a session in an SW
  instance writes a clock_anchor with sourceSeq 0 — is the (SW instance,
  session) segment model a faithful application of 1.3?
- **Deviation from the 2.6 contract's downstream note**: 2.6 anticipated
  2.7 using `restoreSessionState`/`getSequenceState` for detection; this
  design queries the events store instead, because lifecycle state lives
  in the event stream, not the 2.6 triple. The triple is untouched.
- **content.js `window` reference**: content scripts always have
  `window`; the guard is for Node-load safety. Acceptable?
- **Test isolation**: lifecycle.js holds per-SW-instance module state
  (`swAnchors`, chains); V1 tests must use unique sessionIds per test
  rather than a test-only reset API. Sound?
