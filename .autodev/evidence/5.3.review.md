## Adversarial focus areas

1. **No-silent-change invariant — all four mechanisms hold mechanically.**
   (a) Write-once: `session_fields.js:294-300` — `setSelection` returns early
   when `!enabled`; verified by direct read. (b) No record-write path: my own
   comment-stripped scan found zero forbidden tokens (AC5 above). (c) Capture
   reads the live form at Start: `selection` is bound from
   `fieldsHandle.getSelection()` at `session_controls.js:652`, before the
   no-category abort; `capture` fires only at the post-`session-save` success
   point — the same values the record path persisted. (d) No load-past-session
   path: `selection_memory.js` exposes no API that reads IDB or the recorder
   channel. **Boot-adoption race:** both orderings are safe — adoption first
   → `setSelection` no-ops (disabled); restore first → adoption's
   `showAdoptedCategory` writes `select.value` directly (bypassing
   `setSelection`) and disables, overriding the remembered values. Adopted
   truth wins either way; a remembered default can never masquerade as the
   adopted session's category. Verified by direct trace of both paths.
2. **capture swallows storage failures — honest, not a defect.** The failure
   affects only a convenience preference *after* the session was recorded
   successfully; the user always sees the values they actually typed
   (in-place form values are correct). Worst case is a blank form next time —
   degraded convenience, never a false record or a false display. Documented
   in the contract (§7) and the code comments; pinned by V1 tests.
3. **chrome.storage.local unavailable — real degradation path.**
   `content.js` throws `TypeError` when the API is absent; the surrounding
   install try/catch absorbs it; `selectionMemory` stays null; the
   `onSessionStarted` closure guards `selectionMemory !== null`. Recording
   proceeds with no remembered defaults. Verified in the diff.
4. **onSessionStarted exactly-once — verified** (see AC7 above). No abort
   path reaches the firing point; the try/catch contains the callback, so a
   throwing callback cannot break Start.
5. **validateRememberedSelection totality — verified by branch reading.**
   Handles null/undefined/arrays/functions/primitives (→ null); unknown
   categories (→ null, whole value); `{}` → clean blanks (a legitimate
   restore of empty fields, effectively a no-op). Corrupt values are
   discarded, never used.
6. **Changed-files discipline — verified.** Non-test, non-evidence changes:
   `selection_memory.js` (new), `session_controls.js`, `content.js`,
   `manifest.json`, `.autodev/DECISIONS.md` — each diff matches the contract's
   allowed list exactly; everything else byte-identical; PLAN.md unmodified.
7. **Boundaries — verified.** Only the three 5.2 fields are remembered; the
   storage key appears in `selection_memory.js` only (production code); no
   `chrome.storage.sync` anywhere outside tests; no export path reads the key
   (§6 does not exist yet, and the contract explicitly excludes remembered
   prefs from export).

## NOTEs (informational only)

1. **V2 awaits the behavioral verifier's independent Chrome re-run**
   (`sw-selection-memory.js` 45/45 was builder-run). AC8–AC10 are
   provisionally accepted on the builder's evidence.
2. **Known contract NOTE (§3):** after an adopted session stops and the page
   reloads, cold-boot restore may lag one session — adopted sessions are never
   captured. The in-place form values are always correct; only the cold-boot
   restore can be stale in this path. Honestly documented, not a defect.
3. **No clear-remembered-defaults UI** is a deliberate non-goal (contract §9);
   recorded as a §5 follow-up if the owner wants it (one-line
   `storage.remove`). The fields remain editable pre-session, so the user is
   never trapped in a stale default.
4. **Pre-existing design edges carried forward:** the `emitPageStart`-throw
   orphan edge and best-effort `clearRecorderSession` (5.2) are unchanged by
   5.3 and remain documented where they belong.

## Why APPROVE

Every AC holds under independent trace or independent V1 re-run (1213/1213).
The dangerous direction — defaults flowing into a recorded session's
metadata/conditions — is blocked by four independent, mechanically verified
mechanisms, and the boot-adoption race is safe in both orderings. The
implementation adds exactly what PLAN §5.3 asks (remember previous selections)
and nothing it forbids (no record-path changes, no new messages/events, no
gameplay change, no PLAN modification). No defect was found that would fail an
acceptance criterion.
