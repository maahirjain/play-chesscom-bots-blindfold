## What was built

**`capture_selection.js` (new)** — DOM-free `createCaptureSelector(opts)` factory
(house convention: dependency-free → guarded `BlindfoldSession` global →
IIFE `'use strict'` → Node shim). Injected `localStorage`-shaped `storage`,
`broker` (SW-leg capture broker client), `emitEvent`, `getSessionId`/`getGameId`
thunks, clock, `getUserMedia` thunk.

- `listModes()` → `{ok, modes:[{mode:'tab'|'screen', available, targetTab, permissionState}]}`;
  tab mode carries the SW-resolved `targetTab` (`{tabId, tabTitle}`) or
  `tabId:null` when no chess.com game tab exists — honest, no active-tab
  fallback.
- `select(captureMode)` → `captureMode ∈ {'tab','screen'}` (else `RangeError`,
  channel maps to `{ok:false, error:'unknown-mode'}`); **persists
  `blindfold.captureMode.v1` to document localStorage (4.2 precedent) BEFORE
  the live selection takes effect** (4.2 SF-1); emits
  `screen_capture_selected` with `source:'user'`. Works pre-session as a
  setting; only the event is inert (3.x precedent). Never silently defaults.
- `requestPermission({captureMode})` → **tab mode probe**: broker
  `getStreamId(tabId)` → `getUserMedia` with `chromeMediaSource`
  constraints (`chromeMediaSource:'tab'`, `chromeMediaSourceId: streamId`);
  **every probe track is stopped before resolving — probe-then-stop, no
  retention** (4.2 precedent; 4.6 re-acquires at Start; `audioIncluded` flag
  exposed for 4.7's feed). `NotAllowedError`/`SecurityError` → `'denied'`;
  `NotFoundError`/`OverconstrainedError` → selection invalidated;
  else `'unknown'` with the raw `errorName`. Concurrent probes share the
  in-flight request (contract §6.5, builder's choice — documented).
  **Screen mode never calls media**: returns `{ok:true,
  permissionState:'prompt', note:'picker-at-start'}` — the OS picker appears
  at Start; denial is a state, not an exception.
- `getState()` → `{ok, captureMode, tabId, permissionState}` (the queryable
  state 4.14/5.6 read).
- `restoreOnBoot()` → reads `blindfold.captureMode.v1`; valid mode → restored
  (`source:'restored'`, tab id re-resolved, never persisted); invalid →
  stays `null`, no event, no silent default.
- Two 4.3-owned event types with exact-keys validators (exported;
  `event_envelope.js` untouched): `screen_capture_permission_changed`
  `{captureMode, permissionState, source:'query'|'request', errorName}` and
  `screen_capture_selected` `{captureMode, tabId, source}`.

**`capture_broker.js` (new)** — SW-side `createCaptureBroker(chromeNs)`
factory (the chrome.* split: offscreen docs expose only `chrome.runtime`,
verified live in V2). All `chrome.*` calls live here:
`resolveTargetTab()` (most-recently-active `https://www.chess.com/play/computer*`
tab via `lastAccessed`; active-tab then first-match fallbacks),
`queryCapturePermission()` (`permissions.contains({permissions:['tabCapture']})`
→ granted/denied), `getStreamId(tabId)`
(`chrome.tabCapture.getMediaStreamId({targetTabId})`; absent API → plain
`Error`, never a weak fallback).

**`recorder.js` (+`recorder.html`)** — instantiates the selector with the
broker client; routes the four channel messages
(`capture-list-modes`, `capture-select`, `capture-request-permission`,
`capture-get-state`) on 4.1's `{kind:'recorder', msg, v:1}` envelope with
failure isolation (every handler answers `{ok:false, error}`, never throws).
Broker client sends the three SW-leg messages
(`capture-resolve-tab`, `capture-query-permission`, `capture-get-stream-id`)
to the SW. Session-gated event emitter reused (4.2's recorder-set-session);
boot-restore wiring announces the restored selection once per session.

**`recording_host.js`** — builds the broker from the shared chrome namespace
and routes the three SW-leg messages with async `{ok}` responses;
`broker-unavailable` when the module is absent; `getCaptureBroker()` exposed
for tests.

**`sw.js`** — `importScripts` gains `capture_broker.js`; the "intentionally
absent" header comment updated (4.4–4.14).

**`manifest.json`** — surgically edited (original formatting preserved):
`permissions: ["offscreen", "tabCapture"]` + `"host_permissions":
["https://www.chess.com/*"]`. V2 verified which is required (see below).

## Deviations and chrome.* split findings (empirical, not assumed)

1. **The split is verified live.** Via CDP `Runtime.evaluate` inside the real
   `recorder.html` target: `chrome.runtime` present; `chrome.tabs`,
   `chrome.tabCapture`, `chrome.permissions` **all absent**. The SW side
   exposes `chrome.tabs` + `chrome.tabCapture`. The SW-broker split is not a
   precaution — it is required.
2. **Manifest requirement answered**: `permissions.contains({permissions:
   ['tabCapture']})` reports `'granted'` (install-time grant effective);
   `host_permissions: ["https://www.chess.com/*"]` is what lets
   `chrome.tabs.query({url})` see the game tab (SW leg resolved a real tabId).
   Both entries are required and both are kept.
3. **Tab probe outcome (observed, not fabricated)**: `getMediaStreamId`
   fails in headless Chrome with `"Extension has not been invoked for the
   current page (see activeTab permission). Chrome pages cannot be captured."`
   — headless has no toolbar invocation, so tab capture is refused. The probe
   honestly reports `{ok:true, permissionState:'unknown', errorName:'Error'}`;
   denial-as-state is preserved, nothing throws. **This is not the declared
   BLOCKER**: the doc-leg API surface was separately proven — a
   `getUserMedia` call with `chromeMediaSource:'tab'` constraints and a bogus
   streamId inside the offscreen document returns `AbortError: "Error
   starting tab capture"`, i.e. Chrome recognizes the constraint format and
   attempts tab capture; only the (bogus) id is rejected. With a valid
   streamId the call would proceed. No workaround was fabricated.
4. **Sandbox network note**: chess.com itself would not load in the test
   sandbox (`ERR_TUNNEL_CONNECTION_FAILED`), but the tab still existed with
   the target URL, so tab resolution and targeting were genuinely exercised.
5. `offscreenTarget.page()` does not attach to offscreen documents in this
   Puppeteer version; the harness uses `target.createCDPSession()` +
   `Runtime.evaluate` instead (recorded for future V2 harnesses).
