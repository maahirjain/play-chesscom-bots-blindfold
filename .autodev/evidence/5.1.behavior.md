## Behavioral honesty checks (traced against real code)

### (a) The 7-state classifier is mechanical — no smoothing

`session_controls.js` `classifyStreamStatus(status, startResult)` (lines 156–226):
- The closed 7-state set is derived mechanically from `lifecycle` + the closed
  adverse-facts list (`chunk:chunk-stalled|chunk-quota-exceeded|chunk-write-error`,
  `recorder-error:*`, `discontinuity:*`, `track:ended|muted(*)`).
- **The masquerade case**: chunk-stalled with `recorderState === 'recording'`
  keeps `lifecycle === 'recording'` and lands on `recording-degraded` (amber)
  via `facts.length > 0` — never `recording-healthy`. No adverse fact can
  yield `recording-healthy` (verified: the only path to `recording-healthy`
  requires `facts.length === 0`).
- Inconsistent input (recording + `finalizedAtUtc` set) fails safe to
  `recording-degraded` with the inconsistency itself appended as a fact.
- Unknown lifecycle string → `unknown` (never green). Malformed status →
  `TypeError` (caller error); malformed *fields* are absent evidence, not a
  crash (poll-safe). Missing kinds in the response render `unknown`, never idle.
- The `startResult` parameter (builder deviation #2) closes the
  denied-screen-masquerading-as-`off-idle` hole: a failed start with lifecycle
  `idle` → `failed-not-started` with `start-failed:<reason>` as a raw fact. It
  adds no smoothing path — it only injects a fact.

### (b) Start sequence order — matches contract §3.3

`onStartClick` (lines 443–560): local interlock (phase !== idle → return) →
`BS.newSessionId()`/`BS.newGameId()` (UUID-v4, session_identity.js) →
`recorder-ensure` (SW-side) → `recorder-set-session` → `recorder-start-streams`
→ `setSlots` + `BS.emitPageStart` + `pollOnce` + `schedulePoll`.
- Start aborts only on channel-level failure: ensure `{ok:false}`/no-response
  (aborts without recorder-side clear — nothing minted yet), set-session
  failure, or start-streams with **no `streams` object** (guard rejections).
  Per-stream failures inside `startResp.streams` do NOT abort Start (4.6
  isolation) — V2 proved it: screen failed, mic+webcam recording, session active.
- `resetEnded()` re-arms the 3.5.4 seam after set-session.

### (c) Stop sequence — matches contract §3.4

`onStopClick` (lines 563–668): `recordStopTermination(reason, result)` via the
3.5.4 seam (null reason unless `getLastObservedEnd()` observed a game ending —
