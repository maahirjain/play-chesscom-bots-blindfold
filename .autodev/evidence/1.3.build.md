## Contract deviations (with justification)

1. **Error class for malformed IDs.** Contract §2.10 lists "non-uuid IDs"
   under `RangeError`, but AC5 and AC15 state explicitly that
   missing/non-uuid `sessionId`/`clockSegmentId` → `TypeError`. The concrete
   acceptance criteria took precedence: missing or malformed IDs (including
   non-uuid strings) → `TypeError` everywhere (eventId, sessionId, gameId,
   clockSegmentId, anchor.segmentId, refs values), matching the 1.1 precedent
   (`'gameId must be a uuid-v4 string'` → `TypeError`). `RangeError` is
   reserved for domain violations of non-ID fields: event-type syntax
   (AC3), sourceContext (AC6), negative/non-integer sequences (AC7/AC16),
   negative/NaN/Infinity monotonicMs (AC13), bad refs role names (AC19).
2. **`deriveWallUtcMs` input validation.** Contract table gives only the
   formula. Added `TypeError`/`RangeError` validation of both inputs per the
   general error conventions (wrong type → `TypeError`; negative/NaN/Infinity
   monotonicMs → `RangeError`). Pure formula unchanged; anchor's own
   `monotonicMs` returns exactly `anchor.utcEpochMs`.
