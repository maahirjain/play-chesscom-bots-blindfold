## Key findings

**Event vocabulary (from sounds.js source):**
- `utterance_started` (requires valid link + active session/game)
- `utterance_ended` with `outcome: 'completed' | 'cancelled' | 'error'`
- `utterance_cancel_requested` (for each in-flight utterance on cancel)
- `CANCEL_SOURCES: ['user', 'interrupt-replace']`

**Link requirement:** The tracker only emits `utterance_started` when the
link is valid (`trigger: 'help-request'` or `'move'`) AND the session/game
are active. This is the 3.4 "inertness" design — unlinked utterances are
not recorded.

**No defects found.** The three-way outcome distinction (`completed` vs
`cancelled` vs `error`) is structurally enforced by the `UTTERANCE_END_OUTCOMES`
validator. All three acceptance tests pass.
