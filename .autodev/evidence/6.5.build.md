## What was built

**`nameSegmentFiles({manifestRecords})`** (sync, pure) in `exporter.js`:

- Assigns a deterministic export filename to every manifest segment:
  `{streamKind}-{NNN}{ext}` (e.g. `microphone-001.webm`).
- Returns `{files: [{segmentId, filename, streamKind, segmentNumber}], bySegmentId}`.
  `segmentNumber` in the output is the EFFECTIVE number (real or on-the-fly).
  `bySegmentId` feeds 6.3's `segmentFiles` input and 6.6's ZIP entry names.
- **Numbering (contract §3.3):** 4.13's `segmentNumber` used verbatim where
  present; nulls get the smallest unused positive integers in 6.3's
  deterministic sort order (reuses `compareSegments`: kind → segmentNumber
  nulls-last → createdAtUtc → segmentId). All-null → chronological 1..N;
  mixed → gap-filling. Per streamKind. On-the-fly numbers are export-time
  labels only — never persisted (readonly rule).
- **Extension resolution (contract §3.4):** manifest `fileExtension` (must
  start with `.`) → derive from `actualMimeType` via the format_support
  mapping (mirrored locally; exporter.js stays dependency-free):
  `video/webm*`|`audio/webm*` → `.webm`; `video/mp4*` → `.mp4`;
  `audio/mp4*` → `.m4a`. Both unusable → `TypeError` naming the segmentId.
- **Fail-closed:** non-array, missing/empty `segmentId`, duplicate
  `segmentId`, non-positive `segmentNumber` → `TypeError`.

## Builder judgments (documented deviations)

1. **Duplicate finalized `segmentNumber` within a kind → TypeError.**
   The contract's validation (§3.1) requires positive integers but does not
   explicitly forbid duplicates. However, 4.13 assigns unique 1-based numbers
   per kind, and the numbering rule's core guarantee is "never collides,
   never reuses". Two segments with the same finalized number would produce
   identical filenames (a ZIP collision). Fail-closed is the honest response
   to this corrupt data, consistent with the 2.6 corruption-honesty precedent.

2. **`fileExtension` without a leading dot** is treated as unusable (falls
   through to mime derivation) rather than used verbatim. A bare `"webm"`
   would produce `microphone-001webm`; the manifest schema specifies the
   leading dot.
