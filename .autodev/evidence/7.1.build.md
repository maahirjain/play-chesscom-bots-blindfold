### Key vocabulary finding (verified in source, pinned by test)

- `submitAttempt` (chess_utils.js) throws `RangeError` unless `validation` is
  exactly `'legal'` or `'illegal'`. There is **no `'ambiguous'` outcome**.
- `content.js` computes `legal = isMoveLegal(game, move)` where `isMoveLegal`
  = `(new Chess(game.fen()).move(move) != null)`.
- An ambiguous SAN (e.g. `'Nd2'` with knights on b1/f1) makes chess.js return
  `null`, so it records as `validation: 'illegal'` with the submitted text
  verbatim.
- Analysts distinguish ambiguity (well-formed SAN like `'Nd2'`) from
  malformation (like `'Qxe9'`, no queen exists) by the text itself.

### Tests

1. **7.1 AC1** — Ambiguous `'Nd2'` (FEN `4k3/8/8/8/8/5N2/8/RN2K3 w - - 0 1`,
   knights on b1/f3, d2 empty) records as `validation: 'illegal'`, never
   `'legal'`, with `submittedText: 'Nd2'` verbatim. Fixture sanity: chess.js
   returns null for `'Nd2'`, accepts `'Nbd2'` and `'Nfd2'`.
2. **7.1 AC1b** — Disambiguated `'Nbd2'` records as `validation: 'legal'`.
3. **7.1 AC2** — Repeated `'e4'` submission yields two `move_attempt` events
   with distinct `eventId`s, identical `submittedText`, both `'legal'`.
4. **7.1 AC3** — Four-way acceptance: `Nbd2` (legal) → `Qxe9` (rejected) →
   `Nd2` (ambiguous) → `Nbd2` (repeated). Validations are
   `['legal','illegal','illegal','legal']`; texts are verbatim; all 4 IDs
   distinct. An analyst can distinguish all four kinds from the records alone.
5. **7.1 AC4** — Submission path never emits `move_confirmed` (legal, illegal,
   and ambiguous submissions produce zero `move_confirmed` events).
6. **7.1 vocabulary** — `submitAttempt` with `validation: 'ambiguous'` throws
   `RangeError`, pinning that the vocabulary has no ambiguous outcome.

The test helper `submitLikeContentJs` faithfully replicates content.js's submit
path (`isMoveLegal` via chess.js → `'legal'`/`'illegal'`). `normalizeMove` and
`isMoveLegal` are not exported from chess_utils.js (browser global scope), so
replication via chess.js is the faithful approach.
