## The key judgment: "finalize ≠ file" is faithful, not a weakening

The focus brief quoted PLAN §4.13 as "concatenate chunks into numbered
files" — **that quote does not match PLAN.md's actual text.** What PLAN
actually says (line 179):

> 4.13. Finalize available chunks on Stop; keep discontinuous or
> restarted recordings as separate numbered segments.

And PLAN assigns file assembly elsewhere (lines 213, 215):

> 6.4. Assemble stored chunks into original-format microphone, screen,
> and webcam files without unnecessary transcoding.
> 6.5. Use numbered files for interrupted recordings and list every
> segment in media-sync.json.

PLAN's own division of labor is: 4.13 numbers **segments** (manifest
`segmentNumber`); 6.4 assembles **files**; 6.5 defines numbered
**filenames**. The contract's reading (4.13 stops/splits/numbers/marks;
§6 consumes) is not an interpretation at all — it is PLAN's literal
text. There is nothing to weaken: the alleged tension was a misquote.
The contract's §0.1 reading notes are consistent with this and are
flagged for the section-4 auditor as designed.

## Per-AC scrutiny

- **AC1 — stop sequence.** Traced `finalizer.js` end to end; the
  11-step order is exactly as contracted: guards (`no-session`,
  `start-in-progress`) before any device/media action (`runStop`);
  snapshot → stop marker iff active streams (marker failure →
  `markerId:null`, try/catch) → `sleep(STOP_MARKER_WAIT_MS)` once,
  globally → `chunkWriter.stopForStream` per stream →
  `recorder.stop()` per stream (skipped when not `'recording'`;
  `InvalidStateError` race → skip) → `awaitFinalFlush` → monitor
  detach **before** track stop → per-track `track.stop()` →
  `starter.discardActiveStream` → finalize pass → response. The
  1000 ms wait wraps steps 4–11, so it precedes **every**
  `recorder.stop()`. Detach-before-stop is in the same promise chain
  (`step 7` block precedes `step 8` block), so a clean Stop emits no
  spurious `track-ended` discontinuities. Verified by direct read.
- **AC2 — finalized marker.** `MANIFEST_KEYS` is exactly 18 with the
  `// 4.13-owned:` comments (`format_support.js:115-117`); validators
  for `segmentNumber` (null-or-positive-integer) and `finalizedAtUtc`
  (null-or-ISO-string) present; exact-keys still rejects a 19th key
  (V1-pinned in `tests/finalizer.test.js`). `recorder.js:1070` sets
  `MANIFEST_FINALIZED_FIELD = 'finalizedAtUtc'`, and 4.9's
  `isManifestRecordFinalized` (`recorder.js:1071-1074`) excludes
  finalized records with **no other 4.9 change** — the reservation
  design worked as intended (traced `checkRestartSuperseded`).
- **AC3 — numbering.** `assignNumbersAndMark` sorts per
  `(sessionId, streamKind)` by `(createdAtUtc, segmentId)` with a
  lexicographic `segmentId` tie-break — deterministic even for
  identical timestamps. 1-based. Idempotent: the finalize pass only
  processes `getUnfinalizedRecords`, so already-finalized records
  keep their numbers; re-finalize never renumbers. Restart
  generations sort chronologically (old `createdAtUtc` = lower
  numbers); split post-gap pieces get finalize-time `createdAtUtc`
  and sort after the pre-gap piece.
- **AC4 — splits.** `maybeSplitSegment` + `splitAtGap` implement the
  contracted rule: non-`'restart'` discontinuity events with finite
  `lastChunkIndex`, split iff `maxIdx > lastChunkIndex` (media on
  both sides); `'restart'` skipped by explicit filter. New uuid-v4
  ID; post-gap chunks re-keyed 0-based; new piece record cloned from
  the **original** template per contract §4 ("clone the original's
  4.5/4.6/4.7 fields" — stream-identity fields are unchanged across
  pieces, so this is correct, not a bug) with fresh
  `segmentId`/`createdAtUtc` and a fresh `clockSegmentId` via 4.10's
  `linkClockSegment` (linker failure → `null`, never a finalize
  failure — `linkPiece`). Multi-gap: sequential splits with
  original-coordinate base tracking (`base = gap + 1`), local
  coordinates converted correctly. Split failure → best-effort
  unsplit (rejection swallowed in the chain; gap stays flagged).
  The atomic transaction (`runSplitTransaction`) performs all
  deletes+puts+piece-put in a **single** readwrite transaction over
  `['media_chunks', 'recording_manifest']` with `oncomplete` /
  `onerror` / `onabort` handling — genuinely atomic on the write
  set. (Reads are computed beforehand via the db wrapper; there is
  no concurrent writer in this architecture — single offscreen
  document — so no staleness vector. NOTE 4.)
- **AC5 — final-flush await.** `awaitFinalFlush` polls
  `recorder.state` → `'inactive'` (100 ms cadence, ≤5000 ms) — **not**
  chunk indexes, as contracted (0-byte flushes are legitimately
  index-less) — then a 1000 ms write grace. Timeout →
  `flushTimedOut:true` set per stream in the response, finalize
  proceeds with available chunks. An unreadable `recorder.state`
  counts as not-inactive (unknown-is-unknown) and reports honestly
  via the timeout path. Constants are named and V1-pinned.
- **AC6 — idempotency + failure isolation.** Double Stop with no
  active streams and no unfinalized records →
  `{ok:true, streams:{}, note:'nothing-to-finalize'}` exactly
  (`finalizeOrphans`). Crash recovery: no active streams + unfinalized
  orphans → finalize pass with **no marker** (no recorders exist to
  capture one) → `finalized-orphans`. `start-in-progress` → guarded
  `{ok:false, error:'start-in-progress'}`. Per-stream failures
  (`failedKinds`) are excluded from the finalize pass and retried by
  a later Stop.
- **AC7 — vocabulary and file discipline.** Exactly one new channel
  message: `MSG_STOP_STREAMS = 'recorder-stop-streams'`
  (`recorder.js:146`); 23 `var MSG_` declarations counted (22→23).
  No new event types (durable trace = manifest mark + 4.11 stop
  `sync_marker` events). `DB_VERSION` stays 2; no new store/index.
  `finalizer.js` references no media-capture APIs (only injected
  recorder/stream handles — the 4.1 boundary holds). Content scripts
  byte-identical (V1-pinned). No gameplay change. PLAN.md
  unmodified. No §6 bleed: no `new Blob(` assembly, no ZIP, no
  downloads/OPFS writes (V1 code-scan pinned).
- **AC8 — changed-files discipline.** The enforced V1 pin
  (`tests/finalizer.test.js:995-1030`) allowlists exactly the 4.13
  files with justification comments and passes. See NOTE 1 on the
  contract prose list.
- **AC9/AC10 — V2.** Build report claims `sw-stop.js` 54/54 plus
  regressions (sw-chunks 42/42, sw-streams 57/57, sw-track-monitor
  46/46, sw-sync-marker 43/43). The harness header (`sw-stop.js:30-34`)

- **AC11 — V3 deferred** to §7/owner device per contract (stop

## NOTEs (informational; none fails an AC)

1. **Contract-text inconsistency (builder-flagged):** AC8's prose file
   list omits `format_support.js`, but AC2 requires the 16→18
   widening that lives there. The *enforced* V1 allowlist includes
   `format_support.js` with a justification comment and passes, so
   this is documentation-only. Recommended mechanical repair:
   add `format_support.js` (16→18 widening) to AC8's list, or a
   one-line erratum in the contract. Coordinator's discretion; the
   section-4 auditor should note it.
2. **Response shape additive field:** failed-kind entries carry
   `errorName` in addition to the contract §8 shape's
   `{ok, error, stage, segments}`. Channel responses are not
   exact-keys records; this is additive data, not a defect.
3. **`flushTimedOut` is response-only, not persisted.** Per contract
   §5's design the timeout is recorded in the channel response; §5
   (the caller) and 4.14 decide whether to persist it. The manifest
   carries no flush-timeout field. Forward note for §5/4.14, not a
   4.13 defect.
4. **Split atomicity scope:** the write set (deletes + re-keyed puts
   + piece record) is atomic in one transaction; the chunk list is
   read beforehand. Safe because there is exactly one writer (the
   offscreen document); no concurrent-mutation vector exists in
   this architecture.
5. **Multi-gap template reuse:** every piece in a multi-gap chain is
   cloned from the *original* record (contract §4's wording), not
   from the preceding piece. Correct, because all cloned fields are
   stream-identity fields unchanged across pieces; `createdAtUtc`
   and `clockSegmentId` are fresh per piece.
6. **Mid-segment split is V1-pinned only.** Post-gap media with a
   surviving recorder is not forceable headless; 36 unit tests with
   a faithful fake IDB cover the logic. Honestly documented in the
   build report and harness header. §7/AC11 item.
7. **Correction for the record:** the review brief's quotation of
   PLAN §4.13 as "concatenate chunks into numbered files" does not
   match PLAN.md's actual text ("separate numbered segments";
   files are 6.4/6.5). The contract's reading needed no
   interpretive charity — it follows PLAN literally.

## Conclusion

Task 4.13 is **APPROVED**. The implementation traces exactly to the
contract on all 11 ACs: the 11-step stop sequence is ordered as
specified (detach-before-stop, once-globally marker wait), the flush
await is bounded and honest, splits are atomic and correctly scoped,
numbering is deterministic and idempotent, crash recovery and double
Stop behave as contracted, and the finalized marker completes 4.9's
reserved design with no other 4.9 change. The "finalize ≠ file"
reading is not a weakening — it is PLAN.md's own division of labor
(4.13 = numbered segments; 6.4/6.5 = files). No blockers, no
SHOULD_FIX. The seven NOTEs are documentation polish or forward
notes for §5/4.14/§7 and the section-4 auditor.
