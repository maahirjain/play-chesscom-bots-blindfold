**Location:** `.autodev/DECISIONS.md` (absent); `sounds.js:378-382` (present, code comment only).

add a `## 3.4 speech instrumentation (PLAN.md §3.4)` section to DECISIONS.md
carrying the bump rule verbatim from the contract, plus the 3.4.4 opt-in site
list (currently exactly one production site: `speakPosition()`'s

## NOTEs

### NOTE-1 — In-flight entry leak if the browser drops both callbacks
`speak()` removes the entry only in `finish()`, which runs on
`onend`/`onerror`/speak-throw. If the browser fires **neither** callback
for an utterance, the entry stays in `inFlight` indefinitely. A later
`cancelRequested` would then emit a spurious `utterance_cancel_requested`
for an utterance that may have audibly finished — a (rare, browser-quirk-
gated) false record. Consider a diagnostic or a bounded in-flight set in
a future task. Not blocking: the trigger requires dropped callbacks.

### NOTE-2 — AC6 opt-in pin could be stronger
The "exactly one production saveText site" test asserts `some()` line
matches the speakPosition opt-in but does not pin the count. A second
opt-in site could be added without updating the contract's 3.4.4 table.
Suggest asserting the exact expected `saveText:` lines (production opt-in
+ plumbing read). Not blocking: grep today confirms exactly one.

### NOTE-3 — speech_settings emit is not retried
`settingsEmitted = true` is set before the emit; if that emit throws, the
baseline is never retried. Best-effort and consistent (no partial state),
just noting the asymmetry with per-utterance settings, which are
self-describing on every `utterance_started`.

### NOTE-4 — `current_utterance` is write-only dead state (pre-existing)
`sounds.js` assigns `current_utterance` in the fallback paths but nothing
reads it — true before 3.4 and unchanged by it. The tracker path does not
update it. No behavior impact; flagging only so a future cleanup doesn't
assume it's live.

### NOTE-5 — Unlinked utterances have in-memory-only IDs
Per the contract's §2.2 design, an utterance with no valid link is spoken
and tracked but emits no `utterance_started`, so its uuid-v4 `utteranceId`
never reaches durable storage. 3.4.1's "give each utterance an ID" is
therefore durable only for linked utterances. Acceptable: every production
call site passes a link whenever the tracker is active (pre-§5 inertness
is the only systematic unlinked case, and it emits nothing at all by
design).

### NOTE-6 — Fixed template strings ride on the bump rule
The `z`-shortcut `"Last move: "` prefix and the `"Game not over."`
fallback are fixed strings in the shortcut templates — reproducible only
because the version bump rule covers "the shortcut text templates". When
the coordinator writes the DECISIONS.md 3.4 section (SF-1), it should name
these templates explicitly so a future text tweak is recognized as a
bump-triggering change.
