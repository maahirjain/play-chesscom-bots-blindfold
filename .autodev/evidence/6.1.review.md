## 1. No fabrication — holds

**gameStartingFen.** `buildGameStartingFen` copies `gameStartingFens[gid]` when it is a string or null, else null. Never synthesized. The contract's hypothesized "1.2 conditions' starting FEN" fallback does not exist — I verified `session_conditions.js`'s seven CONDITION_FIELDS contain no FEN field, so the builder's "provided FEN → null" precedence is the only honest option. Non-string/non-null values degrade to null (unknown), not to invented data.

**Completion mapping.** Absent stopVerdict → `{verdict:'unknown', warnings:[], note:'stop-verdict-unavailable', ...}` — fail-closed toward unknown, never 'complete'. Unrecognized verdict string → TypeError (never silently defaulted). `'failed'` → throws `Error('exporter: session-not-complete')` so 6.6's orchestration refuses the export; a bundle can never document a session whose Stop failed. (See N1 on the throw-vs-return deviation.)

**Training fields (the documented deviation).** The contract's schema comment said "5.2's fields, verbatim from metadata." I verified this is factually wrong: `session_identity.js` (1.1) carries only identity + versions + category; `trainingApproach`/`verbalScaffolding` are 1.2 conditions fields (confirmed in `session_conditions.js` CONDITION_FIELDS and in the 5.2 contract: "`trainingApproach` (conditions, user-selected)"). The builder reads them from `conditions.{field}.value` (null when conditions absent). This is the honest correction — reading from the actual source of truth — and the `initialConditions` block still exports the full seven-field record verbatim, so no data is lost or duplicated.

**Media inventory.** Zero-segment kinds are explicit (`{segments:0, finalized:0, formats:[]}`), never omitted. Counts only; `finalized` = `segmentNumber !== null` (4.13's mark); formats are sorted unique mime types. No metrics.

## 2. Purity — holds

- No I/O, no IndexedDB reads, no ID minting. The only clock read is `new Date().toISOString()` inside `defaultNowUtcIso` — the contract-sanctioned labeled exception (`exportedAtUtc`), injectable via `nowUtcIso` for testability. No `Date.now()`, `performance.now()`, `Math.random()`, or `crypto` anywhere in the module.
- Does not mutate inputs: `gameIds.slice()`, `warnings.slice()`, and all builders construct fresh objects. Pinned by test ("does not mutate its inputs").
- Module-level `BlindfoldSession` global mutation follows repo convention; `EXPORTER_STREAM_KINDS` is frozen.

## 3. Byte-stability — holds (with a 6.7 note)

- Key order is fixed by object-literal insertion order at every level, matching contract §3 exactly (pinned by the golden test's `Object.keys` assertion).
- `JSON.stringify(doc, null, 2)` with fixed 2-space indent; `formats.sort()`; `gameStartingFen` keys in `gameIds` order; `warnings` order preserved from input. Byte-equality test pins this.
- **N4 (for 6.6/6.7, not a 6.1 defect):** `exportedAtUtc` is the real export time, so two exports of the same session differ in bytes. The architecture's "retried byte-identically (6.7)" will need to normalize or exclude this field. Inherent to the contract's requirement; 6.1 cannot fix it.

## 4. Strict validation — holds (minor notes)

TypeError on: non-object args; malformed metadata (non-uuid sessionId, non-uuid gameIds entries, empty versions/category strings, non-string/null protocolVersion); non-object or partial conditions (all seven fields required — a partial record is malformed, not an excuse to invent); non-array manifestRecords; manifest records lacking streamKind; non-object stopVerdict; unrecognized verdict; negative or fractional eventCount; non-function nowUtcIso; nowUtcIso returning non-string. `'failed'` → plain `Error` (correct per repo convention: refused operation, not malformed input).

- **N2 (minor):** Optional nested fields degrade leniently rather than throwing: a non-string `trainingApproach.value` → null in the `training` block (while `copyConditionsVerbatim` copies the same malformed value verbatim into `initialConditions` — a slight inconsistency between the two blocks); a malformed `stopResp.finalizedAtUtc` → null; a non-string/non-null `gameStartingFens[gid]` → null. All fail-safe (→ null = unknown), and top-level required structure is strictly validated. Not fabrication, not a safety issue.
- **N3 (trivial):** `undeliveredEvents` accepts fractional `pending` (e.g. 1.5) since the check is `typeof === 'number' && >= 0`. Nonsensical but harmless; 5.10 produces integers by construction.

## Notes (non-blocking)

**N1 — 'failed' verdict: throw vs. return (documented deviation).** Contract §3 says "6.1's builder returns the verdict; 6.6's orchestration enforces the refusal." The implementation throws `Error('exporter: session-not-complete')` instead. The safety property is preserved — arguably strengthened, since a throw cannot be accidentally ignored the way a returned verdict could. The build report documents the choice and the test pins it. **Coordination note for 6.6:** its orchestration must catch this throw (not check a returned verdict); anyone reading only the contract would expect the latter.

**N2/N3** — as above; lenient coercion in optional nested fields and fractional pending acceptance. Fail-safe, not defects.

**N4** — exportedAtUtc vs. 6.7 byte-identity; inherent, for 6.7 to resolve.

**N5** — `metadata.gameIds: []` passes validation (empty array is honest data, though odd). Not forbidden by the contract.
