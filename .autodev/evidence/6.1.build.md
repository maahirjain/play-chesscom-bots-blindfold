## What was built

**`exporter.js`** (new, 13.7 KB): dependency-free classic script →
guarded `BlindfoldSession` global → IIFE `'use strict'` → Node
`module.exports` shim (repo convention).

`buildMetadataJson({metadata, conditions, manifestRecords, stopVerdict, eventCount, gameStartingFens, nowUtcIso})`:

- **Schema:** exact contract §3 key order (sessionId, gameIds,
  sessionCategory, versions, training, initialConditions,
  gameStartingFen, completion, mediaInventory, coverage,
  exportedAtUtc). 2-space pretty-print; key order stable for 6.7's
  byte-identity (verified by byte-equality test).
- **Inputs:** metadata (required, strict uuid/category/version
  validation); conditions (optional, null → initialConditions null);
  manifestRecords (required array, may be empty); stopVerdict
  (optional); eventCount (required non-negative integer).
- **Completion mapping:** 'complete' → complete; 'complete-with-warnings'
  → warnings verbatim + finalizedAtUtc from stopResp +
  undeliveredEvents from flushResult.pending; absent → 'unknown' with
  note 'stop-verdict-unavailable' (never 'complete'); 'failed' →
  throws `Error('exporter: session-not-complete')` for 6.6's
  orchestration to map to `{ok:false}`; unrecognized verdict →
  TypeError (malformed, never silently defaulted).
- **Media inventory:** per-kind `{segments, finalized, formats}` —
  counts only; zero-segment kinds explicit; finalized =
  segmentNumber !== null (4.13's finalize mark); formats = sorted
  unique actualMimeType.
- **gameStartingFen:** per gameId in gameIds order; null where unknown,
  never synthesized.
- **Purity:** no I/O, no IndexedDB, no ID minting; single labeled clock
  read via injected `nowUtcIso` (defaults to real UTC ISO); does not
  mutate inputs (verified by test).

## Open questions (contract §8) — resolved

1. **gameStartingFen precedence:** the contract listed "game_started
   observation → 1.2 conditions' starting FEN → null". Investigation
   found the 1.2 conditions record carries **no FEN field** in the
   current schema (seven CONDITION_FIELDS, none a FEN) — that source
   does not exist. The implemented precedence is: `gameStartingFens`
   input (which 6.6's orchestration extracts from the game_started
   event payloads' `{fen}`, per game_records.js's denormalization
   rule) → `null`. The input is optional; absent → all null. This is
   honest: the builder never reads events itself (pure), and never
   synthesizes a FEN.

2. **Byte-stability for 6.7:** confirmed. Fixed key insertion order +
   `JSON.stringify(doc, null, 2)` = deterministic bytes. Sorted
   `formats` arrays; gameStartingFen keys follow gameIds order.
   Byte-equality test pins this.

## Contract deviation (documented)

The contract's schema comment says `"training": {...} // 5.2's fields,
verbatim from metadata`. The 1.1 metadata record carries only
identity + versions + category (six keys) — `trainingApproach` and
`verbalScaffolding` are **1.2 conditions fields** (5.2's contract:
"trainingApproach (conditions, user-selected)"). The builder reads
them from `conditions.{field}.value` (null when conditions absent),
which is the honest interpretation of the contract's intent. The
initialConditions block still exports the full seven-field record
verbatim, so no data is lost or duplicated.
