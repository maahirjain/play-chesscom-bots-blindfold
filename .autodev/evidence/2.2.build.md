# Task 2.2 Build Report — Extension-owned IndexedDB database

## Implementation

**`db.js`** (new, repo root, 12.4 KB): plain dependency-free script following
the Section-1 module pattern — guarded `BlindfoldSession` global (shared, not
redeclared), IIFE `'use strict'`, Node `module.exports` shim. Exposes
`BlindfoldSession.DB` with exactly the contract §2.5 API:

- Frozen constants: `DB_NAME = 'blindfold-experiment'`, `DB_VERSION = 1`,
  `SCHEMA` (deep-frozen `{dbName, version, stores[]}` — the single source of
  truth consumed by `openDatabase()`).
- Five stores per contract §2.3: `events` (keyPath `eventId`, indexes
  `bySessionId`/`byAppendSeq`, both non-unique), `session_metadata`,
  `conditions`, `sequence_state` (all keyPath `sessionId`), `media_chunks`
  (compound keyPath `['segmentId','chunkIndex']`).
- `openDatabase()` → cached-handle `Promise<IDBDatabase>`; idempotent
  `onupgradeneeded` (guarded store/index creation, never deletes data);
  `onblocked` → plain `Error` rejection.
- `put`/`get`/`getAll` (all `async`, so every failure mode is a rejection,
  never a sync throw): single-store transactions; `getAll(store, {index,
  lower, upper})` opens IDBKeyRange ranges on indexes or primary keys.
- `closeDatabase()` → void; closes and clears the cached handle.
- `globalThis.indexedDB` (and `IDBKeyRange`) read lazily per call, never
  cached: the module loads in Node with `indexedDB` undefined.
- Argument validation runs BEFORE any platform access (V1 exercises the error
  contract with `indexedDB` deleted).
- Error conventions per AGENTS.md: unavailable platform → plain `Error`
  (never a silent in-memory fallback); unknown store/index → `RangeError`;
  wrong types → `TypeError`; IDB request/transaction failures (incl. quota) →
  plain `Error` wrapping the DOMException name/message (`cause` attached).
- No envelope/record validation, no Section-1 imports, no `chrome.*`, no
  `localStorage`, no `deleteDatabase`/`count()`/transaction-runner.

**`sw.js`** (modified): added exactly one functional line,
`importScripts('db.js');`, after `'use strict';`; removed the `2.2:` line from
the "Intentionally absent" header (2.3–2.9 remain). Diff is exactly those two
hunks.

**`tests/db.test.js`** (new): 20 V1 checks — SCHEMA deep-equality, frozen
constants, API surface, error contract with `indexedDB` deleted, static
guards (no `localStorage`/`chrome.` in db.js, no `importScripts` call in code,
sw.js code-lines exactly `['use strict';, importScripts('db.js');]`, header
still lists 2.3–2.9, manifest.json byte-identical to HEAD).

**`~/workspace/tools/ext-verify/sw-db.js`** (harness tooling, outside the
repo): V2 driver — loads the extension in real headless Chrome
(`ignoreDefaultArgs: ['--disable-extensions']` per DECISIONS.md #7), evaluates
in the real SW context, probes page-context origin isolation via a localhost
page (`about:blank` is an opaque origin where `indexedDB` is denied —
harness lesson), cleans up the test database afterwards.

## Test-evolution notes (not deviations)

- `put`/`get`/`getAll` were made `async` (not just promise-returning) so
  argument-validation failures are rejections, never sync throws — matches
  contract §2.5 "All async methods return Promises" most faithfully.
- `tests/manifest_sw.test.js` (2.1) pinned 2.1-era transient facts and failed
  5 assertions after the legitimate 2.2 sw.js amendment. Updated to cumulative,
  git-independent invariants: sw.js code-lines exactly the use-strict
  directive + one `importScripts('db.js')`; manifest head exactly the four
  expected keys. The superseded "sw.js is new at HEAD" check was replaced with
  a pointer to `tests/db.test.js`, which now owns the sw.js assertions.
- The db.js header comment avoids the literal tokens `localStorage` and
  `chrome.` so the static guards stay meaningful (the AC2 check is a naive
  substring search by contract).

## Deviations from the contract

None material. The contract §3.2 parenthetical on `importScripts` placement
("after the header comment (before 'use strict'...)") was self-contradictory;
the builder placed `importScripts('db.js');` after the header comment and
after `'use strict';`, keeping the strict directive in prologue position —
functionally cleanest, and AC4's "diff = importScripts line + header update"
holds either way.
