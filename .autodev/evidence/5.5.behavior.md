  between the guard and `sessionId = sid;`. Reasonable code-review
  pin for the synchronous check-and-set.

  transports — `created:true` skips the query (no get-status between

  `duplicate-start:session-active` title), `{ok:false}` and
  no-response proceed, missing `created` runs the pre-check
  conservatively. Faithful.
- **AC4 refusal mapping:** the set-session `session-active` refusal
  aborts via the local-only path — asserts exactly **one**
  `set-session` call (the refused one), i.e. no
  `clearRecorderSession` second call that would wipe the other tab's
  session; no `start-streams` after refusal; other failures keep the
  existing `set-session-failed:<err>` path. Faithful — the
  single-set-session-call assertion is the key anti-footgun.
- **AC7:** diff-discipline allowlist, 24 offscreen `MSG_*`

  `session_controls.js`, PLAN.md unmodified vs `main`. Confirmed

refused tab's sessionCategory is never adopted" asserts the session
and owner are intact rather than the category value directly. There
is no public `sessionCategory` getter on the recorder (it surfaces

V2-covered); the guard's placement before the category assignment
makes adoption structurally impossible. The comment is transparent
about the coverage split. Acceptable.
