# 2.8 build report — session status indicator

## Implementation

**New `status_indicator.js`** (BlindfoldSession convention: guarded global →
IIFE `'use strict'` → Node shim; no `chrome.*`, DOM + sender only):

- `classifySenderStatus(status)` — pure. Input is `sender.getStatus()`
  (`{pendingCount, lastError, transportAvailable, retryScheduled}`).
  Output is a frozen `{state, detail}`; `detail` is the raw `lastError`
  string (null when healthy). `TypeError` on malformed input.
  Classification table:
  - `lastError === null` → `healthy` (any pendingCount — a non-empty
    queue with no failure is normal draining; never cry wolf before the
    first attempt).
  - `send-timeout` / `no-ack` / `transport-error:<name>` →
    `degraded-retrying` (amber).
  - `write-failed:QuotaExceededError` → `failed-storage-full` (red,
    distinct class).
  - any other `write-failed:<code>` → `failed-persistent` (red). Covers
    `CorruptSequenceState`: the writer rejects every subsequent write,
    so the indicator honestly latches.
  - any other non-null `lastError` (including `''`) → `failed-persistent`
    (fail-closed; a failure we don't understand is never "will recover").
- `installStatusIndicator(sender, options)` — creates one `<span>●</span>`,
  anchors it after `#blindfold-chess-move-input` (fixed-corner fallback
  when the anchor is absent), polls `getStatus()` every 2000ms
  (injectable `intervalMs`; `globalThis.setTimeout` resolved per tick —
  2.5 mock.timers precedent), re-renders only on state/detail change.
  `title` carries the raw detail code. Invalid sender/options →
  `TypeError` before any timer starts; a throwing `getStatus` is
  swallowed (indicator keeps last state, never breaks page code).
  Missing document → plain `Error` (platform capability).
  Returns `{element, stop}`.

**`content.js`** — install call after the move-input creation block (so the
anchor exists), with a 3-line comment. **`manifest.json`** — js list gains
`'status_indicator.js'` after `'lifecycle.js'`. **`overlay.css`** —
additive indicator classes only. **`sender.js` unchanged** (contract §3.1).

## Deviation from the contract

**Contract AC10 said `manifest.json` byte-identical to HEAD.** That is
unachievable: `status_indicator.js` must be in the manifest's
content_scripts js list to load in the content-script world (content
scripts have no `importScripts`; inlining into content.js would violate
module conventions). The js list gains exactly one entry after
`'lifecycle.js'`; the manifest pin evolves from byte-identical to
exact-diff (one line removed, one added, nothing else changed). The
reviewer should confirm this was the right call vs. the contract text.

## Notes for the reviewer

1. The manifest deviation above (AC10 vs. loadability).
2. The sender only keeps a writer's error string when the ack's `eventId`
   matches the head event (`recordAckFailure`); anything else is `no-ack`
   → amber. The harness's simulated rejections echo the eventId, matching
   real writer behavior. This means a writer bug that drops eventId would
   surface as transient-amber rather than red — fail-open in that one
   corner. Worth a reviewer opinion on whether the classifier should
   treat `no-ack` after N attempts as persistent (out of 2.8 scope;
   suggested §5/2.9 follow-up, not a 2.8 blocker).
