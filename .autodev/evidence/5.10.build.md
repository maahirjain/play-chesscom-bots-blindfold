**Builder:** task builder subagent. **Date:** 2026-10-06.

## Outcome

Implemented PLAN.md §5.10 per the contract. The Stop sequence now awaits
`sender.flush()` (final storage acknowledgments) after the stop-streams
response, computes an honest completion verdict via the new pure
`computeCompletion()`, surfaces `flushTimedOut` and undelivered events in
the completion presentation, and retains the enriched verdict for §6.

## What was built

**`session_controls.js`** (only product file changed):

1. **Pure `computeCompletion(stopResp, flushResult)`** — returns frozen
   `{verdict: 'complete'|'complete-with-warnings', warnings: [...]}`.
   Verdict is `'complete'` only when every required stream finalized ok
   with no `flushTimedOut` AND `flushResult.pending === 0`. Warnings name
   each gap: `<kind>-flush-timed-out`, `<kind>-failed:<error>`,
   `<kind>:missing-stream-result`, `<N>-events-undelivered`,
   `stop-response-malformed`, `flush-result-unknown`. Malformed inputs
   fail closed toward warning — never a silent `'complete'`. Exported as
   `BlindfoldSession.computeCompletion` with `COMPLETION_COMPLETE` /
   `COMPLETION_COMPLETE_WITH_WARNINGS` constants.

2. **Stop-sequence ordering** (contract §3): `recordStopTermination` →
   `MSG_STOP_STREAMS` → `pollOnce()` → NEW transitional "Finalizing…"
   button state (phase stays STOPPING, button enabled so a hung flush
   never traps the user) → `opts.sender.flush()` await (defensive:
   missing/non-function flush → honest warning, never crash/hang;
   rejection → same via the rejection handler) → NEW `finalizeStop()` →
   idle. The button never shows clean idle before the flush resolves.

3. **`finalizeStop(stopResp, flushResult)`** — computes the verdict
   (defensive try/catch → fail-closed warning), retains the enriched
   `{stopResp, flushResult, verdict, warnings}` via the existing
   `lastStopResponse`/`getLastStopResponse` seam (extended shape, still
   null before any Stop), calls `opts.onStopComplete(enriched)` (the
   5.1 handoff, extended not broken — the full stop response is carried
   as `.stopResp`), then the unchanged idle mechanics with warnings as
   the button detail text (`finalize-warnings:<w1>;<w2>`).

4. **Failure paths unchanged:** `MSG_STOP_STREAMS` `{ok:false}` /
   no-response → stays in "Stopping…" with `stop-failed:<err>`, no flush
   attempted, session retained for retry (5.1 behavior preserved).

## Contract decisions (open questions §7)

1. **Wording:** transitional label "Finalizing…"; warning detail
   `finalize-warnings:<w1>;<w2>` (follows the `stop-failed:<err>`
   precedent).
2. **`onStopComplete` payload:** the enriched
   `{stopResp, flushResult, verdict, warnings}` object. The 5.1 handoff
   tests were evolved honestly: they now assert `.stopResp` carries the
   full response (same reference), plus the verdict/warnings/flushResult.
3. **Flush failure isolation:** defensive try/catch around the flush()
   call itself + rejection handler → `flushResult: null` → honest
   `'flush-result-unknown'` warning. The Stop never hangs.
