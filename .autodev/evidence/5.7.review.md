## 1. The "no auto-stop" claim — verified independently

I did not trust the builder's reading; I re-verified each link in the chain by reading the code directly.

**`recordGameEnded` (chess_utils.js:1682) is clean.** I extracted its body by brace matching and scanned for stop machinery: no `onStopClick`, no `stop-streams`, no `MSG_STOP_STREAMS`, no `channelCall`, no `abortStart`, no `setSlots`, no phase assignment, no stream-stop references. It validates input, emits the `game_ended` event via the injected `emitEvent`, marks per-source idempotency, and freezes `lastObservedEnd` for `chess_rules`/`chesscom_dialog` sources. That is all it does.

**`onStopClick` (session_controls.js:1299) has exactly one call site** — the button/keydown UI handler at line 1396, gated on phase (`IDLE`→Start, `ACTIVE`/`STOPPING`→Stop). `content.js` contains zero references to `onStopClick` (verified by grep, not just the test).

**Game-end observation sites are pure observation.** `content.js:197` calls `recordChessRulesEnded` inside the move observer, wrapped in a failure-isolated try/catch. `session_controls.js` consumes the lifecycle recorder only at Start (`resetEnded()`, line 1211) and at Stop (`getLastObservedEnd()` + `recordStopTermination()`, lines 1316–1328). The poll loop (`pollOnce`, lines 783–880) contains zero references to game-end state — I grepped the full function range.

**`announceResultIfOver` (sounds.js:79) is speech-only.** Brace-matched body extraction confirms no recording-state access, no channel calls, no phase references.

**No `game_ended` event subscribers exist that could trigger a stop.** The event type is defined in `game_records.js`, emitted by `recordGameEnded`, and referenced only in comments elsewhere. It flows to the SW writer for storage; nothing consumes it as a control signal.

**The reverse direction is correct, not a violation.** `recordStopTermination` is called FROM the Stop sequence (line 1326), recording a manual termination. Stop→record is the 3.5.4 seam working as designed; game-end→stop would be the violation, and it does not exist.

## 2. Attacking the static pins (AC1)

The three static tests use comment-stripped source, word-boundary regexes, call-site counting with a negative lookbehind, and brace-matched body extraction. I assessed each for bypassability:

**Pin 1 (content.js has no `onStopClick`):** Could be bypassed by a stop path that avoids the literal name — e.g., dispatching a synthetic click on the button, or calling the channel message directly. However: (a) a synthetic click goes through the UI handler at line 1396, which is the legitimate path — the pin's intent is "no game-end-triggered stop," and any game-end code dispatching synthetic clicks would be bizarre and visible; (b) content.js has no access to `MSG_STOP_STREAMS` (it lives in session_controls.js's closure) and no channel-call affordance for it. The pin is adequate for its purpose.

**Pin 2 (exactly one `onStopClick()` call site):** The regex `(?<!function )onStopClick\(\)` would also match method-style calls (`x.onStopClick()`), so it is not easily bypassed by namespacing. Dynamic dispatch (`fn.call()`) would evade it, but the behavioral tests (below) provide the real defense.

**Pin 3 (recordGameEnded body has no stop references):** Could be bypassed by refactoring `recordGameEnded` to delegate to a helper that stops. But `recordChessRulesEnded`, `recordDialogEnded`, and `recordStopTermination` all delegate TO `recordGameEnded` — covering its body covers every game-end recording site. And again, the behavioral tests are the backstop.

**The real strength is AC2–AC5, not AC1.** The behavioral tests drive the REAL `createGameLifecycleRecorder` (merged namespaces, not mocks) from all three sources during an ACTIVE session and assert: phase stays ACTIVE, slots/session identity unchanged, zero `recorder-stop-streams` messages, button still "Stop", emitter still active, badge unchanged, and the 3.5.4 seam intact. Even a hypothetically clever static-pin bypass that actually stopped recording would fail these tests. Defense in depth holds.
