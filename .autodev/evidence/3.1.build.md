### chess_utils.js

- **`observeMoves` — content comparison (3.1.1)**: replaced the
  length-only guard with element-wise string comparison (`halfMovesEqual`).
  Same-length substitutions (takeback + different move) now fire the
  observer. Signature unchanged.
- **`updateGame` removed** (contract §2.10, flagged): its contract
  (silent reset-on-shorter, unvalidated advance) is exactly what
  3.1.1/3.1.2/3.1.5 replace. No wrapper possible (the tracker owns its
  game instance); dead code is worse.
- **New `createHistoryTracker({gameId, emitEvent, onGameReset,
  suspectThreshold, desyncThreshold})`**:
  - Owns one stable `Chess` instance (reset + replay, never replaced —
    `content.js`/`sounds.js` keep working).
  - `observe(halfMoves)` DOM-free, synchronous → `{confirmed, revised,
    recovered, syncFailed, reset}`.
  - **Validation (3.1.2)**: raw SAN first, then `normalizeMove` fallback;
    never advances on failure.
  - **Reconciliation**: clean append / takeback (strict non-empty prefix,
    immediate) / correction (divergent, O not shorter) / suspect window
    (empty or shorter-divergent; `suspectThreshold` consecutive →
    genuine reset → `onGameReset()`, state `'ended'`).
  - **Batch/recovery (3.1.6)**: `history_recovered` marker-first;
    `'page_reload'` (first observation has history) / `'late_attachment'`;
    no time fields in payloads; no backdating.
  - **Sync failures (3.1.7)**: two-tier — `history_sync_failed` per
    irreconcilable observation (5 reasons, exact keys
    `{reason, plyIndex, observedSan, internalFen}`) + bridge test (full
    replay from initial on scratch board; observation-wins on
    `internal_desync`) + `position_checkpoint` behind 1.4's strict gate
    (one only, last-known-good FEN, `unreconciled_history`).
  - **Promotion rule (1.4)**: promotion-shaped SAN with indeterminable
    piece → `unobservable_promotion`; never a guessed `move_confirmed`.
  - **Null gameId**: board advances, count advances, zero emissions
    (track-but-don't-emit).
  - Exports on `BlindfoldSession`: `createHistoryTracker`,
    `HISTORY_SYNC_FAILED_EVENT_TYPE`, `SYNC_FAILURE_REASONS`,
    `activeGameId` (§5-owned, null default). Node `module.exports` shim
    added (repo convention). Cross-module 1.4 factory access via
    `sharedBS()` (globalThis merge pattern).
- `normalizeMove`, `isMoveLegal`, board-click, piece-set helpers:
  byte-identical.

### content.js (§2.9 wiring)

Tracker instantiated with `gameId: BlindfoldSession.activeGameId || null`
(null until §5 → track-but-don't-emit); `emitEvent` wraps
`sender.emit`; `onGameReset` is a §5 stub. `const game =
historyTracker.getGame()` replaces `new Chess()`; `game_half_move_count`
removed. Observer callback speaks each newly confirmed move in order via
`sayMove(new Chess(m.preFen), m.san)` (preFen is in-memory only).

### manifest.json

`game_records.js` added to content-scripts js list before

content-script world. (Deviation from contract §2.10's "no other product

were not loaded. Minimal necessary change.)

## Deviations from contract

1. **manifest.json**: added `game_records.js` (see above). All manifest
   js-list pins updated with justification comments.
2. **Shorter-divergent is suspect, not correction**: the contract's step
   5/6 boundary was ambiguous for `O` shorter than `C` but divergent
   (e.g. `['e4','d5']` vs 4 confirmed). Implemented: divergent `O` with
   `O < C` → suspect window; divergent with `O >= C` → correction.
   Rationale: a truncated divergent observation is the ambiguous case
   3.1.5 names; a complete divergent history is a revision.
3. **`const game` not `let game`** in content.js: the instance is never
   replaced (tracker-owned), so `const` is accurate.
