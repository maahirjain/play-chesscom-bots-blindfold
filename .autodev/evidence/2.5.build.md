# Task 2.5 Build Report — Retry unacknowledged events while the originating context remains available

## What was implemented

Extended `sender.js` (only app file touched) with exactly the two mechanisms
from the contract (`.autodev/evidence/2.5.contract.md` §2–§3):

1. **Per-attempt send timeout** (`SENDER_SEND_TIMEOUT_MS = 10000`, injectable):
   each send races the transport promise against a timeout via
   `Promise.race`. Timeout win → `lastError = 'send-timeout'`, head stays
   queued, pump stops, retry scheduled. The loser is discarded by identity
   (`err === timeoutError`, not message matching): a late ack cannot
   double-dequeue or corrupt pump state; if the late ack was `{ok:true}` the
   event was durably written and the retry's byte-identical resend receives
   the idempotent `{ok:true}` from the writer's eventId dedup. The losing
   promise is subscribed by the race, so no unhandled rejection escapes.
   `setTimeout`/`clearTimeout` resolved from `globalThis` at call time
   (transport-lazy pattern); if timers are unavailable the attempt fails
   fast as a timeout — honest, still queued, still retryable.
2. **Retry timer** (`SENDER_RETRY_INTERVAL_MS = 5000`, injectable): after any
   *failed* send attempt (transport throw/reject, timeout, `undefined` /
   mismatched ack, writer `{ok:false}` — uniform, no classification), if the
   queue is non-empty, no retry is already pending, and a transport is
   resolvable, schedule exactly one `setTimeout(onRetryTimer, ...)`.
   `onRetryTimer` clears its handle *before* kicking the pump; any new pump
   run (`emit()`/`flush()`/timer) calls `clearRetry()` first — at-most-one
   invariant holds across all interleavings. Drain and no-transport paths
   never schedule.
3. **Injectable options** `createSender({sendTimeoutMs, retryIntervalMs})`:
   non-number (incl. `NaN`) → `TypeError`; non-finite or `<= 0` →
   `RangeError` (each option independently). Defaults are the exported
   frozen constants.
4. **`getStatus()`** gains `retryScheduled` (frozen into the returned
   object) for 2.8. No `destroy()`/`close()` (rejected per contract: the
   timer dies with the context). No failure classification. No
   `pagehide`/unload flush (rejected: ack path dead at unload; 2.7's
   discontinuity marking is the honest mechanism). No other API changes;
   `emit()`'s synchronous timestamp-then-queue contract untouched; wire
   message shape untouched.

## For the reviewer to stress-test

- The timeout-vs-late-ack race: verify the implementation actually races
  (identity-discarded loser) rather than clearing the timeout on any
  settle and misattributing a late ack; verify the losing promise's
  handlers are attached (no unhandled rejection).
- `scheduleRetry` called **only** on failed attempts (never on drain,
  never on no-transport); at-most-one-timer invariant across
  `emit()`/`flush()`/timer interleavings.
- Head-of-line blocking under uniform retry: a permanently-rejected head
  (e.g. deterministic `event-id-content-mismatch`) blocks the queue
  forever by design — confirm this is the contracted reading of PLAN
  §2.5 and that 2.8's surfacing (via `lastError` + `retryScheduled`) is
  sufficient.
- The mock-timer test strategy: `mock.timers.tick()` runs timer callbacks
  synchronously without interleaving microtasks, so chained retries need
  one `advance()` per interval (documented in AC4).
