# Task 3.4 build report — Instrument speech lifecycle

## Implementation

Per `.autodev/evidence/3.4.contract.md` (13 ACs: AC1–AC11 V1, AC12 V2, AC13 V3-deferred).

### `sounds.js`
- **3.4-owned event vocabulary** (1.3 §2.2, each task owns its vocabulary):
  `UTTERANCE_STARTED_EVENT_TYPE = 'utterance_started'`,
  `UTTERANCE_ENDED_EVENT_TYPE = 'utterance_ended'`,
  `UTTERANCE_CANCEL_REQUESTED_EVENT_TYPE = 'utterance_cancel_requested'`,
  `SPEECH_SETTINGS_EVENT_TYPE = 'speech_settings'`; frozen
  `UTTERANCE_TRIGGERS` (`move`/`help-request`/`game-result`),
  `UTTERANCE_END_OUTCOMES` (`completed`/`cancelled`/`error`),
  `CANCEL_SOURCES` (`user`/`interrupt-replace`); **`SPEECH_LOGIC_VERSION =
  '1'`** with a bump rule in the comment (any change to what/when/why
  speech fires, utterance text derivation, or trigger/link assignment
  requires a version bump). `event_envelope.js` untouched.
- **Exact-keys validators** `requireValidUtteranceStartedPayload`
  (`{utteranceId, trigger, speechLogicVersion, rate, pitch, volume,
  voiceName, text}`; `text` string-or-null),
  `requireValidUtteranceStartedRefs` (**sparse single key**: exactly one
  of `{moveEventId}` / `{helpRequestEventId}`, value uuid-v4),
  `requireValidUtteranceEndedPayload`
  (`{utteranceId, outcome, cancelSource, errorName}`),
  `requireValidUtteranceCancelRequestedPayload`
  (`{utteranceId, source}`), `requireValidSpeechSettingsPayload`
  (`{voiceName, voiceCount, rate, pitch, volume}`), exposed on
  `BlindfoldSession`. TypeError on wrong types, RangeError on bad enums
  (3.1/3.2 precedent). `utterance_ended`/`utterance_cancel_requested`
  carry **no refs** (contract §2.2: utteranceId is the join key).
- **`createSpeechTracker({getSessionId, getGameId, emitEvent, speak,
  cancel, getVoices, newUtterance})`**: DOM-free, Node shim, namespace
  export (3.1/3.2/3.3 precedent). `speak(text, {rate, pitch, volume,
  link, saveText, onDone})` is the **single choke point**: assigns a
  uuid-v4 utteranceId (via 1.3's `newEventId`), attaches
  onend/onerror, emits `utterance_started` (then the injected `speak`
  primitive), and tracks the in-flight set. Emission gated on non-empty
  sessionId AND gameId via thunks — pre-§5 inert (speech proceeds, no
  events). Failure-isolated per 3.2 SF-1: every emit is try/caught, the
  tracker never throws into speech paths.
- **3.4.3 requested-vs-observed:** `cancelRequested(source)` records
  `utterance_cancel_requested` per in-flight utterance (payload
  `{utteranceId, source}`, no refs) and calls the cancel primitive.
  Later onend/onerror → outcome `'cancelled'` **only if** a cancel was
  recorded for that utterance; otherwise `'completed'` / `'error'`
  with the raw `errorName` (callback names are never trusted alone).
- **3.4.4 text rule:** `utterance_started.text` is `null` unless the
  call site passes `saveText` (the verbatim text). The only production
  opt-in is `speakPosition()`'s `"Board not found."` DOM-failure text
  (pinned by a test enumerating `saveText:` sites).
- **3.4.5:** one-time `speech_settings` baseline (voiceName/voiceCount/
  rate/pitch/volume) emitted at the first utterance.
- Instrumented speech functions route through the tracker with
  failure-isolated fallback to direct speechSynthesis:
  `speakText(text, {interrupt, rate, link, saveText})`,
  `speakTextAsync` (promise still resolves on end AND error — the
  tracker's `onDone` fires for every outcome),
  `announceResultIfOver(link)`, `sayMove(game, san, link)`,
  `speakPosition(link)` (the 3.4.4 opt-in), `speakFullMoveList(half_moves,
  link)` (each line links the same helpRequestEventId; timestamp-guard
  abandonment documented as not-a-cancel — no `cancel()` call),
  `stopAllSpeech()` → `cancelRequested('user')`.
  `playIllegalMoveSound` untouched (non-speech audio; still bypasses
  the tracker).
- **`illegal_move_audio` Node-guard** (deviation #1): top-level `new
  Audio(...)` now guarded by `typeof Audio !== 'undefined'` and
  `chrome.runtime.getURL` availability so `sounds.js` loads in Node for
  V1; `playIllegalMoveSound` returns early when null. Behavior in the
  browser unchanged.

## Deviations

1. **`illegal_move_audio` Node-guard** (see above): the top-level `new
   Audio(chrome.runtime.getURL(...))` threw under Node, blocking V1
   coverage of the tracker in the same file. Guarded with
   `typeof Audio !== 'undefined'` + `chrome.runtime.getURL`
   availability; `playIllegalMoveSound` early-returns when null.
   Browser behavior unchanged; a test pins the audio path stays
   tracker-free.
2. **Sparse started refs** (contract-conformant; found by V2): the
   first implementation used `{moveEventId, helpRequestEventId}` with
   one null, but the contract (§2.2) specifies **one of**
   `{moveEventId}` / `{helpRequestEventId}`, and the sender's
   `requireRefs` (event_envelope.js, untouchable) rejects null ref
   values — every utterance event was silently dropped at the real
   emit path (V1's injected emitEvent masked this). Fixed to the
   sparse single-key form; validator, `normalizeLink`, V1 tests, and
   the V2 harness updated. This is the kind of integration bug V2
   exists to catch.
3. **Harness iteration (mine, not product):** the first harness passed
   `trigger`/`moveEventId` at `opts` top level instead of
   `opts.link` (contract §2.3) — the tracker correctly treated those
   utterances as unlinked (speech works, no events). Also corrected
   harness assertions that expected `refs.utteranceId` on ended /
   cancel_requested (contract: no refs, join via payload) and an
   invented `hasVoices` settings field.
4. Test-pin evolutions in 10 suites (allowlist additions for
   `sounds.js`, `tests/speech.test.js`, 3.4 evidence; 3.3's "existing
   help UX unchanged" and "no 3.4/3.5 scope" pins evolved — the latter
   narrowed to 3.5 since 3.4 is now the current task; retention's
   byte-identical pin now exempts 3.4's legitimate `sounds.js` change)
   — all inline-documented, none weakened.
