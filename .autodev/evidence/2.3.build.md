# Task 2.3 Build Report — Content-script event sender

## What was implemented

**`sender.js`** (new, repo root): the §2.3 event sender in the Section-1
script pattern (guarded `BlindfoldSession` global, IIFE `'use strict'`,
Node shim). Exports `createSender(options?)` and `SENDER_MESSAGE_KIND`
(`'event'`).

- **Timestamp-at-observation**: `emit()` reads `performance.now()` first,
  then builds the frozen 11-key envelope via `createEvent`, appends to the
  in-memory FIFO, and kicks the pump. Monotonic time is the observation
  time even if the SW is dead for the page's whole lifetime; the pump never
  mutates queued envelopes.
- **Per-session `clock_anchor`**: anchor captured at `createSender()`
  (context startup); `createAnchorEvent` emitted lazily on first `emit()`
  per sessionId (`sourceSeq` 0, `gameId` null); the counter is per sender
  instance and failed validations consume no sequence numbers.
- **Queue**: unbounded in-memory FIFO, context-scoped, stop-and-wait —
  exactly one event ever unacknowledged.
- **Transport**: one-shot `chrome.runtime.sendMessage`, resolved lazily per
  attempt (bracket notation keeps the `chrome.` literal out of the source);
  `options.transport` injection for tests. Message `{kind:'event',event}`;
  ack `{ok,eventId,error?}`. Anything but a matching positive ack keeps the
  head queued, records `lastError` (`'no-ack'` / `'transport-error:<name>'`
  / writer's error string), stops the pump. `flush()` → `{delivered,pending}`
  is the §2.5 retry primitive; `pendingCount()` and `getStatus()` serve §2.8.
- **Call-time reads**: `event_envelope.js` exports are resolved per call via
  the shared namespace (never cached at load); the module loads in Node
  with `chrome` undefined. No `chrome.*` at load time.

**`manifest.json`**: `content_scripts[0].js` is now exactly
`["event_envelope.js", "sender.js", "sounds.js", "chess.min.js",
"chess_utils.js", "content.js"]`. Nothing else changed.

**`content.js`**: exactly one added line at top level:
`BlindfoldSession.sender = BlindfoldSession.createSender();`

**`tests/sender.test.js`** (new): 28 V1 checks — module surface, timestamp
bounds (`t0 <= monotonicMs <= t1 <= sendTime`), anchor-first ordering and
per-session re-emission, FIFO/stop-and-wait, full ack discipline
(ok:true / ok:false / undefined / rejection / sync-throw / eventId-mismatch /
shape-mismatch), no-transport queueing, retry re-sends the identical
envelope, stale-promise regression test, and static diff guards.

**`~/workspace/tools/ext-verify/sw-sender.js`** (harness, outside the repo):
V2 driver — see below.

## Deviations and findings

1. **Contract AC8's V2 design was unimplementable as written — adapted
   honestly.** The contract assumed the sender could be evaluated in the SW
   and message a test listener in the same SW. Empirically, Chrome rejects
   SW-to-SW `chrome.runtime.sendMessage` ("Could not establish connection.
   Receiving end does not exist"). The harness instead runs the sender in a
   real content-script isolated world via a /tmp test-only extension copy
   (extra manifest entry for a local test page + harness-only driver
   script; product code byte-identical to the repo). This is the actual
   deployment topology, so the verification is stronger than the contract's
   proxy — not weaker. AC8/AC9 intent fully preserved.
2. **Empirical correction to a contract reviewer note**: the contract
   suggested content-script→SW sendMessage with no listener "resolves
   undefined". Observed: it **rejects** (generic `Error`), so the sender
   records `'transport-error:Error'`. Both paths (`undefined` → `'no-ack'`,
   rejection → `'transport-error:<name>'`) keep the event queued — the
   sender is correct either way. Recommend recording in DECISIONS.md for
   §2.4/§2.5: the pre-2.4 no-listener state surfaces as a transport
   rejection, not a silent undefined.
3. **Real bug found and fixed during V1**: the shared `pumpPromise` was
   clobbered when a pump run finished synchronously — the Promise executor
   runs before the `pumpPromise = new Promise(...)` assignment completes,
   so `finish()`'s `pumpPromise = null` was overwritten by the in-progress
   assignment, leaving a stale resolved promise that later `flush()` calls
   wrongly joined (flush reported stale summaries; new events never sent).
   Fixed with a `finished` flag + identity check (`pumpPromise ===
   myPromise`), with an explanatory comment. A dedicated regression test
   ("consecutive flush() calls after synchronous pump runs each start
   fresh") pins it.
4. **Test evolution (precedent: 2.2)**: two transient git-relative
   assertions legitimately broke on 2.3's manifest change and were evolved
   with comments, invariants preserved or strengthened —
   `tests/db.test.js` ("manifest byte-identical to HEAD" →
   "differs from HEAD only in the content_scripts js list") and
   `tests/manifest_sw.test.js` ("content_scripts+web_accessible_resources
   byte-identical" → "web_accessible_resources byte-identical"; the js
   list itself is pinned exactly in `tests/sender.test.js`).
5. No §6 non-goal violations: no SW intake, no validation, no
   dedup/appendSeq, no retry policy, no restore, no lifecycle types, no
   status UI, no retention/export, no other manifest changes, no changes to
   chess_utils.js/sounds.js/sw.js/db.js/PLAN.md or any Section-1 module.
