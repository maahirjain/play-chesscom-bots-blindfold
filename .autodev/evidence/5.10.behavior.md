## 3. Contract behaviors — verified against the implementation

I read `session_controls.js` directly (not just the build report):

- **(a) Clean stop → 'complete':** `computeCompletion` returns `{verdict: 'complete', warnings: []}` only when all three streams are `ok`, no `flushTimedOut`, and `flushResult.pending === 0`. Confirmed in code (lines 473–508) and by V1 AC1 test (`'AC1: all-ok + drained → complete, no warnings'`).
- **(b) flushTimedOut → named warnings:** per-stream `flushTimedOut === true` produces `<kind>-flush-timed-out` (e.g. `webcam-flush-timed-out`). Surfaced in the button detail as `finalize-warnings:<w1>;<w2>` and retained in `getLastStopResponse().warnings`. Confirmed by V1 test at line 1225 (`'flushTimedOut:true is handed to the 5.10 seam undropped and surfaced as a warning'`).
- **(c) Killed transport → undelivered-count warning without hang:** `flushResult.pending > 0` produces `<n>-events-undelivered`. The flush await is guarded three ways: try/catch around `sender.flush()`, rejection handler → `finalizeStop(stopResp, null)` → honest `flush-result-unknown` warning. Missing `sender.flush` entirely → `Promise.resolve(null)` → warning, never a hang (V1 test `'AC6: missing sender.flush is an honest warning, never a hang or crash'`). V2 AC10 confirms no hang in real Chrome.
- **(d) Button never shows clean idle before flush resolves:** the Stop sequence sets the button to `'Finalizing…'` (phase stays STOPPING) before awaiting the flush; `finalizeStop` (which presents idle) runs only after the flush promise resolves. V1 test `'AC5: button shows Finalizing… (not clean idle) while the flush is in flight'` gates the flush and asserts: phase `stopping`, button `Finalizing…`, zero completion handoffs — then releases the flush and asserts clean idle follows. This is a genuine temporal pin, not a vacuous assertion.
- **(e) Stop-channel failure path unchanged:** `MSG_STOP_STREAMS` `{ok:false}` → stays in `'Stopping…'` with `stop-failed:<err>`, **no flush attempted** (the `return` precedes `pollOnce()`), session retained for retry. V1 test `'AC6: stop-channel failure → no flush attempted; stays in Stopping… for retry'` asserts `flushCalls === 0` and zero completions. Confirmed in code (lines 1640–1646).
